# 하나의 전략으로 워크포워드 검증해 보기

## 도입 멘트 (2분)

지난 클립에서 워크포워드의 그림을 그렸으니, 오늘은 그 그림을 여러분 컴퓨터에서 실제로 돌립니다. 코드는 한 줄도 쓰지 않습니다. 우리가 할 일은 "끝나면 뭐가 보여야 하는지"를 정확히 말하는 것뿐입니다.

## 진행 흐름

- (0~2분) 도입: 오늘의 목표 화면(윈도우 표 + 비교 곡선) 미리 보여주기
- (2~6분) 이론: 요청 전에 결과 모습 그리기 — 보여야 할 3가지 (표·곡선·비교 요약)
- (6~15분) **실습 08 시연**: 프롬프트 입력 → 워크포워드 실행 → 결과 확인
  - (6~8분) 프롬프트를 소리 내어 읽으며 "결과 모습만 담고 방법은 지정하지 않았다"는 점 강조
  - (8~12분) 실행 대기 중 윈도우가 굴러가는 구조 복습, 결과 표 확인
  - (12~15분) `wfa_single_strategy_result.html`을 브라우저로 열어 두 곡선 비교 — 격차 = 과최적화의 크기라고 화면에서 직접 해석
- (15~19분) 결과 읽기: 윈도우별 파라미터 안정성 확인
  - 파라미터가 구간마다 조금씩 다른 것은 정상, 널뛰면 경고라는 기준 제시
- (19~22분) 체크리스트 함께 점검 + 결과가 다를 때의 후속 프롬프트 안내 → 마무리

## 강조 포인트

- 프롬프트에 윈도우 길이·간격 같은 세부 조건을 나열하지 않는 이유를 설명할 것 — 조건이 아니라 목표를 전달
- 강사와 수강생의 윈도우 분할이 달라도 "구간이 겹치지 않고 굴러가는가"가 맞으면 성공임을 반복
- 확인은 반드시 사람이 눈으로 — AI에게 "잘 됐는지 확인해줘"라고 시키지 않게 주의
- 두 곡선의 격차를 볼 때 실망하는 수강생이 나올 수 있음 — "격차를 아는 것이 실전 손실을 막는 것"이라고 재해석
- Fold 1~5에서 최적 파라미터가 100일~150일선 사이에서 안정적으로 머무는 모습을 파라미터 안정성(Stability)의 실제 증거로 짚어줄 것
