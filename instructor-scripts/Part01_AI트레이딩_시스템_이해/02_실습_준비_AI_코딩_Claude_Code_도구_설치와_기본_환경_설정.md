# 실습 준비: AI 코딩 도구 실행과 기본 환경 설정

## 촬영 전 준비 (카메라 밖)

- [ ] **VS Code로 촬영할 것** (강의 기본 편집기). Claude Code 확장은 **미리 지운 상태**로 시작 — 설치 장면을 실제로 보여줘야 함
- [ ] 바탕화면에 `ai-trading` 폴더가 **없는 상태** 확인
- [ ] 브라우저에 포털 주식 시세 탭을 미리 열어 두기 (Step 4 대조용)
- [ ] 프롬프트 입력창 아래 **모드 표시를 클릭**해 목록을 미리 열어 **내 화면에 `Auto`가 있는지 확인** — 멘트가 달라짐
- [ ] `Auto`가 안 보이면 순서대로: ① `/model`로 모델이 최신 Sonnet/Opus인지 확인 → ② 확장 Update → ③ `Ctrl+Shift+P` → `Reload Window`
- [ ] **Step 5용 준비**: 촬영 전 diff 화면이 실제로 뜨는지 한 번 리허설 (`Manual` 모드에서 아무 파일이나 한 줄 수정 요청)

## 도입 멘트 (1분)

지난 클립에서 완성품을 보셨죠. 오늘부터 그걸 만들 도구를 손에 쥡니다. 설치라고 하면 벌써 머리가 아픈 분 계실 텐데, 오늘의 핵심은 **"설치조차 AI에게 시킨다"**는 겁니다. 우리가 직접 하는 건 클릭 몇 번뿐입니다.

## 구간별 상세

### (1~2분) 이론 압축

- 전통 코딩 vs AI 코딩 비교 카드 — **30초 안에 넘어갈 것.** 지난 클립에서 이미 다룬 내용
- **"오늘의 진행 흐름" 6단계 카드는 읽지 말 것 (10초, 화면 3초 고정)**
  목차를 낭독하는 건 영상에서 가장 에너지가 죽는 구간이고, 해보지 않은 6단계는 어차피 기억에 안 남습니다. **색깔 패턴 하나만** 심고 넘어가세요.
  > "오늘 순서는 이렇습니다. **색깔만 보세요. 앞은 제가 직접 하고, 가운데는 AI에게 맡기고, 마지막엔 다시 제가 확인합니다.**
  > 이 리듬이 앞으로 5개 파트 내내 반복됩니다. **지금 외우실 필요 없습니다.** 하시면서 자연스럽게 익으실 거예요."
  - **같은 화면을 마무리에서 한 번 더 띄울 것** — 그때는 예고가 아니라 **방금 겪은 경험의 요약**이라 효과가 완전히 다릅니다
  - 각 Step 시작마다 이 화면으로 되돌아오지 말 것. 전환만 늘고 리듬이 끊깁니다

### (2~6분) Step 0 — 편집기·확장 설치와 모드 설정

- **편집기 안내 먼저 (30초)** — 이 강의는 **VS Code 기준**임을 못 박을 것
  > "아무것도 안 깔려 있으시면 **VS Code**를 받으세요. 무료고, 오늘 보실 화면이 전부 이 화면입니다."
- **설치 과정은 시연하지 말 것 (10초).** 대다수는 이미 편집기가 있고, 없는 분도 유튜브에 널렸습니다. 교재 표를 3초 띄우고 넘어가세요
  > "VS Code 설치 자체는 다루지 않겠습니다. 아직 없으신 분은 **교재의 표 하나만 보시면** 됩니다 — Windows는 `User Installer`의 `x64`, Mac은 큰 파란 버튼.
  > **오늘은 확장 설치부터 시작합니다.**"
- **Install 버튼을 누르기 직전에 "왜 확장인가" 카드 3장 (40초).** 교재도 이 순서로 배치돼 있음 — 무엇을 고를지 정한 **직후, 실행하기 직전**이 정당화가 가장 잘 박히는 자리
  - **②번(diff로 나란히 보여줌)만 강조.** ①③은 읽지 말고 언급만
  - **여기서 Step 5 예고를 걸 것**: "오른쪽 칸은 승인 전에 제가 직접 고칠 수 있습니다. **이 화면은 오늘 맨 마지막에 직접 만져보실 겁니다.**"
- **오해 정정 두 가지를 반드시 짚을 것** (인터넷에 옛날 정보가 많음)
  - "터미널 설치는 Node.js를 깔아야 한다" → 옛날 이야기
  - "확장이 토큰을 덜 쓴다" → 사실 아님. 같은 엔진, 같은 요금제
- Extensions에서 `Claude Code` 검색 → Install → 로그인까지 실시간
- **프롬프트 입력창 맨 아래 모드 표시를 클릭**해서 목록 열기 (단축키 `Shift+Tab`은 "이것도 됩니다" 정도로만 언급)
- **⚠️ `Auto`를 고르라고 말할 것. `Edit automatically`는 대안이 아님**
  > "이름 때문에 오해하기 쉬운데, `Edit automatically`가 자동 승인해주는 건 **파일 편집**입니다.
  > 오늘 할 일은 대부분 **설치와 실행 명령**이라, 이걸 골라도 승인 버튼은 그대로 뜹니다.
  > 그걸 없애주는 건 **`Auto` 하나뿐**입니다."
- **⚠️ 가장 중요한 멘트 — 반드시 할 것**
  > "제 화면에는 모드가 N개 보이는데, 여러분 화면에는 다를 수 있습니다. 실제로 저도 어제는 `Auto`가 안 보였는데 오늘은 보입니다.
  > 그래서 제가 '위에서 세 번째를 고르세요'라고 말하지 않겠습니다. **이름으로 찾으세요.**"
- **`Auto`가 없는 수강생에게는 대안 한 줄만.** 원인 진단(모델·버전·조직 정책)은 하지 말 것 — 검색으로 풀리는 문제고, 여기서 시간을 쓰면 90%의 흐름이 끊깁니다
  > "`Auto`가 안 보이는 분은 `Edit automatically`를 고르시고, 승인 창이 뜰 때마다 **'다시 묻지 않기'**를 눌러주세요. 처음 몇 번만 누르면 조용해집니다."
- 이어서 원칙 한 문장:
  > "AI 도구는 화면이 자주 바뀝니다. **화면을 외우지 말고 목적을 기억하세요.** 이 강의 내내 반복될 이야기입니다."

### (6~7분) Step 1 — 폴더 만들기 + 오늘의 위치

- 폴더 생성/열기는 **말 없이 빠르게**. 대신 열자마자 지도 한 장을 띄울 것
  > "앞으로 만들 시스템이 아무리 복잡해져도 결국 세 가지입니다. **① 시세가 들어온다 → ② 규칙이 판단한다 → ③ 주문이 나간다.**
  > ①이 없으면 나머지는 존재할 수 없습니다. 그래서 오늘은 ① 하나만, 가장 작게 확인합니다."
- 파일 이름을 여기서 미리 심어둘 것
  > "프로그래밍 입문의 첫 줄이 `Hello, World`를 찍는 거라면, **우리 강의의 첫 줄은 '시장아, 안녕?'** 입니다. 그래서 오늘 만들 파일 이름이 `hello_market.py`입니다."

### (7~9분) Step 2 — 진단 프롬프트

- **⚠️ 프롬프트를 띄우기 전에 "왜 파이썬인가"부터 (30초).** 여기까지 파이썬이 왜 필요한지 한 번도 안 나왔습니다. 바로 프롬프트를 보여주면 수강생 머릿속엔 **"AI가 다 해준다며? 근데 왜 갑자기 파이썬?"** 이 뜹니다
  > "우리가 만들 시스템은 **파이썬**이라는 언어로 돌아갑니다. 주식 데이터를 다루는 도구가 이 언어에 제일 많거든요.
  > **여러분이 파이썬을 배우실 필요는 없습니다. 코드는 AI가 씁니다.** 다만 그 코드가 **실행되려면** 컴퓨터에 파이썬이 깔려 있어야 해요.
  > **레시피는 AI가 쓰고, 파이썬은 그 요리를 할 주방입니다.** 주방이 없으면 레시피가 아무리 좋아도 아무 일도 안 일어나죠.
  > 그래서 오늘의 첫 질문은 **'내 컴퓨터에 주방이 있나?'** 입니다."
  - `uv`도 프롬프트 **띄우기 전에** 한 줄: "파이썬 설치를 대신해주는 도구입니다. 지금은 그 정도만 아시면 됩니다"
- 프롬프트를 띄운 뒤 **모르는 줄이 있어도 괜찮다고 명시할 것**
  > "마지막 두 줄이 이상하게 구체적이죠? **지금 이해 안 하셔도 됩니다.** 그대로 복사하시고, 이유는 바로 설명드릴게요."
  - 초보자의 이탈은 "모르는 게 나왔다"가 아니라 **"이걸 알아야 하는 건지 아닌지 모르겠다"** 에서 생깁니다
- 입력 전에 **왜 진단을 따로 하는지** 설명 (30초)
  > "한 번에 다 시키면 AI가 막혔을 때 멈추지 않고 혼자 우회로를 찾습니다. 그게 오늘 마지막에 보실 사고의 원인이었습니다."
- Windows 껍데기 Python 줄을 짚으며:
  > "이 줄이 왜 이렇게 구체적이냐면, 제가 여기서 10분을 날렸기 때문입니다. Windows에는 Python인 척하는 껍데기가 기본으로 들어 있는데 AI도 여기 속습니다."
#### ⚠️ 촬영자 화면과 수강생 화면이 갈리는 지점

**촬영용 컴퓨터에는 Python이 이미 있어서 "있음"이 나오지만, 수강생 대부분은 "없음"이 나옵니다.**
별도 촬영 없이 **말로 안내**하고 넘어갑니다. 교재의 갈림길 표를 화면에 띄운 채 이렇게 말하세요.

> "제 화면에는 'Python 있음'이라고 나왔는데, **여러분 화면에는 '없음'이라고 나올 가능성이 더 높습니다. 그게 정상입니다.** 요즘 컴퓨터에는 Python이 기본으로 안 깔려 있거든요.
>
> 없다고 나와도 하실 일은 딱 한 줄 추가하는 것뿐입니다. 다음 프롬프트의 `[만들 것]` 맨 위에 **`uv를 사용해서 Python 3.12부터 설치해줘.`** 이 한 줄만 넣으시면, `uv`라는 도구가 Python까지 알아서 깔아 줍니다.
>
> 그래서 진단을 먼저 한 겁니다. **내 컴퓨터가 어느 쪽인지 알고 요청하면, 한 줄만 바꾸면 됩니다.** 모르고 요청하면 AI가 혼자 헤맵니다."

- 이 멘트 뒤에 **교재 갈림길 표를 3초 이상 화면에 고정**할 것 (수강생이 캡처할 시간)
- "없음" 화면을 억지로 재현하려 하지 말 것 — 시간만 쓰고 실익이 없음

### (9~15분) Step 3 — 구축 프롬프트

- **프롬프트를 붙여넣기 전에 네 칸 표부터 보여줄 것.** 각 칸 30초씩, 총 2분
  > "복사만 하고 넘어가면 다음 프로젝트에서 못 씁니다. 왜 이 칸들이 있는지만 이해하고 가세요."
- `[하지 말 것]` 칸에서 시간을 더 쓸 것 — 가장 낯선 개념
  > "라이브러리 3개만 요청했는데 AI가 22개를 설치한 적이 있습니다. 그래서 이 줄이 생겼습니다."
- 실행. **설치 로그가 흘러가는 구간은 편집으로 압축**하되, 그 위에 자막:
  > "여러분 화면은 다르게 흘러갑니다. 마지막 결과만 확인하면 됩니다"
- 결과가 나오면 `[확인]` 칸이 요구한 것(버전 3개 + 5행 표)이 실제로 나왔는지 짚기
- **⚠️ `.venv` 설명 30초 — 빼먹지 말 것.** 수강생이 가장 낯설어하는 지점
  1. **통증 먼저**: "라이브러리를 컴퓨터 전체에 깔면, A 프로젝트 때문에 버전을 올렸다가 **B가 조용히 망가집니다.** 몇 주 뒤에야 압니다."
  2. **정의**: "`.venv`는 **이 폴더에서만 쓰는 전용 도구 상자**입니다."
  3. **안심 (이게 제일 중요)**: "그래서 오늘 뭘 잘못 설치하셔도 괜찮습니다. **`.venv` 폴더 하나만 지우면 전부 사라지고 컴퓨터는 원래대로 돌아옵니다.**"
  4. **화면으로 10초**: `.venv` 안쪽 `site-packages`에 `pandas` 폴더가 실제로 있는 걸 열어서 보여줄 것 (Windows는 `.venv/Lib/site-packages`). "설치한 게 어디로 갔나"가 눈으로 해결됨
- 프롬프트에 `.venv`라는 단어를 **일부러 안 썼다**는 점을 짚을 것
  > "제가 프롬프트에 '가상환경'이라고 안 쓰고 **'이 폴더 안에서만 쓰는 독립된 환경'**이라고 썼죠. **목적을 쓰면 AI가 방법을 고릅니다.** 용어를 몰라도 됩니다."

### (15~18분) Step 4 — 대조와 훅 ★하이라이트

1. 체크리스트 앞의 세 항목을 화면에서 빠르게 확인
2. **폴더를 열어 파일이 `hello_market.py` 하나뿐인지 눈으로 보여줄 것** (울타리가 작동한 증거)
3. **브라우저를 켜서 포털 시세와 종가를 직접 대조** — 이 장면이 오늘의 핵심
   > "AI가 '완료했습니다'라고 해도 아직 끝난 게 아닙니다. 앞의 세 개는 화면만 봐도 알지만, 이건 **다른 창을 열어야만** 알 수 있습니다."
4. 다음 클립 훅 걸기 (여기서 자세히 설명하지 말 것 — 30초)
   > "제가 이 프롬프트를 만들 때 실제로 사고가 있었습니다. AI가 주가를 못 가져오자 인터넷에서 찾은 숫자를 코드에 적어 넣고 '완료했습니다'라고 보고했습니다. 화면은 완벽했고 에러도 없었습니다. **6,500원이 틀렸습니다.**
   > 그게 왜 치명적인지는 다음 클립에서 숫자로 보여드리겠습니다."

### (18~21분) Step 5 — diff 화면과 직접 편집 ★두 번째 하이라이트

**이 구간은 말보다 손이 중요합니다. 화면 조작을 크게, 천천히.**

1. 모드 표시를 클릭해 **`Manual`** 로 내리기. 클릭하는 손을 화면에 보여줄 것
   > "지금까지는 속도를 위해 자율권을 줬습니다. 이제 **반대쪽을 한 번 해보겠습니다.**"
2. 프롬프트 입력 (교재와 동일: 5일 평균 종가 한 줄 추가)
3. **diff 창이 뜨면 손가락으로 좌우를 가리키며**
   > "왼쪽이 지금 제 파일, 오른쪽이 AI 제안입니다. 초록색이 새로 들어올 줄이고요.
   > 참고로 이 화면은 **가운데 편집기에 새 탭으로** 열립니다. 맨 오른쪽 Claude 대화창이랑 헷갈리지 마세요."
4. **★핵심 장면 — 오른쪽 칸에 커서를 놓고 실제로 타이핑할 것.** 편집으로 압축하지 말고 **타이핑하는 손을 그대로 보여줄 것**
   - 예: `평균 종가:` → `5일 평균 종가(원):`
   > "AI가 쓴 코드는 **읽기 전용이 아닙니다.** 승인 전에 제가 먼저 고칠 수 있습니다."
5. 승인 → 결과 확인
   > "그리고 Claude는 **제가 손댔다는 걸 압니다.** 자기가 쓴 그대로라고 착각하지 않고, 제가 고친 버전에서 이어갑니다."
6. **마무리 멘트 — 이 클립에서 가장 중요한 두 문장**
   > "AI가 초안을 쓰고 **사람이 최종 결정을 했습니다.** 이게 앞으로 5개 파트 내내 지킬 자세입니다.
   > 그리고 이제 아실 겁니다 — **`Auto`는 속도를 얻는 대신 이 화면을 포기하는 선택입니다. 공짜가 아닙니다.**
   > 모드는 한 번 정하고 끝나는 게 아니라 **왔다 갔다 하는 겁니다.** 중요한 판단이 든 코드는 `Manual`로 내려서 보세요."

> ⚠️ **촬영 주의**: 이 구간에서 diff가 안 뜨면 모드가 아직 `Auto`인 것. 당황하지 말고 그대로 노출한 뒤 "보세요, `Auto`면 이 화면이 아예 안 뜹니다"로 활용할 것 — 오히려 좋은 장면이 됨

## 강조 포인트

- **"몇 번째를 고르세요"라는 표현을 절대 쓰지 말 것** — 환경마다 화면이 다름
- **편집기는 VS Code 하나로 안내할 것.** 다른 편집기 분기를 만들지 말 것 — 대다수가 안 듣는 문단만 늘어남
- **`Edit automatically`와 `Auto`를 같은 것처럼 말하지 말 것** — 전자는 편집만, 후자는 명령까지. 오늘 실습은 명령이 대부분이라 `Auto`가 아니면 승인 지옥
- **Step 5의 타이핑 장면은 편집으로 자르지 말 것** — 이 클립에서 가장 전달력 높은 3초
- 설치 화면이 수강생마다 다르다는 것을 최소 2번 언급
- 프롬프트는 **읽고 나서** 붙여넣기 — 복붙 지시로 들리면 안 됨
- 에러가 나면 당황하지 말고 그대로 노출할 것. "에러를 복사해 붙여넣는다"가 유일한 대응임을 예고 (Clip 05에서 자세히)
