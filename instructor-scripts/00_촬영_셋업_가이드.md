# 촬영 셋업 가이드 (OBS + Windows)

43개 클립 전부에 적용됩니다. **최초 1회만 설정하고, 이후에는 맨 아래 "매 촬영 전 체크리스트"만 보시면 됩니다.**

---

## 0. 전체 그림

| 파일 | 무엇 | 누가 찍나 |
|---|---|---|
| **obs 파일** | 화면 녹화 + 강사 음성 | OBS (이 문서) |
| **cam 파일** | 강사 얼굴 | 아이폰 (별도) |

편집자가 **박수 소리**로 두 파일의 싱크를 맞춥니다.

> ⚠️ **OBS 씬에 웹캠을 넣지 마세요.** 얼굴은 아이폰으로 따로 찍고 편집자가 합성합니다. OBS에 웹캠을 넣으면 편집자가 얼굴 크기·위치를 조정할 수 없습니다.

---

## 1. 소스 만들기 — `창 캡처` 두 개

**`Display Capture`는 지우세요.** 작업 표시줄, 시계, 알림 팝업이 전부 찍힙니다.

### 1-1. 브라우저 창 캡처

`Sources` 패널 → `+` → **`Window Capture`** → 이름: `브라우저`

| 항목 | 값 | 이유 |
|---|---|---|
| **Window** | 강의 자료를 띄운 브라우저 | |
| **Capture Method** | **`Windows 10 (1903 and up)`** | ⚠️ `BitBlt`는 **가려진 창을 못 찍습니다** |
| **Window Match Priority** | **`Match title, otherwise find window of same executable`** | ⚠️ 탭을 바꾸면 창 제목이 바뀌어 캡처가 끊깁니다 |
| **Capture Cursor** | ✅ 켜기 | 어디를 클릭하는지 보여야 함 |

### 1-2. 편집기 창 캡처

`+` → `Window Capture` → 이름: `VS코드`. 설정은 위와 동일하되 Window만 `[Code.exe]`로.

> ⚠️ **VS Code는 파일을 열 때마다 창 제목이 바뀝니다.** Window Match Priority를 반드시 `same executable`로 두세요. 안 그러면 촬영 중간에 화면이 검게 변합니다.

### 1-3. ⚠️ 검은 화면이 나올 때 — 원인 순서대로

미리보기에서 소스가 **까맣게** 나오는 건 창 캡처에서 가장 흔한 증상입니다. **아래 순서로 확인하세요.**

#### 원인 ① 두 창이 서로 다른 모니터에 있음 ← **실제로 겪은 원인**

**촬영에 쓰는 창(브라우저·편집기)은 반드시 같은 모니터에 두세요.**

여러 모니터를 쓰면 창이 어느 모니터에 있느냐에 따라 **그 창을 그리는 그래픽 파이프라인이 달라집니다.** OBS가 다른 파이프라인의 창 텍스처를 못 읽으면 검은 화면이 나옵니다. 노트북 내장 그래픽 + 외장 모니터 조합에서 흔합니다.

**OBS 창 자체는 다른 모니터에 둘 수 있는지 테스트해보세요.** 된다면 이게 최고의 배치입니다.

```
모니터 1 (촬영용)          모니터 2 (내 눈으로만)
┌──────────────────┐      ┌──────────────────┐
│ Chrome           │      │ OBS 미리보기      │
│ VS Code          │      │ 대본             │
└──────────────────┘      └──────────────────┘
```

단축키를 눌렀을 때 결과를 모니터 2에서 **실시간으로 확인**하면서 강의할 수 있습니다. 안 되면 전부 모니터 1에 두세요.

#### 원인 ② Capture Method가 `BitBlt`

소스 선택 → `Properties` → **`Capture Method: Windows 10 (1903 and up)`**. `BitBlt`는 가려진 창을 못 찍습니다.

#### 원인 ③ 창이 최소화됨

최소화된 창은 어떤 방식으로도 캡처되지 않습니다.

#### 원인 ④ Chrome의 "가려진 창 렌더링 중단" (안전망으로 꺼두세요)

Chrome에는 창이 **100% 가려지면** 그리기를 멈추는 절전 기능이 있습니다. (VS Code는 이 기능이 꺼져 있어 해당 없음)

- **끄는 법**: 주소창에 `chrome://flags/#calculate-native-win-occlusion` → **`Disabled`** → `Relaunch`
- **항목이 없다면**: Chrome 바로가기 우클릭 → 속성 → `대상` 끝에 한 칸 띄고 `--disable-features=CalculateNativeWinOcclusion`
- **설정 없이 푸는 법**: VS Code를 최대화하지 말고 살짝 밀어 **Chrome이 1픽셀이라도 보이게** 두기. 창 캡처를 쓰므로 삐져나온 부분은 영상에 안 나갑니다

이번 사례의 원인은 아니었지만, 배치가 바뀌면 언제든 만날 수 있으니 꺼두는 편이 안전합니다.

### 1-4. 캡처 "예열" — OBS를 켤 때마다

OBS를 실행한 직후에는 창 캡처가 아직 붙지 않아 검게 나올 수 있습니다.

**작업 표시줄에서 Chrome 한 번, VS Code 한 번 클릭**해주면 캡처가 붙습니다. 30초짜리이고, **이걸 안 하면 녹화 앞부분이 까맣게 나갑니다.** 아래 체크리스트에 넣어뒀습니다.

## 2. 씬 2개 만들기

`Scenes` 패널 `+` 로 아래 두 개를 만듭니다. 이름 앞 번호가 순서를 고정해 줍니다.

| 씬 | 소스 | 언제 쓰나 |
|---|---|---|
| `01_자료` | `브라우저` | 개념 설명, 프롬프트 보여주기 |
| `02_실습` | `VS코드` | 프롬프트 입력, 결과 확인, 폴더 확인, diff |

### 왜 "확대 씬"을 안 만드나

**Claude Code를 에디터 탭으로 크게 띄우면** 잘라낼 게 왼쪽 파일 탐색기(약 340px)뿐입니다. 20% 커지자고 씬을 만들 이유가 없습니다.

**가독성은 크롭이 아니라 VS Code 줌으로 확보합니다.**

> **크롭 확대 = 픽셀을 늘리는 것** (화질 손실)
> **줌 확대 = 처음부터 크게 그리는 것** (손실 없음)

나중에 특정 순간에 정말 확대가 필요해지면 그때 씬을 하나 추가하면 됩니다. 미리 만들지 마세요.

### 소스를 두 씬에서 공유하기

`01_자료`에 두 소스가 다 들어 있다면, `VS코드`의 **눈 아이콘(👁)을 꺼서** 숨기세요. (삭제 아님)

`02_실습`은 새로 만든 빈 씬이므로 `Sources` `+` → `Window Capture` → **`Add Existing`** → `VS코드` 로 넣습니다.

> ⚠️ 새로 만들지 말고 **`Add Existing`**. 원본 하나만 고치면 모든 씬에 반영됩니다.

### 각 씬에서 화면 채우기

소스를 클릭한 뒤 **`Ctrl` + `F`** (화면에 맞추기). 아래·옆에 검은 띠가 남지 않아야 합니다.

## 3. 씬 전환 단축키

`Settings` → **`Hotkeys`** → 씬 이름별 **`Switch to scene`** 칸을 클릭하고 키를 누릅니다.

```
Ctrl + Alt + 1  =  01_자료
Ctrl + Alt + 2  =  02_실습
```

#### ⚠️ `F1`·`F2`를 쓰지 마세요

**OBS 단축키는 전역이지만, 그 키를 앱에서 빼앗지 않습니다.**

```
F1 누름  →  OBS: 씬 전환 ✅
         →  Chrome: 도움말 탭 열림 ✅   ← 둘 다 실행됨
```

`F1`은 거의 모든 프로그램에서 "도움말"입니다. **어떤 앱도 안 쓰는 조합**을 골라야 합니다.

| 조합 | 비고 |
|---|---|
| **`Ctrl`+`Alt`+`1` / `2`** | **권장.** Chrome·VS Code 모두 안 씀, 한 손으로 누르기 편함 |
| `Ctrl`+`Alt`+`Z` / `X` | 안전 |
| `Pause` / `Scroll Lock` | 아무것도 안 씀 — 가장 안전. 노트북엔 키가 없을 수 있음 |

#### 바꾼 뒤 반드시 테스트

1. **Chrome을 앞에 놓고** 눌러보기 → 씬만 바뀌고 Chrome에선 아무 일도 없어야 함
2. **VS Code를 앞에 놓고** 눌러보기 → 마찬가지
3. **Claude 입력창에 커서를 놓고** 눌러보기 → **글자가 안 써져야 함**

3번을 꼭 하세요. 프롬프트 입력 중에 씬을 전환할 일이 생기는데, 그때 입력창에 문자가 들어가면 곤란합니다.

**이게 아마추어와 프로를 가르는 지점입니다.** 단축키를 쓰면 녹화 내내 **OBS 창이 한 번도 화면에 안 나옵니다.**

### 전환 순서 — 반드시 이 순서로

```
1. 말로 예고    "이제 실습으로 가보겠습니다"
2. Ctrl+Alt+2  ← 시청자는 즉시 편집기를 봄
3. Alt+Tab      ← 시청자는 이걸 못 봄
4. 작업 시작
```

**씬을 먼저, 창 전환을 나중에.** 순서가 바뀌면 Alt+Tab 화면이 그대로 녹화됩니다.

실제 창 전환이 필요한 건 **자료 ↔ 실습 왕복뿐**입니다. Clip 하나당 6회 정도면 충분합니다.

### 전환 효과

메인 화면 오른쪽 아래 **`Scene Transitions`** → **`Fade`** / **`Duration: 200 ms`**
- 기본값 300ms는 강의엔 약간 깁니다
- `자르기(Cut)`는 너무 툭 끊겨서 눈이 피로합니다

## 4. 녹화 설정

### 4-1. 출력

`Settings` → **`Output`** → **`Output Mode: Advanced`** → **`Recording`** 탭

| 항목 | 값 | 이유 |
|---|---|---|
| **Recording Format** | **`Hybrid MP4 (.mp4)`** | 크래시·정전에도 파일이 안 날아가고, 편집자가 바로 받습니다 |
| | (없으면 `Matroska Video (.mkv)`) | mkv도 안전하지만 편집자가 변환해야 할 수 있음 |
| **Video Encoder** | **`AMD HW H.264 (AVC)`** | Radeon 860M 하드웨어 인코더. CPU 부담이 줄어 편집기가 안 버벅임 |
| **Rate Control** | **`CQP`** | 화질 기준 고정. 텍스트 화면에 적합 |
| **CQP** | **`20`** | 낮을수록 고화질·큰 용량. 20이면 충분합니다 |
| **Preset / Profile** | `Quality` / `high` | |

> ⚠️ **그냥 `MPEG-4 (.mp4)`는 고르지 마세요.** 녹화 중 프로그램이 죽으면 파일 전체가 재생 불가가 됩니다. `하이브리드 MP4`는 그 문제를 해결한 형식입니다.

> 📌 mkv로 찍었다면 `File` → **`Remux Recordings`** 로 mp4 변환하면 됩니다. 재인코딩이 아니라 화질 손실이 없습니다.

### 4-2. 비디오

`Settings` → **`Video`**

| 항목 | 값 |
|---|---|
| **Base (Canvas) Resolution** | `1920x1080` |
| **Output (Scaled) Resolution** | `1920x1080` |
| **Common FPS Values** | **`29.97`** |

> 아이폰은 "30fps"로 설정해도 실제로는 29.97로 기록됩니다. OBS를 29.97로 맞춰두면 두 파일이 완전히 같은 속도로 흘러 **싱크가 밀리지 않습니다.**

### 4-3. 오디오

**영상 강의는 화질보다 음질이 체감 완성도를 좌우합니다.** 화면이 흐린 건 참지만 소리가 웅웅거리면 5분 만에 이탈하고, 이건 후보정으로 못 살립니다. 이 절에 시간을 쓰세요.

#### 장치

`Settings` → **`Audio`** → `Global Audio Devices`

| 항목 | 값 | 이유 |
|---|---|---|
| **Desktop Audio** | **`Disabled`** | 알림음·시스템 소리가 섞입니다 |
| **Mic/Auxiliary Audio** | 쓰는 마이크 | 강의 음성이자 **박수 싱크 신호**. 반드시 켜져 있어야 합니다 |

`Settings` → `Output` → **`Audio`** 탭 → **`Track 1` Audio Bitrate `192`**
(Track 2~5는 녹화에 안 쓰이므로 그대로 두면 됩니다)

#### 레벨 목표

`Audio Mixer`에서 말해보며 확인합니다.

| | 목표 |
|---|---|
| **평상시 말할 때 (평균)** | **-18 ~ -12 dB** |
| **가장 크게 말할 때 (피크)** | **-12 ~ -6 dB** |
| **절대 넘으면 안 되는 선** | **0 dB (빨강)** — 소리가 깨집니다 |

**-18보다 아래에서만 논다면 너무 작은 겁니다.** 그대로 찍으면 편집자가 볼륨을 올려야 하는데, 그때 배경 소음도 같이 커집니다.

#### 레벨이 낮을 때 — 위에서부터 순서대로

**① Windows 입력 볼륨** (여기가 먼저)
`설정` → `시스템` → `소리` → `입력` → 마이크 선택 → **`입력 볼륨` `100`**

원본에서 키우는 게 항상 낫습니다. OBS에서 키우면 노이즈도 같이 커집니다.

**② OBS 필터** — `Audio Mixer`의 `Mic/Aux` **우클릭 → `Filters`** → 좌하단 `+`

| 순서 | 필터 | 값 | 역할 |
|---|---|---|---|
| 1 | **`Noise Suppression`** | `RNNoise` | 팬·에어컨 소음 제거 |
| 2 | **`Gain`** | **`+6` ~ `+12 dB`** | 레벨 올리기 |
| 3 | **`Limiter`** | `Threshold: -3 dB` | **박수 소리가 깨지는 것 방지** |

**순서가 중요합니다.** 필터 목록에서 드래그로 위 순서를 맞추세요.

> 💡 **Limiter를 꼭 넣으세요.** 박수는 순간적으로 아주 큰 소리라 클리핑되기 쉬운데, 클리핑되면 편집자가 파형으로 싱크 맞출 때 불리합니다.

#### 마이크

**노트북 내장 마이크는 43개 클립 분량에 권하기 어렵습니다.** USB 마이크 하나(3~10만원대)면 체감이 크게 달라집니다.

## 5. Windows 설정

### 5-1. 알림 차단

`설정` → `시스템` → `알림` → **`방해 금지` 켜기**

창 캡처를 써도 팝업이 창 위에 겹치면 찍힐 수 있습니다. 그리고 **전화·메신저 알림음이 마이크에 들어갑니다.**

같은 화면의 `자동 규칙`에서 **`전체 화면 모드로 앱을 사용할 때`** 도 켜두면 좋습니다.

#### 방해 금지로도 안 막히는 것 — 시스템 대화상자

`Program Compatibility Assistant` 같은 **시스템 대화상자는 알림이 아니라서 방해 금지로 안 막힙니다.** 창 캡처를 쓰면 영상에는 안 찍히지만 **포커스를 빼앗아 흐름이 끊깁니다.**

자주 뜨는 것: Bonjour의 `mdnsNSP.dll`이 LSA 보호에 의해 차단됐다는 알림 (무해합니다).

**대응**: 뜰 때 **`Don't show this message again` 체크 → `Cancel`** 로 영구히 끄기. 프로그램을 삭제할 필요는 없습니다.

### 5-2. 마우스 포인터 키우기

`설정` → `접근성` → `마우스 포인터 및 터치`

| 항목 | 값 | 이유 |
|---|---|---|
| **포인터 스타일** | **`사용자 지정`** → 밝은 노랑 또는 연두 | ⚠️ 흰색은 밝은 브라우저 화면에서, 검정은 어두운 편집기에서 **사라집니다.** 컬러는 양쪽 다 보입니다 |
| **크기** | **3~4단계** | 기본 1단계는 1080p 영상에서 안 보입니다 |

이걸 안 하면 수강생이 **"방금 뭘 눌렀지?"** 를 계속 하게 됩니다.

### 5-3. VS Code 촬영 설정 — 글자를 생각보다 훨씬 크게

**`Ctrl` + `=` 를 2~3번** 눌러 줌 레벨을 올립니다. (되돌리기 `Ctrl` + `0`)

> 💡 `Ctrl+=`(줌 레벨)은 **파일 탐색기·탭·상태바까지 UI 전체**가 커집니다. 설정의 `editor.fontSize`는 코드 글자만 커지고 UI는 그대로라 촬영엔 맞지 않습니다.

#### 얼마가 적당한지 확인하는 유일한 방법

1. 줌을 올린 상태로 **30초 테스트 녹화**
2. 그 파일을 **화면의 1/4 크기 창으로 재생**
3. 프롬프트와 응답이 **편하게 읽히면** 통과

수강생이 노트북으로 볼 때의 조건입니다. **거의 항상 "생각보다 훨씬 크게"가 정답입니다.**

#### 그 밖에 정리할 것

- **Claude Code는 사이드 패널이 아니라 에디터 탭으로** 크게 띄우기 — 확대 씬이 필요 없어집니다
- 상단·하단의 **안내 배너를 전부 닫기** (`Prefer the Terminal experience?` 등)
- **촬영용 폴더는 비어 있어야 합니다** — 수강생은 빈 `ai-trading` 폴더에서 시작합니다

> 💡 **선택 사항** — VS Code **프로필**(`File` → `Preferences` → `Profiles`)로 "촬영용" 프로필을 만들면 줌 레벨·테마·확장 구성을 평소 작업 환경과 분리할 수 있습니다. 매번 줌을 올렸다 내릴 필요가 없어집니다.

### 5-4. 브라우저는 `F11` 전체화면으로

탭바와 주소창이 사라지고 **본문이 그만큼 커집니다.** 강의 자료의 왼쪽 목차 사이드바는 켜두세요 — 수강생에게 "지금 어디"를 알려줍니다.
