## 도입 멘트 (2분)

강의 내내 Claude Code를 썼습니다. 그런데 만약 내일 이 도구가 사라지면 여러분이 배운 것도 사라질까요? 오늘은 그 질문에 실험으로 답합니다. 지금까지 쓰던 프롬프트를 Codex에 그대로 넣어서, 여러분의 진짜 자산이 도구가 아니라 작업 방식이라는 것을 확인하겠습니다.

## 진행 흐름

- (0~2분) 도입: "도구가 사라지면?" 질문 던지기
- (2~6분) 이론: 도구는 바뀌어도 루프는 남는다
  - 생각→요청→확인→개선 루프가 도구 중립적임을 설명
  - 도구 독립성의 가치: 가격 인상·단종·더 좋은 도구 등장에 대한 보험
- (6~14분) **실습 23 시연**: Codex에 기존 프롬프트 적용
  - Part 1의 차트 프롬프트를 Codex에 그대로 입력 → 차트 생성 확인
  - 시연 중: Claude Code가 만든 코드와 Codex가 만든 코드를 나란히 띄워 "다르다"를 먼저 보여주고, 그다음 결과 화면이 같은 체크리스트를 통과함을 확인
  - 시간이 되면 일일 보고서 프롬프트(실습 20)도 시도
- (14~17분) 이론 정리: 같은 프롬프트, 다른 코드, 같은 체크리스트
  - "코드가 아니라 결과 화면을 검증한다"가 도구 독립성의 뿌리임을 연결
- (17~18분) 체크리스트 복기 + 마무리

## 강조 포인트

- 이 클립에서는 "결과가 다르다"가 문제가 아니라 학습 목표 그 자체
- 두 도구의 코드 차이를 숨기지 말고 오히려 크게 보여줄 것
- Codex 설치·로그인 등 환경 세팅은 사전 녹화나 빠른 배속으로 처리 (본질이 아님)

## 마무리 멘트 (1분)

오늘 확인했습니다 — 여러분의 자산은 특정 도구가 아니라 프롬프트 템플릿과 체크리스트, 그리고 작업 루프입니다. 다음 클립이 이 강의의 마지막입니다. 모든 조각을 일간·주간·월간 운영 루틴으로 묶겠습니다.
