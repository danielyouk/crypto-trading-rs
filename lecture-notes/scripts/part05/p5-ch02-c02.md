# 과도한 주문을 방지하는 주문 한도와 긴급 정지 기능 만들기

## 도입 멘트 (2분)

전략이 틀리면 천천히 잃지만, 시스템 버그는 몇 분 만에 계좌를 비울 수 있습니다. 오늘은 전략이 아무리 잘못돼도 뚫리지 않는 세 겹의 안전장치 — 일일 주문 한도, 포지션 한도, 그리고 긴급 정지 버튼을 만들겠습니다. 이 강의에서 가장 중요한 실습 중 하나입니다.

## 진행 흐름

- (0~2분) 도입: 실제 사고 사례 톤으로 — 반복 시그널·무한 재시도가 계좌를 비우는 시나리오
- (2~7분) 이론: 세 겹의 안전장치
  - 한도 3종 표 설명 + "안전장치는 전략 바깥, 주문 길목에 있어야 한다"
  - 정지는 쉽게, 재개는 어렵게 — 비대칭 설계의 이유
- (7~16분) **실습 22 시연**: 안전장치 3종 추가
  - 프롬프트 입력 → 구현 확인 → **일부러 한도를 초과시키는 테스트**가 시연의 핵심
  - 11번째 주문 거부 + 텔레그램 한도 초과 알림 도착 장면
  - 긴급 정지 → 새 시그널이 와도 주문이 안 나가는 로그 확인 → 명시적 해제
- (16~19분) 이론 보강: 긴급 정지 중에도 손절 매도는 살아있어야 하는 이유
  - 신규 매수 차단 vs 보유 포지션 방어의 구분
- (19~20분) 체크리스트 복기 + 마무리

## 강조 포인트

- "한도를 일부러 넘겨보는 테스트"를 반드시 수강생도 하게 할 것 — 만들었다≠작동한다
- 모의계좌에서 시연 중임을 화면에 노출
- "얼마나 버는가만큼 얼마나 덜 잃는가" — 안전장치가 수익 기능보다 우선함을 반복

## 마무리 멘트 (1분)

이제 여러분 시스템에는 브레이크가 달렸습니다. 시스템이 폭주해도, 여러분 판단이 흔들려도, 한도와 정지 버튼이 계좌를 지킵니다. 다음 클립에서는 드디어 "실전으로 넘어가도 되는가"를 점검하는 전환 체크리스트를 다루겠습니다.
