# 카카오톡과 이메일로 매매 알림 받아보기

## 도입 멘트 (2분)

텔레그램 알림이 잘 오지만, "카톡으로는 안 되나요?"라는 질문이 반드시 나옵니다. 오늘은 카카오톡과 이메일을 보조 채널로 붙여보고, 동시에 왜 승인 버튼은 텔레그램에만 두는지 그 이유를 이야기합니다.

## 진행 흐름

- (0~2분) 도입
- (2~7분) 이론: 채널별 성격 비교 표 (텔레그램=승인, 카카오톡=인지 보조, 이메일=기록·백업)
  - "승인 관문은 하나만" 원칙 — 여러 곳에서 승인 가능하면 상태가 꼬임
- (7~11분) 이론 + 현실 안내: 카카오톡의 제약
  - 자유 봇 불가, "나에게 보내기" API 방식, 토큰 갱신 번거로움
  - 그래서 **선택 확장**임을 명확히 — 막히면 건너뛰어도 시스템 완성에 지장 없음
- (11~16분) **시연**: 이메일 알림 연결 (따라 해보기 프롬프트)
  - 앱 비밀번호 발급 화면 (값 가림) → .env 저장 → 테스트 신호 → 메일함 도착 확인
  - 시간이 되면 카카오톡 "나에게 보내기" 결과 화면도 짧게
- (16~18분) 자주 발생하는 문제 (앱 비밀번호 vs 계정 비밀번호, 카카오 토큰 만료) + 마무리

## 강조 포인트

- 이 클립은 수강생 간 결과 차이가 가장 큰 클립 — "카카오톡은 안 돼도 괜찮다"를 여러 번 말할 것
- 카카오 개발자 사이트 UI는 자주 바뀌므로 화면 자체보다 "AI에게 오류를 그대로 전달하는 습관"을 강조
- 커리큘럼 노트: 실습 번호 매핑이 조정될 수 있는 클립 (실습 15 확장 포지션)

## 마무리 멘트 (1분)

알림 채널이 완성되었습니다. 다음 클립이 Part 4의 하이라이트입니다. 승인 버튼과 모의주문을 연결해서, 여러분이 누른 승인이 실제 체결로 이어지는 순간을 만들겠습니다.
