# 주문 목록을 확인하고 승인·거절하는 절차 만들기

## 이번 클립에서 만들 것

장 마감 뒤 만들어진 **주문 목록 파일을 직접 열어 값을 확인하고, 매수 주문의 승인 상태를 고쳐 두는 절차**를 만듭니다. 승인해 두면 다음 날 개장 때 주문이 자동으로 나갑니다. 주문 목록이 비어 있는 날은 확인만 하고 끝납니다.

> 💡 고치지 않으면 매수는 나가지 않습니다. 거래하지 않는 것이 기본값이라, 확인을 놓쳐도 위험이 늘지 않습니다.

- 승인이 필요한 주문과 필요 없는 주문
- 파일에서 승인 상태를 고치는 방법
- 고친 파일이 올바른지 검사하는 프로그램
- **실습 18**: `approve_orders.py` 작성 및 승인·거절 시험

---

## 이론 핵심

### 1. 무엇을 승인하나

| 주문 | 승인 | 이유 |
|---|---|---|
| 매수 | **필요** | 위험을 늘리는 주문. 승인이 없으면 그날은 사지 않음 |
| 매도 | 필요 없음 (자동) | 위험을 줄이는 주문. 응답을 기다리다 늦으면 안 됨 |
| 장중 손절 | 필요 없음 (자동) | 급락 때 사람의 답을 기다릴 수 없음 |

매수 주문은 장 마감 뒤에 정해지고 다음 날 개장 때 나갑니다. 그 사이에 승인해 두면 되므로 시간에 쫓기지 않습니다.

---

### 2. 승인은 파일에서 직접 합니다

주문 목록 파일(`orders.json`)에는 주문마다 **승인 상태** 칸이 있습니다. 처음에는 매도가 '자동', 매수가 '승인 대기'로 적혀 있습니다.

```json
{
  "신호 기준일": "2026-10-05",
  "주문": [
    { "매수/매도": "매도", "종목명": "하나금융지주", "수량": 5, "예상 금액": 450000,
      "이유": "페어 스위칭이 KB금융으로 교체", "승인 상태": "자동", "메모": "" },
    { "매수/매도": "매수", "종목명": "KB금융", "수량": 3, "예상 금액": 520000,
      "이유": "페어 스위칭이 KB금융으로 교체", "승인 상태": "승인 대기", "메모": "" }
  ]
}
```

위 값은 예시이고, 항목 이름은 여러분의 파일과 조금 다를 수 있습니다.

1. 파일을 열어 종목, 수량, 예상 금액, 이유를 확인합니다.
2. 매수 주문의 `승인 대기`를 `승인` 또는 `거절`로 고쳐 저장합니다. 거절이면 `메모`에 사유를 한 줄 적습니다.
3. 고치지 않고 두면 '승인 대기'로 남아 그 매수는 나가지 않습니다.

**승인 상태와 메모 말고는 고치지 않습니다.** 수량이나 종목을 바꾸고 싶다면 주문 목록이 아니라 입력값을 고쳐 신호부터 다시 만들어야 합니다. 직접 고치기 번거로우면 Claude Code에게 "orders.json에서 KB금융 매수를 승인으로 바꿔줘"라고 요청해도 됩니다.

거절이 잦으면 백테스트로 검증한 전략과 다른 것을 운용하는 셈이 됩니다. 메모에 사유를 남겨 두면 나중에 그 판단이 옳았는지 되돌아볼 수 있습니다.

---

### 3. 고친 파일을 검사합니다

사람이 손으로 고친 파일이 그대로 주문이 되므로, 주문을 보내기 전에 검사합니다.

| 검사 | 걸리면 |
|---|---|
| 파일이 형식에 맞게 저장됐는가 | 어디가 잘못됐는지 알려 주고, 매수는 나가지 않음 |
| 매도는 '자동' 그대로이고, 매수는 승인 대기·승인·거절 중 하나인가 | 위와 같음 |
| 승인 상태와 메모 말고 다른 값이 원본과 달라졌는가 | 위와 같음 |

검사를 통과하면 "다음 개장 때 나갈 주문"과 "나가지 않을 주문"을 나눠 보여 주고, 승인·거절 결과를 기록으로 남깁니다.

---

### 4. 승인 방식과 자동 방식

| 방식 | 매수 주문 | 쓰는 때 |
|---|---|---|
| **승인 방식** (기본) | 내가 파일에서 승인해야 나감 | 처음 시작할 때. 시스템이 규칙대로 움직이는지 지켜보는 기간 |
| **자동 방식** | 승인하지 않아도 나감 | 시스템에 익숙해진 뒤 |

두 방식 모두 매도와 손절은 자동입니다. 이 강의의 실습은 승인 방식으로 합니다.

## 실습 — 실습 18: 승인 상태 검사 프로그램 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 `prepare_orders.py`가 저장한 `orders.json`(주문 목록)과 `logs/orders_original.json`(사람이 고치기 전의 원본)을 읽습니다. 승인·거절 이력은 `approvals_log.json`에 쌓입니다. 실습에서는 실제 주문 목록 대신 시험용 파일로 절차를 확인합니다.

```prompt
[맥락] 다음 개장 때 낼 주문 목록('orders.json')을 내가 직접 열어 매수 주문의 승인 상태를 고쳐 둘 거야. 그 파일이 올바르게 고쳐졌는지 검사하고, 다음 개장 때 나갈 주문을 정리해 주는 프로그램을 만들고 싶어.

[만들 것] 다음 조건에 맞춰 파이썬 스크립트 'approve_orders.py'를 작성하고 실행해줘:
1. 먼저 작업 폴더의 'prepare_orders.py'와 'orders.json', 'logs/orders_original.json'을 읽어 항목 이름과 구조를 확인해줘.
2. 옵션 없이 실행하면 'orders.json'을 검사해줘. 아래 가운데 하나라도 걸리면 무엇이 잘못됐는지 알려 주고, 모든 매수를 '나가지 않을 주문'으로 처리해:
   - 파일이 JSON 형식에 맞지 않음 (몇 번째 줄인지 알려줘)
   - 매도의 승인 상태가 '자동'이 아니거나, 매수의 승인 상태가 '승인 대기', '승인', '거절' 말고 다른 값임
   - 승인 상태와 메모 말고 다른 값(종목, 수량, 금액 등)이 'logs/orders_original.json'과 다름
3. 검사를 통과하면 [다음 개장 때 나갈 주문: 매도(자동)와 승인된 매수]와 [나가지 않을 주문: 승인 대기·거절인 매수]를 나눠 표로 보여 주고, 'approvals_log.json'에 [검사 시각, 신호 기준일, 종목, 매수/매도, 수량, 승인 상태, 메모]를 덧붙여줘.
4. '--auto'를 붙여 실행하면 모든 매수의 승인 상태를 '승인'으로 바꾸고 메모에 '자동 방식'이라고 적어 저장한 뒤, 2~3번과 똑같이 검사하고 'approvals_log.json'에 기록해줘.
5. 검사 결과(통과 여부와 나갈 주문 목록)를 다른 스크립트가 불러와 쓸 수 있게 함수로 만들어줘. 다른 스크립트가 이 함수로 검사할 때도 3번처럼 'approvals_log.json'에 기록이 남게 해줘.
6. 이 실습에서는 실제 'orders.json'을 건드리지 말고, 같은 구조의 시험용 파일 'orders_test.json'과 'logs/orders_test_original.json'(KB금융 3주 매수 1건, 하나금융지주 5주 매도 1건)을 만들어 세 가지를 시험해줘. 파일 이름은 '--file orders_test.json'처럼 넘길 수 있게 해줘.
   - 매수의 승인 상태를 '승인'으로 고친 경우
   - 아무것도 고치지 않은 경우
   - 승인으로 고치면서 수량도 3주에서 30주로 바꾼 경우

[하지 말 것]
- 검사하고 기록하기만 해. 매수·매도 주문 API를 호출하지 마.
- 실제 'orders.json'의 승인 상태를 네가 정하지 마. 승인 상태는 내가 고친다. ('--auto'와 시험용 파일은 예외)
- 검사에 걸린 파일을 네가 고쳐서 통과시키지 마. 무엇이 잘못됐는지만 알려줘.
- 화면 입력을 기다리며 멈추는 코드를 넣지 마.

[확인] 대화창에 세 가지 시험의 결과(나갈 주문과 나가지 않을 주문, 또는 검사에 걸린 이유)가 출력되었는지, 'approvals_log.json'에 이력이 쌓였는지 확인해줘.
```

---

### 내 눈으로 확인할 체크리스트

- [ ] 승인으로 고친 매수는 나갈 주문에, 고치지 않은 매수는 나가지 않을 주문에 들어갔다.
- [ ] 수량을 바꾼 파일은 검사에 걸려 매수가 나가지 않았다.
- [ ] 시험용 파일을 직접 열어 승인 상태를 고쳐 보고, 다시 검사해 결과가 바뀌는 것을 확인했다.
