# 주문 목록을 확인하고 승인·거절하는 절차 만들기

## 이번 클립에서 만들 것

장 마감 뒤 만들어진 주문 목록 파일을 열어 **매수의 승인 상태를 고쳐 두는 절차**와, 고친 파일을 검사하는 프로그램(`approve_orders.py`)을 만듭니다.

> 💡 고치지 않으면 매수는 나가지 않습니다. 확인을 놓쳐도 위험이 늘지 않습니다.

- 파일에서 승인하는 방법
- 고친 파일 검사하기
- **실습 18**: 내 주문 목록에서 매수 승인하기, `approve_orders.py` 작성 및 검사

---

## 이론 핵심

### 1. 승인은 파일에서 직접 합니다

장 마감 후 가장 최근 날짜의 주문 목록 파일을 엽니다. 매도는 '자동', 매수는 '승인 대기'로 적혀 있습니다.

```json
{
  "신호 기준일": "2026-10-02",
  "주문": [
    { "매수/매도": "매도", "종목명": "하나금융지주", "수량": 5, "예상 금액": 450000,
      "이유": "페어 스위칭이 KB금융으로 교체", "승인 상태": "자동", "메모": "" },
    { "매수/매도": "매수", "종목명": "KB금융", "수량": 3, "예상 금액": 520000,
      "이유": "페어 스위칭이 KB금융으로 교체", "승인 상태": "승인 대기", "메모": "" }
  ]
}
```

1. 종목, 수량, 예상 금액, 이유를 확인합니다.
2. 매수의 `승인 대기`를 `승인` 또는 `거절`로 고쳐 저장합니다. 거절이면 `메모`에 사유를 적습니다.
3. 승인 상태와 메모 말고는 고치지 않습니다.

직접 고치기 번거로우면 Claude Code에게 "오늘 주문 목록에서 KB금융 매수를 승인으로 바꿔줘"라고 요청해도 됩니다.

---

### 2. 고친 파일은 주문 전에 검사합니다

손으로 고친 파일이 그대로 주문이 되므로, 형식이 깨졌거나 승인 상태 말고 다른 값(수량 등)이 바뀌었으면 매수를 내보내지 않습니다.

| 방식 | 매수 | 쓰는 때 |
|---|---|---|
| **승인 방식** (기본) | 내가 승인해야 나감 | 처음 시작할 때 |
| **자동 방식** | 승인하지 않아도 나감. 내가 '거절'로 고친 매수는 안 나감 | 시스템에 익숙해진 뒤 |

---

## 실습 — 실습 18: 주문 목록 승인하고 검사하기

### 먼저: 내 손으로 승인하기

1. VS Code에서 가장 최근 날짜의 주문 목록 파일(`orders_날짜.json`)을 엽니다.
2. 매수 주문 하나의 `승인 상태`를 `승인 대기`에서 `승인`으로 고치고 저장합니다. 거절하고 싶은 매수가 있으면 `거절`로 고치고 `메모`에 사유를 적습니다.
3. 나머지는 그대로 둡니다. 매수가 여럿이면 하나는 `승인 대기`로 남겨 두세요. 승인한 것과 하지 않은 것이 어떻게 갈리는지 바로 다음에 봅니다.

주문 목록이 비어 있는 날이면 이 단계는 건너뜁니다. 검사 결과도 비어 있고, 그것이 정상입니다.

### 이어서: 검사 프로그램 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 내가 고친 주문 목록과 원본(`logs/orders_날짜_original.json`)을 읽고, 승인·거절 기록을 `approvals_log.json`에 쌓습니다.

```prompt
[맥락] 장 마감 후 만든 주문 목록('orders_기준일.json')에서 내가 매수의 승인 상태를 '승인'이나 '거절'로 고쳐 두었어. 고친 파일이 올바른지 검사하고, 다음 개장 때 나갈 주문을 정리하는 프로그램을 만들고 싶어. 고치기 전 원본은 'logs/(주문 목록 파일 이름)_original.json'에 있어.

[만들 것] 파이썬 스크립트 'approve_orders.py'를 작성하고 실행해줘:
1. 가장 최근 확정 종가일의 주문 목록을 원본과 비교해 검사해줘. 그날 파일이 없으면 이전 파일을 쓰지 말고 '주문 목록이 만들어지지 않았음'이라고 알려줘.
2. 아래 중 하나라도 걸리면 무엇이 잘못됐는지 알려 주고, 매수는 모두 '나가지 않을 주문'으로 처리해.
   - 파일이 깨져서 읽을 수 없음
   - 매도가 '자동'이 아니거나, 매수가 '승인 대기'·'승인'·'거절' 중 하나가 아님
   - 승인 상태와 메모 말고 다른 값이 원본과 다름
3. 통과하면 [나갈 주문: 매도와 승인된 매수]와 [나가지 않을 주문]을 표로 보여 주고, 'approvals_log.json'에 [검사 시각, 신호 기준일, 종목코드, 매수/매도, 수량, 승인 상태, 메모]를 덧붙여줘.
4. 자동 방식도 만들어줘. 자동 방식으로 실행하면 '승인 대기'인 매수만 '승인'으로 바꾸고(메모에 '자동 방식') 같은 검사를 거쳐. 내가 '거절'로 고친 매수는 그대로 둬. 어떻게 실행하는지는 네가 정하고 알려줘.
5. 다른 프로그램도 이 검사를 그대로 가져다 쓸 수 있게 해줘. 검사할 파일을 정해서 넘길 수 있어야 해.
6. 지금 내 주문 목록으로 한 번 실행해 결과를 보여줘.

[하지 말 것]
- 주문을 보내지 마. 검사하고 기록만 해.
- 주문 목록의 승인 상태를 네가 바꾸지 마(자동 방식은 예외). 검사에 걸린 파일을 고쳐서 통과시키지도 마.

[확인] 나갈 주문과 나가지 않을 주문 표, 'approvals_log.json' 기록, 자동 방식을 실행하는 방법을 보여줘.
```

---

### 내 눈으로 확인할 체크리스트

- [ ] 내가 승인으로 고친 매수만 나갈 주문에 들어갔고, 그대로 둔 매수는 나가지 않을 주문에 있다.
- [ ] `approvals_log.json`에 오늘 검사 기록이 남았다.
