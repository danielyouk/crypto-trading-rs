# 주문 목록을 확인하고 승인·거절하는 절차 만들기

## 이번 클립에서 만들 것

장 마감 뒤 만들어진 주문 목록 파일을 열어 **매수의 승인 상태를 고쳐 두는 절차**와, 고친 파일을 검사하는 프로그램(`approve_orders.py`)을 만듭니다.

> 💡 고치지 않으면 매수는 나가지 않습니다. 확인을 놓쳐도 위험이 늘지 않습니다.

- 파일에서 승인하는 방법
- 고친 파일 검사하기
- **실습 18**: `approve_orders.py` 작성 및 승인·거절 시험

---

## 이론 핵심

### 1. 승인은 파일에서 직접 합니다

장 마감 후 가장 최근 날짜의 주문 목록 파일을 엽니다. 매도는 '자동', 매수는 '승인 대기'로 적혀 있습니다.

```json
{
  "신호 기준일": "2026-10-05",
  "주문": [
    { "매수/매도": "매도", "종목명": "하나금융지주", "수량": 5, "예상 금액": 450000,
      "이유": "페어 스위칭이 KB금융으로 교체", "승인 상태": "자동", "메모": "" },
    { "매수/매도": "매수", "종목명": "KB금융", "수량": 3, "예상 금액": 520000,
      "이유": "페어 스위칭이 KB금융으로 교체", "승인 상태": "승인 대기", "메모": "" }
  ]
}
```

1. 종목, 수량, 예상 금액, 이유를 확인합니다.
2. 매수의 `승인 대기`를 `승인` 또는 `거절`로 고쳐 저장합니다. 거절이면 `메모`에 사유를 적습니다.
3. 승인 상태와 메모 말고는 고치지 않습니다.

직접 고치기 번거로우면 Claude Code에게 "오늘 주문 목록에서 KB금융 매수를 승인으로 바꿔줘"라고 요청해도 됩니다.

---

### 2. 고친 파일은 주문 전에 검사합니다

손으로 고친 파일이 그대로 주문이 되므로, 형식이 깨졌거나 승인 상태 말고 다른 값(수량 등)이 바뀌었으면 매수를 내보내지 않습니다.

| 방식 | 매수 | 쓰는 때 |
|---|---|---|
| **승인 방식** (기본) | 내가 승인해야 나감 | 처음 시작할 때 |
| **자동 방식** | 승인하지 않아도 나감. 내가 '거절'로 고친 매수는 안 나감 | 시스템에 익숙해진 뒤 |

---

## 실습 — 실습 18: 승인 상태 검사 프로그램 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 주문 목록과 원본을 읽고, 승인·거절 기록을 `approvals_log.json`에 쌓습니다. 실습은 시험용 파일로 합니다.

```prompt
[맥락] 장 마감 후 만든 주문 목록('orders_기준일.json')을 내가 직접 열어 매수의 승인 상태를 고쳐 둘 거야. 고친 파일이 올바른지 검사하고, 다음 개장 때 나갈 주문을 정리하는 프로그램을 만들고 싶어. 원본은 'logs/(주문 목록 파일 이름)_original.json'에 있어.

[만들 것] 파이썬 스크립트 'approve_orders.py'를 작성하고 실행해줘:
1. 가장 최근 확정 종가일의 주문 목록을 원본과 비교해 검사해줘. 아래 중 하나라도 걸리면 이유를 알려 주고 매수는 모두 내보내지 않아: JSON 형식 오류 / 매도가 '자동'이 아니거나 매수가 '승인 대기'·'승인'·'거절'이 아님 / 승인 상태와 메모 말고 다른 값이 원본과 다름. 그날 파일이 없으면 이전 파일을 쓰지 말고 '주문 목록이 만들어지지 않았음'이라고 알려줘.
2. 통과하면 [나갈 주문: 매도와 승인된 매수]와 [나가지 않을 주문]을 표로 보여 주고, 'approvals_log.json'에 [검사 시각, 신호 기준일, 종목, 매수/매도, 수량, 승인 상태, 메모]를 덧붙여줘.
3. '--auto'를 붙이면 '승인 대기'인 매수만 '승인'으로 바꾸고(메모 '자동 방식') 같은 검사를 거쳐. 내가 '거절'로 고친 매수는 그대로 둬.
4. 다른 프로그램이 이 검사를 함수로 불러 쓸 수 있게 해줘.
5. 시험용 'orders_test.json'과 그 원본(KB금융 3주 매수, 하나금융지주 5주 매도)을 만들어 '--file'로 넘겨, 세 경우를 시험해줘: 매수를 승인으로 고침 / 아무것도 안 고침 / 승인하면서 수량을 30주로 바꿈.

[하지 말 것]
- 주문 API를 부르지 마.
- 실제 주문 목록의 승인 상태를 네가 정하지 마('--auto'는 예외). 검사에 걸린 파일을 고쳐서 통과시키지도 마.

[확인] 세 시험의 결과와 'approvals_log.json' 기록을 보여줘.
```

---

### 내 눈으로 확인할 체크리스트

- [ ] 승인으로 고친 매수만 나갈 주문에 들어갔다.
- [ ] 수량을 바꾼 파일은 검사에 걸려 매수가 나가지 않았다.
