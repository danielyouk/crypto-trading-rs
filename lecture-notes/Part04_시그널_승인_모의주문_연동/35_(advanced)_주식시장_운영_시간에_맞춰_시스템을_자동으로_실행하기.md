# (Advanced) 주식시장 운영 시간에 맞춰 시스템을 자동으로 실행하기

## 이번 클립에서 만들 것

이 클립이 끝나면, 여러분은 리눅스/Mac의 **크론탭(Crontab)**이나 윈도우의 **작업 스케줄러(Task Scheduler)**(둘 다 정해진 시각에 프로그램을 자동으로 켜 주는 기능)를 활용하여, 한국 주식 시장의 운영 시간표에 맞춰 **아침 08:30 시그널 생성, 09:00~15:20 실시간 매매/하드 손절 감시, 15:40 일일 매매 일지 작성**을 100% 무인으로 스스로 실행하는, 여러 프로그램을 시간표대로 차례로 켜고 끄는 **'자동화 오케스트레이션'**을 구축하게 됩니다.

> 💡 **수강생 안심 안내**: 크론탭 설정이 낯설더라도 걱정하지 마세요. Claude Code에게 내 컴퓨터 종류(Mac/Linux/Windows)를 알려주면 정확한 스케줄러 등록 방법과 마스터 실행 스크립트(`orchestrator.py`)를 자동으로 완성해 줍니다.

- 한국거래소(KRX) 정규장 시간표와 시간대별로 돌릴 프로그램 짝짓기
- 크론탭의 예약 시각 적는 법(크론 표현식)과, 예약 실행 때도 작업 폴더의 파이썬(`.venv`)을 쓰게 하는 방법
- 모든 단계를 순서대로 부르는 마스터 실행기 `orchestrator.py`의 설계
- 실행 기록(로그) 파일을 날짜별로 나눠 보관(`logs/system_YYYYMMDD.log`)
- **실습 23**: 전체 파이프라인 무인 스케줄링 등록 및 통합 시뮬레이션

## 이론 핵심

### 1. 주식시장 타임테이블과 시스템 작업 맵핑

아래 시간표의 **상주 루프**는 한 번 켜지면 장이 끝날 때까지 쉬지 않고 같은 확인을 되풀이하는 부분입니다. 모의투자 서버는 계좌당 **초당 1회**만 요청을 받으므로(2026년 4월 기준), 오케스트레이터 안의 상주 루프 **하나**가 1초에 한 번씩 요청을 보내며 변동성 돌파 감시와 하드 가드레일 점검을 번갈아 합니다. 그래서 각 감시는 약 2초마다 돌고, 기준에 닿으면 다음 요청 차례에 바로 주문을 냅니다. 주문은 매수든 청산이든 모두 `execute_orders.py`의 주문 함수로만 나갑니다. 클립 01에서 "0.1초 감시"라고 소개한 것은 판정한 뒤 주문을 만드는 계산이 그만큼 빠르다는 뜻이고, 가격을 확인하는 간격은 증권사 호출 한도가 정합니다.

```text
[08:30] ──> ① 사전 점검 & 당일 시그널 생성 (generate_signals.py)
              • 토큰 갱신, 계좌 잔고 확인, 주간 정책(weekly_policy.json) 유효성 검사
              • 전일 종가로 판정이 끝난 추세추종·듀얼 모멘텀·페어 신호를 signals.json에 기록

[09:00] ──> ② 개장 시가 주문 집행 (execute_orders.py)
              • signals.json에 적힌 추세추종/듀얼 모멘텀/페어 진입을 시가에 발주

[09:00 ~ 15:20] ──> ③·④ 장중 상주 루프 (orchestrator.py 안에서 1초에 요청 하나씩, 둘을 번갈아)
                      ③ 변동성 돌파 감시: realtime_signals.py로 KODEX 레버리지 현재가와 당일 목표가를
                         대조, 돌파하면 execute_orders.py로 매수
                      ④ 하드 가드레일: risk_guard.py로 잔고를 조회해 개별 종목 -3% 또는 계좌 -2%에
                         닿으면 사람에게 묻지 않고 execute_orders.py로 청산

[15:20] ──> ⑤ 변동성 돌파 당일 보유분 청산 (orchestrator.py가 execute_orders.py로 시장가 전량 매도)
              • 15:20~15:30은 주문을 모았다가 한 가격(종가)으로 체결하는 시간이라, 이때 낸 시장가 매도는 종가에 체결됨
[15:40] ──> ⑥ 장 마감 후 일일 AI 매매 일지 작성 (daily_journal.py)
```

### 2. 크론탭(Crontab) 설정 예시

```bash
# 월~금(1-5) 08:25에 오케스트레이터 하나만 띄웁니다.
# 08:30 시그널부터 15:40 일지까지 시각별 작업과 장중 상주 루프는 오케스트레이터가 스스로 챙깁니다.
25 8 * * 1-5 /path/to/ai-trading/.venv/bin/python /path/to/ai-trading/orchestrator.py >> /path/to/ai-trading/logs/cron.log 2>&1
```

**한 줄 읽는 법**: 앞의 다섯 칸이 예약 시각(크론 표현식)이고, 그 뒤가 실행할 명령입니다.

| 칸 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 뜻 | 분 | 시 | 날짜 | 달 | 요일 (1=월 … 5=금) |
| `25 8 * * 1-5` | 25분 | 8시 | 상관없음(`*`) | 상관없음(`*`) | 월~금 |

- 줄 끝의 `>> .../cron.log`는 프로그램이 화면에 찍는 내용을 그 파일 끝에 이어 적으라는 뜻이고, `2>&1`은 에러 메시지도 같은 파일에 함께 적으라는 뜻입니다. 예약 실행은 화면이 없으니 이렇게 남겨야 나중에 무슨 일이 있었는지 볼 수 있습니다.
- 파이썬을 `.venv/bin/python`으로 직접 적는 이유는, 예약 실행은 터미널에서처럼 가상환경을 켜 주지 않기 때문입니다. 이렇게 적어야 라이브러리를 설치해 둔 작업 폴더의 파이썬으로 실행됩니다.

## 실습 — 실습 23: 무인 자동화 오케스트레이터 구축

Claude Code 대화창에 아래 프롬프트를 입력하세요.

```prompt
[맥락] 한국 주식 시장 운영 시간에 맞춰 전체 퀀트 시스템을 자동으로 스케줄링하는 마스터 오케스트레이터를 완성하고 싶어.

[만들 것] 다음 조건에 맞춰 스크립트와 가이드를 작성하고 실행해줘:
1. 아침 시그널 생성(08:30, generate_signals.py) ➔ 개장 발주(09:00, execute_orders.py) ➔ 장중 상주 루프(09:00~15:20) ➔ 15:20 변동성 돌파 청산 ➔ 장 마감 일지(15:40, daily_journal.py)를 시각에 맞춰 차례로 실행하는 마스터 파이썬 스크립트 'orchestrator.py'를 작성해줘. 모의투자 서버는 계좌당 초당 1회만 요청을 받으니, 상주 루프는 하나만 두고 1초에 한 번씩 요청을 보내며 변동성 돌파 감시(realtime_signals.py)와 하드 가드레일 점검(risk_guard.py)을 번갈아 해줘. 매수든 청산이든 주문은 모두 execute_orders.py의 주문 함수로만 보내고, 15:20에는 변동성 돌파 당일 보유분을 execute_orders.py로 시장가 전량 매도한 뒤 상주 루프를 끝내.
2. 내 컴퓨터 종류에 맞는 예약 실행 등록 가이드(Mac/Linux의 경우 crontab 파일, Windows의 경우 schtasks 스크립트)를 'docs/scheduler_setup.md'로 작성해줘. 예약은 orchestrator.py 하나를 평일 08:25에 실행하는 것 한 줄이면 돼.
3. 모든 실행 출력과 에러 내용이 날짜별 로그 파일('logs/system_YYYYMMDD.log')로 안전하게 자동 저장되도록 로깅 시스템을 구성해줘.
4. 전체 파이프라인을 처음부터 끝까지 한 번 도는 드라이런(실제 주문은 보내지 않고 흐름만 끝까지 돌려 보는 시험 실행)을 실행하여 정상 작동을 증명해줘. 드라이런에서는 상주 루프를 한 바퀴만 돌리고 다음 단계로 넘어가.

[하지 말 것]
- 드라이런에서는 실제 주문 API를 호출하지 마. 각 단계가 순서대로 호출되고 로그가 남는지만 확인해.
- 스케줄러(crontab/schtasks)에 내 확인 없이 자동 등록하지 마. 가이드 문서만 쓰고 등록은 내가 직접 한다.
- 어느 한 단계가 실패했을 때 다음 단계로 그냥 넘어가지 마. 실패를 로그에 남기고 이후 단계는 건너뛰어.

[확인] 대화창에 드라이런 완료 로그(아침 시그널 ➔ 개장 발주 ➔ 변동성 돌파 감시 ➔ 하드 가드레일 ➔ 15:20 변동성 돌파 청산 ➔ 장 마감 일지의 6단계 순차 호출)가 출력되었는지, 'logs/' 폴더에 날짜별 로그 파일이 생겼는지, 그리고 'docs/scheduler_setup.md' 경로가 표시되었는지 확인해줘.
```

### 내 눈으로 확인할 체크리스트

- [ ] 마스터 오케스트레이터(`orchestrator.py`)가 전체 모듈을 순서대로 에러 없이 호출했다.
- [ ] 드라이런 로그에 15:20 변동성 돌파 청산 단계가 빠지지 않았다.
- [ ] 스케줄러 가이드가 `orchestrator.py` 하나를 평일 08:25에 실행하도록 되어 있고, 장중 상주 루프(변동성 돌파 감시와 하드 가드레일을 1초씩 번갈아)가 오케스트레이터 안에 들어 있는지 확인했다. 이게 없으면 장중 감시가 아예 돌지 않는다.
- [ ] `logs/` 폴더에 날짜별 통합 시스템 로그가 기록되는 것을 확인했다.
- [ ] 평일 아침부터 장 마감까지 컴퓨터가 스스로 시스템을 안전하게 운용할 준비를 마쳤다.
