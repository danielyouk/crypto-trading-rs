# (advanced) 주식시장 운영 시간에 맞춰 시스템을 자동으로 실행하기

## 이번 클립에서 만들 것

지금까지 만든 프로그램을 **장 시간표에 맞춰 차례로 실행하는 프로그램(`orchestrator.py`)**을 만들고, 컴퓨터의 예약 실행 기능으로 평일 아침마다 자동으로 켜지게 합니다. 예약 실행 기능은 리눅스/Mac에서는 **크론탭(Crontab)**, 윈도우에서는 **작업 스케줄러(Task Scheduler)**라고 부릅니다.

> 💡 크론탭 설정이 낯설어도 괜찮습니다. Claude Code에게 내 컴퓨터 종류(Mac/Linux/Windows)를 알려 주면 등록 방법을 문서로 정리해 줍니다.

- 하루 시간표와 시간대별로 실행할 프로그램
- 크론탭의 예약 시각 적는 법(크론 표현식)
- 실행 기록(로그)을 날짜별로 남기기
- **실습 23**: `orchestrator.py` 작성 및 드라이런

## 이론 핵심

### 1. 하루 시간표

```text
[08:50] ① 개장 전 점검
          • 접근 토큰 갱신, orders.json이 가장 최근 종가로 만든 것인지 확인
          • 승인 방식이면 사람이 전날 장 마감 후 고쳐 둔 승인 상태를 검사 (approve_orders.py)
          • 자동 방식이면 매수 주문을 모두 승인 처리 (approve_orders.py --auto)

[09:00] ② 개장 주문 (execute_orders.py)
          • 매도와 승인된 매수를 보냄. 주문 목록이 비어 있으면 건너뜀
          • 체결 결과를 이메일로 알림

[09:00 ~ 15:30] ③ 장중 상주 루프 (risk_guard.py)
          • 1~2초마다 잔고를 조회해 개별 종목 -3% 또는 계좌 -2%에 닿으면 바로 청산

[15:40] ④ 장 마감 후
          • generate_signals.py ➔ prepare_orders.py ➔ daily_journal.py 순서로 실행
          • 사람은 이 주문 목록을 보고 다음 날 개장 전까지 매수를 승인
```

**상주 루프**는 한 번 켜지면 장이 끝날 때까지 같은 확인을 되풀이하는 부분입니다. 모의투자 서버는 계좌당 **초당 1회**만 요청을 받으므로(2026년 4월 기준), 요청 사이에 1초씩 쉽니다.

대부분의 날은 ②에서 아무 주문도 나가지 않고, ④에서 만든 주문 목록도 비어 있습니다. 매일 돌아가는 것은 확인이고, 주문은 신호가 바뀐 날에만 나갑니다.

### 2. 크론탭(Crontab) 설정 예시

```bash
# 월~금(1-5) 08:45에 오케스트레이터 하나만 띄웁니다.
# 08:50 점검부터 15:40 장 마감 후 작업까지는 오케스트레이터가 스스로 챙깁니다.
45 8 * * 1-5 cd /path/to/ai-trading && .venv/bin/python orchestrator.py >> logs/cron.log 2>&1
```

**한 줄 읽는 법**: 앞의 다섯 칸이 예약 시각(크론 표현식)이고, 그 뒤가 실행할 명령입니다.

| 칸 | 1 | 2 | 3 | 4 | 5 |
|---|---|---|---|---|---|
| 뜻 | 분 | 시 | 날짜 | 달 | 요일 (1=월 … 5=금) |
| `45 8 * * 1-5` | 45분 | 8시 | 상관없음(`*`) | 상관없음(`*`) | 월~금 |

- 명령 맨 앞의 `cd /path/to/ai-trading &&`는 작업 폴더로 먼저 옮겨 간 뒤 실행하라는 뜻입니다. 예약 실행은 터미널과 달리 홈 폴더에서 시작하므로, 옮겨 가지 않으면 프로그램이 `orders.json` 같은 파일을 엉뚱한 폴더에서 찾습니다.
- 줄 끝의 `>> logs/cron.log`는 프로그램이 화면에 찍는 내용을 그 파일 끝에 이어 적으라는 뜻이고, `2>&1`은 에러 메시지도 같은 파일에 함께 적으라는 뜻입니다. 예약 실행은 화면이 없으니 이렇게 남겨 둡니다.
- 파이썬을 `.venv/bin/python`으로 직접 적는 이유는, 예약 실행은 터미널에서처럼 가상환경을 켜 주지 않기 때문입니다. 이렇게 적어야 라이브러리를 설치해 둔 작업 폴더의 파이썬으로 실행됩니다.
- 공휴일에는 장이 열리지 않습니다. 쉬는 날에 켜져 주문을 보내더라도 증권사가 받지 않으며, 그 실패는 기록과 알림으로 남습니다.

## 실습 — 실습 23: 시간표대로 실행하는 프로그램 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 앞에서 만든 프로그램들과 `orders.json`을 읽고, 실행 기록을 `logs/system_YYYYMMDD.log`에, 예약 등록 안내를 `docs/scheduler_setup.md`에 저장합니다. 드라이런에서도 장 마감 후 단계는 그대로 실행되어 `signals.json`, `orders.json`, `logs/orders_original.json`을 새로 만듭니다. 매수를 승인해 둔 뒤에 드라이런을 돌렸다면 `orders.json`의 승인 상태를 다시 확인하세요.

```prompt
[맥락] 한국 주식 시장 운영 시간에 맞춰, 작업 폴더에 있는 프로그램들(generate_signals.py, prepare_orders.py, approve_orders.py, notifier.py, execute_orders.py, risk_guard.py, daily_journal.py)을 차례로 실행하는 프로그램을 만들고 싶어. 먼저 이 파일들을 읽어 각각 어떤 함수와 실행 옵션이 있는지 확인하고 시작해줘.

[만들 것] 다음 조건에 맞춰 스크립트와 가이드를 작성하고 실행해줘:
1. 파이썬 스크립트 'orchestrator.py'를 작성해줘. 어느 폴더에서 실행하든(예약 실행 포함) 작업 폴더의 파일을 읽고 쓰게 해줘. 맨 위에 실행 방식('승인' 또는 '자동', 기본값 '승인')을 두고, 아래 시간표대로 실행해:
   - 08:50 개장 전 점검: 접근 토큰 갱신, orders.json이 있는지 확인. 실행 방식이 '승인'이면 approve_orders.py를 옵션 없이 실행해 검사만 하고, '자동'이면 '--auto'로 실행
   - 09:00 개장 주문: execute_orders.py를 옵션 없이 실행한 것과 같게 매도와 승인된 매수를 보냄. 보낼 주문이 없으면 건너뜀
   - 09:00 ~ 15:30 장중 상주 루프: risk_guard.py의 점검 함수를 '--live'로 실행한 것과 같게 되풀이 호출. 모의투자 서버는 계좌당 초당 1회만 요청을 받으니 루프는 하나만 두고 요청 사이에 최소 1초를 둬
   - 15:40 장 마감 후: generate_signals.py ➔ prepare_orders.py ➔ daily_journal.py 순서로 실행. 승인은 사람이 주문 목록 파일에서 하므로 이 단계에서 승인하거나 묻지 마
2. 내 컴퓨터 종류에 맞는 예약 실행 등록 가이드(Mac/Linux는 crontab, Windows는 schtasks)를 'docs/scheduler_setup.md'로 작성해줘. 예약은 orchestrator.py 하나를 평일 08:45에 실행하는 것 한 줄이면 돼.
3. 모든 실행 출력과 에러 내용이 날짜별 로그 파일('logs/system_YYYYMMDD.log')에 저장되게 해줘.
4. 'orchestrator.py'를 '--dry-run'으로 실행하면 전체 흐름을 처음부터 끝까지 한 번 도는 드라이런(실제 주문은 보내지 않고 흐름만 끝까지 돌려 보는 시험 실행)이 되게 해줘. 드라이런에서는 시각을 기다리지 말고 바로 다음 단계로 넘어가고, 상주 루프는 한 바퀴만 돌리고, 주문 단계는 execute_orders.py의 '--dry-run'과 risk_guard.py의 옵션 없는 실행(주문 없이 점검만)을 써. 이 실습에서는 '--dry-run'으로만 실행해줘.
5. 옵션 없이 실행했을 때 이미 지난 시각의 단계는 건너뛰고 그 사실을 로그에 남겨. 단, 장중(09:00 ~ 15:30)에 시작했으면 상주 루프는 바로 시작해.

[하지 말 것]
- 드라이런에서는 실제 주문 API를 호출하지 마. 각 단계가 순서대로 호출되고 로그가 남는지만 확인해.
- 실행 방식이 '승인'일 때 오케스트레이터가 매수를 대신 승인하지 마. 승인 대기인 매수는 보내지 않고 넘어가.
- 주문은 모두 execute_orders.py의 주문 함수로만 보내. 오케스트레이터에 주문 코드를 따로 만들지 마.
- 스케줄러(crontab/schtasks)에 내 확인 없이 자동 등록하지 마. 가이드 문서만 쓰고 등록은 내가 직접 한다.
- 어느 한 단계가 실패했을 때 다음 단계로 그냥 넘어가지 마. 실패를 로그에 남기고 '오류' 알림을 보낸 뒤, 그 결과를 써야 하는 뒤 단계만 건너뛰어(08:50 점검이 실패하면 09:00 개장 주문을, 15:40에 앞 프로그램이 실패하면 그 뒤 프로그램을 건너뜀). 장중 상주 루프(안전장치)와 15:40 장 마감 후 단계는 그 앞 시간대의 단계가 실패해도 실행해. 그래야 다음 날 주문 목록이 새로 만들어져.
- approve_orders.py 검사에 걸린 것은 단계 실패로 보지 마. 걸린 이유를 로그에 남기고 '오류' 알림으로 '검사에 걸려 매수는 보내지 않음'을 알린 뒤, 09:00 개장 주문과 15:40 장 마감 후 단계를 그대로 실행해(이때 execute_orders.py는 매도만 보냄).
- 기존 프로그램 파일을 수정하지 마.

[확인] 대화창에 드라이런 로그(개장 전 점검 ➔ 개장 주문 ➔ 장중 안전장치 ➔ 장 마감 후 신호·주문 목록·일지)가 순서대로 출력되었는지, 'logs/' 폴더에 날짜별 로그 파일이 생겼는지, 'docs/scheduler_setup.md' 경로가 표시되었는지 확인해줘.
```

### 내 눈으로 확인할 체크리스트

- [ ] 드라이런에서 `orchestrator.py`가 네 단계를 순서대로 호출했고, 실제 주문은 나가지 않았다.
- [ ] 실행 방식이 '승인'일 때 승인 대기인 매수를 건너뛰는지 확인했다.
- [ ] `docs/scheduler_setup.md`에 평일 08:45 예약 한 줄이 있고, `logs/` 폴더에 날짜별 로그가 쌓였다.
