# 주식시장 운영 시간에 맞춰 시스템을 자동으로 실행하기

## 이번 클립에서 만들 것

지금까지 만든 프로그램을 **장 마감 후 작업**과 **개장 작업** 두 개로 묶고, 컴퓨터의 예약 실행 기능(윈도우 **작업 스케줄러**, Mac **launchd**)에 등록해 장 운영 시간에 맞춰 저절로 돌게 합니다. 예약을 걸지 않고 저녁과 아침에 두 작업을 직접 실행해도 똑같이 돌아갑니다. 프롬프트는 프로그램을 만들 때 한 번만 쓰고, 운용할 때는 프롬프트 없이 이 두 작업만 돌립니다.

- 하루에 두 번 실행하는 이유
- 윈도우와 Mac에서 예약 실행 등록하기 (예약 없이 직접 실행해도 됨)
- **실습 23**: 장 마감 후 작업과 개장 작업 만들기, 안내 문서대로 예약 등록하기

---

## 이론 핵심

### 1. 하루 전체 흐름 — 프로그램 두 번, 사람 한 번

지금까지 만든 프로그램은 아래 순서로 이어집니다. 예약 실행에 올리는 것은 **장 마감 후 작업**과 **개장 작업** 두 개이고, 그 사이의 승인은 사람이 합니다.

```text
[17:00 장 마감 후 작업] run_after_close.py
  ① generate_signals.py   오늘 종가로 신호 계산 — 전략별로 "무엇을 몇 주 들고 있어야 하나"   → signals_날짜.json
  ② prepare_orders.py     그 목표와 계좌의 실제 보유를 비교해 "그래서 몇 주를 사고팔지"       → orders_날짜.json (매도 '자동', 매수 '승인 대기')
  ③ daily_journal.py      오늘 일지 — 체결 결과와 다음 거래일 주문, 승인 대기 건수            → docs/daily_journal_날짜.md
        ↓
[저녁 ~ 다음 날 08:50 전] 사람이 하는 유일한 일
  일지를 읽고 orders_날짜.json에서 매수의 '승인 대기'를 '승인' 또는 '거절'로 고쳐 저장
        ↓
[08:50 개장 작업] run_market_open.py
  ⓪ 08:50  generate_signals.py → prepare_orders.py
                              어젯밤 작업이 돌았으면 이미 있는 목록 그대로. 안 돌았으면 지금 만듦(매수는 승인 대기)
  ① 08:50  risk_guard.py      아침 계좌 총자산 기록                                    → logs/day_start_asset.json
  ② 09:00  execute_orders.py  approve_orders.py의 검사로 고친 목록을 원본과 대조
                              통과 → 매도, 체결 뒤 승인된 매수                            → orders_history.json, approvals_log.json
                              걸림 → 매수는 보내지 않고 매도만
  ③ 장중    risk_guard.py      15:30까지 1분마다 감시. 아침보다 3% 이상 줄면 모두 매도 → 메일 → lock.flag
```

- **승인 검사(`approve_orders.py`)가 따로 안 보이는 이유**: 주문 프로그램이 주문을 보내기 직전에 스스로 이 검사를 거칩니다. 그래서 예약 작업에 따로 올릴 것이 없습니다.
- **17:00**: 장은 15:30에 끝나지만 종가가 데이터에 반영되기까지 시간이 걸려 여유를 둡니다.
- **08:50**: 장이 열리기 전에 계좌 총자산을 찍어 두어야 그날 손실을 잴 수 있습니다. 주문은 09:00에 보냅니다. 모의투자에는 저녁에 주문을 맡겨 두는 **예약주문**이 없어서, 장이 열릴 때 프로그램이 직접 보냅니다.
- **장중 15:30까지**: 개장 작업(`run_market_open.py`)이 켜진 채로 `risk_guard.py`를 1분마다 돌립니다. 장중에 급락이 와도 사람이 컴퓨터 앞에 없을 때 알아서 모두 팔고, 그 뒤에 메일이 옵니다.
- **⓪은 안전망입니다.** 어젯밤 장 마감 후 작업이 돌았으면 오늘 만들 목록의 날짜가 이미 있는 목록과 같아서 아무것도 바뀌지 않습니다(승인해 둔 상태 그대로). 어젯밤 작업이 안 돌았으면(컴퓨터가 꺼져 있었거나 등록 전) 그때 목록이 만들어지고, 매수는 승인 대기라 나가지 않고 **매도만** 나갑니다. 빠진 매수는 그날 저녁 목록에 다시 올라옵니다.

**예약은 선택입니다.** 등록하지 않았다면 장 마감 후에 장 마감 후 작업을, 장이 열리기 전에 개장 작업을 직접 실행합니다. 하는 일은 같고, 컴퓨터가 대신 켜 주느냐 내가 켜느냐만 다릅니다. 개장 작업은 15:30까지 켜 둔 채 두어야 장중 안전장치가 돕니다.

### 2. 윈도우와 Mac에서 예약 실행하기

예약 실행에는 **실행 파일**을 등록합니다. 작업 폴더로 옮겨 간 뒤 그 폴더 가상환경의 파이썬으로 프로그램을 돌리는 몇 줄짜리 파일입니다. 예약 실행은 터미널과 달리 작업 폴더와 가상환경을 잡아 주지 않아서 이렇게 적어 둡니다. 윈도우용은 대략 이런 모양이고, AI가 내 작업 폴더 경로를 넣어 만들어 줍니다.

```bat
@echo off
cd /d C:\ai-trading
.venv\Scripts\python.exe run_after_close.py
```

| | 윈도우 | Mac |
|---|---|---|
| 예약 실행 기능 | 작업 스케줄러 (`schtasks` 명령) | launchd (`launchctl` 명령) |
| 실행 파일 | `.bat` | `.sh` |
| 예약 설정이 저장되는 곳 | 작업 스케줄러 라이브러리 | `~/Library/LaunchAgents` 폴더의 `.plist` 파일 |

등록 절차는 AI가 **내 컴퓨터에 맞춰 쓴 `docs/scheduler_setup.md`**를 따릅니다(실습에서 만듭니다). 영상은 윈도우로 보여 주지만, 문서가 내 컴퓨터용으로 만들어지므로 Mac도 같은 순서입니다. 등록한 뒤에는 작업을 바로 한 번 실행해 **실행 기록**에 남는지 봅니다. 실행 기록은 두 작업이 돌 때마다 언제 켜져서 어디까지 갔는지를 적는 파일로, `logs/` 폴더에 날짜별로 하나씩(`logs/run_날짜.log`) 생깁니다. 그 시각에 할 일이 없으면 "휴장일" 또는 "장 시간 아님"에서 멈추는데, 그것으로 예약이 실행 파일까지 제대로 이어진 것은 확인된 셈입니다.

자동으로 도는 것은 **실행 시각**뿐입니다. 매수는 여전히 내가 미리 승인한 것만 나가고, 승인하지 않은 매수는 나가지 않습니다.

## 실습 — 실습 23: 장 운영 시간에 맞춰 실행되는 작업 만들기

### 먼저: 두 작업과 실행 파일 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 앞에서 만든 프로그램들을 불러 쓰고, 실행 기록을 `logs/run_YYYYMMDD.log`에, 등록 안내를 `docs/scheduler_setup.md`에 저장합니다. 같은 날짜의 주문 목록이 이미 있으면 덮어쓰지 않으므로, 고쳐 둔 승인 상태는 그대로 남습니다.

```prompt
[맥락] 작업 폴더의 프로그램들(generate_signals, prepare_orders, daily_journal, approve_orders, execute_orders, risk_guard)을 거래일마다 장 운영 시간에 맞춰 저절로 돌게 하고 싶어. 먼저 파일들이 하는 일과 실행 방법, 그리고 내 컴퓨터 종류(윈도우, Mac)를 확인해줘.

[만들 것]
1. 'run_after_close.py'(장 마감 후 작업): 오늘이 휴장일이면 아무것도 하지 않고 끝내. 아니면 generate_signals.py → prepare_orders.py → daily_journal.py를 차례로 실행해. 가격이 오늘 종가까지 오지 않았으면 주문 목록을 만들지 말고 기록에 남겨. 같은 날짜 주문 목록이 이미 있으면 그대로 둬.
2. 'run_market_open.py'(개장 작업): 오늘이 휴장일이거나 15:30이 지났으면 아무것도 하지 않고 끝내. 아니면 장이 열리기 전에 먼저 generate_signals.py → prepare_orders.py를 돌리고(가장 최근 확정 종가일의 주문 목록이 이미 있으면 그대로 둬. 저녁 작업이 빠졌던 날만 그때 만들어지고, 그 목록의 매수는 승인 대기라 나가지 않아. 대신 승인하지 마), risk_guard.py로 그날 아침의 계좌 총자산을 기록하고 09:00까지 기다려. 그다음 execute_orders.py로 주문을 보내고(이 프로그램이 approve_orders.py의 검사를 거쳐 매도와 승인된 매수만 고른다), 15:30까지 risk_guard.py의 실제 감시를 돌려(1분마다 기록하고 한도를 넘으면 모두 팖).
3. 두 스크립트의 시각 판단(휴장일, 09:00, 15:30)은 컴퓨터의 시간대와 상관없이 한국 시간 기준으로 해. 두 스크립트는 어느 폴더에서 실행해도 작업 폴더의 파일을 쓰고, 출력과 에러를 'logs/run_YYYYMMDD.log'에 남겨. 한 단계가 실패하면 기록하고, 그 결과가 필요한 뒤 단계만 건너뛰어(안전장치는 늘 돌려).
4. 내 컴퓨터에 맞는 실행 파일 두 개(윈도우 '.bat', Mac '.sh')와 'docs/scheduler_setup.md'를 만들어줘. 문서에는 평일 17:00·08:50 예약을 등록 → 등록됐는지 확인 → 지금 바로 한 번 실행해 보기 → 삭제하는 방법을 순서대로 적고, 노트북이 배터리로 돌 때·예약 시각을 놓쳤을 때·잠자기 상태일 때도 작업이 돌게 하는 설정과, 작업 폴더 위치 때문에 실행이 막히는 경우를 피하는 방법을 포함해.
5. 만든 뒤 지금 바로 두 스크립트를 한 번씩 실행하고, 무슨 일이 있었는지(어디서 멈췄는지, 또는 어떤 단계가 돌았는지) 그대로 보여줘.

[하지 말 것]
- 예약 실행에 직접 등록하지 마. 등록은 내가 안내 문서를 보고 한다.
- 매수를 대신 승인하지 마. 승인 상태는 내가 주문 목록 파일에서 고친 그대로 써.
- 주문은 execute_orders.py의 주문 보내기로만 보내고, 기존 프로그램 파일은 고치지 마.

[확인] 두 작업의 실행 결과와 'logs/run_YYYYMMDD.log', 실행 파일 두 개와 'docs/scheduler_setup.md'가 생겼는지, 예약 없이 직접 실행하는 명령을 보여줘.
```

### 이어서: 안내 문서대로 예약 등록하기

1. `docs/scheduler_setup.md`를 열어 내 컴퓨터(윈도우 또는 Mac) 부분을 그대로 따라 두 작업을 등록합니다. 예약 시각은 컴퓨터 시계 기준이니, 한국 밖에서 돌리면 한국 시간 17:00·08:50에 해당하는 현지 시각으로 등록합니다.
2. 문서의 "지금 바로 한 번 실행해 보기"대로 등록한 작업을 실행합니다. 지금 시각에 따라 "휴장일" 또는 "장 시간 아님"에서 멈추는 것이 정상입니다.
3. `logs/run_날짜.log`에 그 실행 기록이 남았는지 봅니다.

예약을 걸지 않을 거라면 이 단계는 건너뛰고, 문서에서 두 작업을 직접 실행하는 명령만 확인해 둡니다.

### 내 눈으로 확인할 체크리스트

- [ ] 두 작업을 한 번씩 실행해 각각 어디까지 돌았는지(또는 왜 멈췄는지) 실행 기록에서 확인했다.
- [ ] `docs/scheduler_setup.md`대로 두 작업을 등록하고 바로 한 번 실행해 `logs/run_날짜.log`에 기록이 남았다. (예약을 걸지 않는다면 직접 실행하는 명령을 확인했다.)
