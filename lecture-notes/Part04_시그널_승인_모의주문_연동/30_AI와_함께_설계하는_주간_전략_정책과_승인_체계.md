# AI와 함께 설계하는 주간 전략 정책과 승인 체계

## 이번 클립에서 만들 것

이 클립이 끝나면, 여러분은 주말 30분 동안 Claude Code와 함께 지난주 시장 성과와 다음 주 거시 환경을 브리핑받고, 한 주 동안 무인 실행 엔진이 엄격히 준수해야 할 **'주간 매매 정책 파일(`weekly_policy.json`)'**을 생성한 뒤, **최고투자책임자(CIO)인 내가 파일을 직접 검토한 뒤 상태를 `ACTIVE`(이번 주 적용)로 바꿔 최종 승인하는 절차**를 완성하게 됩니다.

> 💡 **수강생 안심 안내**: 복잡한 설정 파일을 직접 코딩할 필요가 없습니다. Claude Code와 자연어로 대화하며 *"다음 주는 변동성이 클 것 같으니 현금 비중 20%를 두고 추세추종만 돌리자"*라고 말하면, AI가 정책을 JSON(프로그램끼리 주고받는 정해진 형식의 텍스트 파일)으로 정리하고, 형식이 맞는지 검사까지 해 줍니다.

- **Tier 1 주간 거버넌스 세션(Weekly Governance Session)**의 표준 진행 절차
- 주간 정책 파일(`weekly_policy.json`)에 반드시 있어야 할 5가지 칸(적용 기간, 전략별 가중치, 유니버스, 위험 한도, 승인자 서명). 이렇게 파일에 반드시 있어야 할 칸과 칸마다 값의 형식을 정해 둔 것을 스키마라고 부릅니다
- `operating_rules.json`의 1층·2층 값이 이 파일의 `risk_limits`로 그대로 옮겨오는 경로
- 정책 파일이 잘못 적히거나 몰래 바뀌는 것을 막는 **형식 검사**: 칸이 빠짐없이 있는지, 값의 형식과 비중 합계가 맞는지 확인(스키마 유효성 검증)
- **실습 18**: Claude Code와의 주간 전략 회의 대화 및 `weekly_policy.json` 생성·승인 실습

## 이론 핵심

### 1. 주간 거버넌스 4단계 프로세스

```text
[Step 1: 주말 브리핑 요청] ──> Claude Code에게 "지난주 시장 리뷰 및 다음 주 전략 추천 브리핑해줘" 입력
          ↓
[Step 2: AI 시장 분석]    ──> KOSPI 200일선 위치, 변동성 지표, 환율/금리 점검 후 전략 가중치 제안
          ↓
[Step 3: 정책 조율 및 합의]──> 운영자(나)가 검토 후 최종 비중 결정 ("페어트레이딩 비중 10% 추가해줘")
          ↓
[Step 4: 정책 승인 및 서명]──> AI가 `weekly_policy.json`을 상태 'DRAFT'(초안)로 생성 ➔ 사람이 파일 검토 후 상태를 'ACTIVE'로 바꿈
```

---

### 2. 표준 주간 정책 스키마 (`weekly_policy.json`)

```json
{
  "policy_version": "1.0",
  "effective_period": {
    "start_date": "2026-08-24",
    "end_date": "2026-08-28"
  },
  "market_regime": "BULL",
  "strategy_weights": {
    "trend_following": 0.40,
    "volatility_breakout": 0.30,
    "dual_momentum": 0.20,
    "pairs_trading": 0.10,
    "cash_reserve": 0.00
  },
  "risk_limits": {
    "max_strategy_pct": 0.60,
    "trailing_stop_pct": -0.10,
    "vol_target": 0.15,
    "hard_stop_loss_pct": -0.03,
    "daily_portfolio_circuit_breaker_pct": -0.02
  },
  "governance": {
    "approved_by": "AinX (CIO)",
    "approval_timestamp": "2026-08-23T15:00:00",
    "status": "ACTIVE"
  }
}
```

위 예시는 **승인이 끝난 뒤의 모습**입니다. `status`는 AI가 처음 저장할 때 `DRAFT`(초안)이고, 사람이 내용을 검토한 뒤 직접 `ACTIVE`로 바꿉니다. 실행 엔진은 `ACTIVE`인 정책만 따릅니다.

## 실습 — 실습 18: 주간 정책 파일 생성 및 승인

Claude Code 대화창에 아래 프롬프트를 입력하여 주간 정책 합의를 진행해 보세요.

> 📁 **공유 파일**: 이 프롬프트는 클립 25에서 저장한 `operating_rules.json`(네 전략의 규칙, 국면 판정 기준, 국면별 비중, 위험관리 값)을 읽습니다. 같은 작업 폴더에 이 파일이 없으면 클립 25 실습을 먼저 실행하세요. 파일이 없거나 항목이 빠져 있으면 AI가 값을 지어내지 않고 멈추도록 해 두었습니다.

```prompt
[맥락] 다음 주(2026-08-24 ~ 2026-08-28) 실행할 주간 트레이딩 정책을 함께 수립하고, 무인 실행 엔진이 읽을 정책 파일을 만들고 싶어.

[만들 것] 다음 조건에 맞춰 'weekly_policy.json' 파일을 작성해줘:
1. 'operating_rules.json'을 읽어, 그 파일의 판정 기준으로 현재 KOSPI 시장 국면을 진단해줘. 아래 2번의 값이 파일의 상승 국면 비중, 1층 위험관리 기본값, 2층 값과 같은지도 대조해줘.
2. 정책 내용:
   - 적용 기간: 2026-08-24 ~ 2026-08-28
   - 전략 가중치: 추세추종 40%, 변동성 돌파 30%, 듀얼 모멘텀 20%, 페어 10% (operating_rules.json의 상승 국면 값)
   - 1층 전략 위험관리: 고점 대비 손절 -10%, 목표 변동성 15%, 전략당 최대 비중 60%
   - 2층 하드 가드레일: 개별 종목 -3% 손절, 일일 계좌 -2% 서킷브레이커
   - 승인자: 'AinX (CIO)', 상태: 'DRAFT'. 승인 시각(approval_timestamp)은 비워 둬. 내가 파일을 검토한 뒤 직접 상태를 'ACTIVE'로 바꾸고 승인 시각을 적는다.
3. 정책 요약표를 대화창에 브리핑 형태로 출력해줘.

[하지 말 것]
- 정책 파일을 만드는 것까지만 해. 이 정책으로 주문을 보내거나 실행 스크립트를 돌리지 마.
- 상태를 'DRAFT' 말고 다른 값으로 저장하거나, 상태를 자동으로 판정해 'ACTIVE'로 바꾸는 로직을 넣지 마. 'ACTIVE'로 바꾸는 것은 내가 검토 후 직접 한다.
- 전략 가중치 합계가 100%가 아니거나 한 전략이 60%를 넘으면 파일을 저장하지 말고 오류로 보고해.
- 위험 한도 값을 네가 판단해서 바꾸지 마. 위 값은 'operating_rules.json'에서 온 것이고, 2층 값(-3%, -2%)은 어떤 경우에도 고정이야. 1번 대조에서 파일과 다른 값이 있으면 파일을 저장하지 말고 차이를 보고해.

[확인] 대화창에 주간 정책 요약표가 출력되었는지, 'weekly_policy.json' 파일이 상태 'DRAFT'로 저장되어 경로가 표시되었는지 확인해줘.
```

---

### 내 눈으로 확인할 체크리스트

- [ ] `weekly_policy.json` 파일이 루트 폴더에 정상 생성되었다.
- [ ] 적용 기간(월~금), 전략별 비중 합계(100%), 1층 값(-10% / 15% / 60%)과 2층 값(-3% / -2%)이 `operating_rules.json`과 같은지 한 칸씩 대조했다.
- [ ] 위 대조를 마친 뒤 내가 직접 상태를 `DRAFT`에서 `ACTIVE`로 바꾸고 승인 시각을 적어, 무인 실행 엔진이 읽을 준비가 되었음을 확인했다.
