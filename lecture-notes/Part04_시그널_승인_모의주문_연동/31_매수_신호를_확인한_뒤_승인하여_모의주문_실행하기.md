# 매수 신호를 확인한 뒤 승인하여 모의주문 실행하기

## 이번 클립에서 만들 것

주문 목록에서 **매도와 내가 승인한 매수**를 모의투자 계좌로 보내고, 체결 결과를 기록하는 주문 프로그램(`execute_orders.py`)을 만듭니다.

- 주문이 나가기까지의 순서
- 거래 코드를 AI가 확인하게 하는 이유
- **실습 19**: `execute_orders.py` 작성 및 모의투자 1주 주문

---

## 이론 핵심

### 1. 주문이 나가기까지

```text
[1] 직전 거래일의 주문 목록이 있는가, 장이 열려 있는가   (아니면 멈춤)
[2] 매도와 승인된 매수만 고름
[3] 매도를 먼저 보내 체결을 확인한 뒤, 주문 가능 금액 안에서 매수. 시장가로 보냄
[4] 주문번호와 체결 가격을 orders_history.json에 기록
```

**시장가**는 가격을 정하지 않고 지금 나와 있는 가격에 바로 사고파는 주문입니다. 바로 체결되는 대신 예상 가격과 조금 다르게 체결될 수 있어(슬리피지), 그 차이를 기록해 둡니다.

주문 목록의 매수 금액은 "매도로 들어올 돈"까지 셈에 넣어 만들었습니다. 그래서 매수는 **매도가 체결된 것을 확인한 뒤** 보내고, 보내기 직전에 증권사에 지금 주문 가능한 금액을 물어봅니다. 모자라면 그 매수는 보내지 않습니다. 돈이 모자란데도 증권사가 먼저 사 주고 나중에 갚게 하는 **미수**(외상 매수)가 생기지 않게 하기 위해서입니다.

주문 프로그램은 **직전 거래일 날짜의 주문 목록만** 씁니다. 전날 목록이 만들어지지 않았으면 더 오래된 목록으로 주문하지 않고 멈춥니다.

---

### 2. 거래 코드는 AI가 공식 자료에서 확인합니다

증권사 API는 기능마다 **거래 코드**가 있고, 모의투자 코드는 `V`로 시작합니다. 주문 코드는 2025년에 바뀌어서, 인터넷 예제에는 예전 코드가 남아 있습니다. 그래서 프롬프트에 코드를 적지 않고 AI가 공식 자료에서 확인하게 합니다. AI가 알려 준 코드가 `V`로 시작하는지, 출처가 공식 자료인지만 보면 됩니다.

## 실습 — 실습 19: 주문 프로그램 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요. 이 실습은 **장이 열려 있는 시간(평일 09:00~15:30)**에 하세요.

> 📁 **공유 파일**: 이 프롬프트는 직전 거래일의 주문 목록을 읽고, 주문과 체결 기록을 `orders_history.json`에 쌓습니다.

```prompt
[맥락] 승인이 끝난 주문 목록에서 매도와 승인된 매수를 모의투자 계좌로 보내는 주문 프로그램을 만들고 싶어. 작업 폴더의 kis_auth.py, market_data.py, approve_orders.py에 만들어 둔 기능을 가져다 쓴다.

[만들 것] 파이썬 스크립트 'execute_orders.py'를 작성하고 실행해줘:
1. 가장 최근 확정 종가일의 'orders_날짜.json'만 써. 그 파일이 없거나 지금이 평일 09:00~15:30이 아니면 주문 없이 멈추고 이유를 알려줘.
2. approve_orders.py의 검사를 거쳐 매도와 '승인'인 매수만 보내. 검사에 걸리면 매수는 보내지 말고, 매도는 원본 파일에서 읽어 보내.
3. 매도 먼저, 매수 나중에 시장가로 보내는 주문 함수를 만들어, 다른 프로그램도 불러 쓸 수 있게 해줘. 매수는 매도가 체결된 것을 확인한 뒤 보내고, 보내기 직전에 주문 가능 금액을 조회해 모자라면 그 매수는 보내지 말고 '현금 부족'으로 기록해. 오늘 이미 같은 종목·같은 방향으로 보낸 개장 주문은 다시 보내지 마.
4. 주문마다 'orders_history.json'에 [주문시간, 종목코드, 매수/매도, 수량, 주문번호, 예상 가격, 이유]를 남기고, 체결을 몇 번 확인해 [체결 수량, 체결 가격, 예상 대비 차이(%)]를 덧붙여줘. 끝내 체결되지 않으면 '미체결'로 적어.
5. 실행 방법: 옵션 없음 = 실제 운용 / '--dry-run' = 보내지 않고 보낼 주문만 출력(언제든 실행 가능) / '--test' = KODEX 200 1주 시험 매수(예상 가격은 보내기 직전 현재가, 이유 '시험 주문'). 이번에는 '--test'로만 실행해줘.

[하지 말 것]
- 거래 코드(기능마다 붙은 이름표)를 짐작으로 쓰지 마. KIS Developers 문서나 한국투자증권 공식 GitHub 예제(koreainvestment/open-trading-api)에서 모의투자용을 확인하고 출처를 알려줘.
- 증권사로 가는 요청은 모두 kis_auth.py를 거쳐서 보내(모의투자 서버만).
- 응답이 불확실해도 같은 주문을 다시 보내지 마. 실패로 기록해.
- 승인 대기·거절인 매수를 보내거나 승인 상태를 바꾸지 마. 돈이 모자라는 매수를 외상(미수)으로 사게 하지도 마.

[확인] [종목 / 매수·매도 / 수량 / 주문번호 / 체결 가격 / 차이(%)] 표와 'orders_history.json' 기록을 보여줘. 증권사 화면과는 내가 대조한다.
```

### 내 눈으로 확인할 체크리스트

- [ ] 예상 가격과 체결 가격의 차이(%)가 기록되었다.
