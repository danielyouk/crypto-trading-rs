# 이메일로 매매 알림 받아보기

## 이번 클립에서 만들 것

거래가 일어났을 때 **무엇을 왜 사고팔았는지** 설명하는 메일을 보내는 알림 모듈(`notifier.py`)을 만듭니다. 이런 일은 신호가 바뀌어야 일어나므로, 과거의 하루를 가상으로 다시 돌려(**리플레이**) 장 마감 후 주문 목록 → 내 승인 → 다음 날 체결 → 메일까지 따라가 봅니다.

> 💡 증권사 앱도 체결 알림을 보내 주지만 "무엇을 얼마에"까지만 알려 줍니다. 우리 메일은 "어느 전략의 어떤 판단 때문에"를 함께 보여 줍니다. 메일로는 승인할 수 없고, 매수 승인은 주문 목록 파일에서 합니다.

- 거래 이유를 담은 메일
- 과거의 하루를 가상으로 다시 돌려 승인까지 따라가 보기
- **실습 20**: `notifier.py`와 `replay_day.py` 작성, 가상으로 승인하고 메일 받기

---

## 이론 핵심

### 1. 메일에 "왜"를 담습니다

```text
[매매] 개장 주문 2건 체결                       (예시)
하나금융지주  5주 매도
KB금융        3주 매수
왜: 페어 스위칭. 전날 종가 기준 Z가 -1.5 아래로 내려가 뒤처진 KB금융으로 교체
    (근거: 그날 신호 파일)
```

"왜"는 새로 계산하지 않습니다. 신호 파일에는 전략마다 바뀐 이유(신호 변경, 국면 변경, 비중 조정)와 판단에 쓴 값이 이미 적혀 있어서, 메일은 그것을 찾아 옮겨 적습니다.

| 메일 | 보내는 때 |
|---|---|
| **매매** | 개장 주문이 체결된 뒤. 무엇을 얼마에, 왜 |
| **안전장치** | 하루 손실 한도에 닿아 모두 팔았을 때 |
| **오류** | 프로그램이 멈췄을 때 |

---

### 2. 과거의 하루를 가상으로 다시 돌립니다

메일이 제대로 오는지 보려면 신호가 바뀌는 날이 있어야 합니다. 그날을 기다리는 대신, 가격 파일에 있는 **과거의 하루를 가상으로 다시 돌립니다.** 실제와 같은 형식의 파일을 만들기 때문에 승인도 실제와 똑같이 해 볼 수 있습니다.

```text
replay_day.py --date 날짜          그날 장 마감 후: 신호 → 주문 목록 (logs/replay 폴더)
        ↓ 내가 그 주문 목록을 열어 매수를 '승인'으로 고치거나 그대로 둠
replay_day.py --date 날짜 --open   다음 날 개장: 매도와 승인된 매수만 그날 시가로 가상 체결 → [가상] 매매 메일
```

리플레이는 증권사에 연결하지 않고 가격 파일만 씁니다. 결과는 `logs/replay` 폴더에만 남고 실제 계좌와 주문 기록은 건드리지 않으므로, 몇 번이든 돌려 볼 수 있습니다.

---

### 3. 메일 설정

프로그램은 **SMTP**(메일을 보낼 때 쓰는 표준 규칙)로 메일을 보냅니다. 아래 다섯 값을 `.env`에 적습니다.

| 값 | 뜻 | 예 (Gmail) |
|---|---|---|
| `SMTP_HOST` | 메일을 보내 주는 서버 주소 | `smtp.gmail.com` |
| `SMTP_PORT` | 접속 번호 | `587` |
| `SMTP_USER` | 보내는 메일 주소 | 내 Gmail 주소 |
| `SMTP_PASSWORD` | **앱 비밀번호** | 16자리 |
| `ALERT_TO` | 알림을 받을 주소 | 내가 자주 보는 메일 주소 |

**앱 비밀번호**는 메일 서비스가 프로그램용으로 따로 내주는 비밀번호입니다. Gmail은 2단계 인증을 켠 뒤 Google 계정 보안 설정에서 발급합니다. 메뉴 위치는 바뀔 수 있으니, 찾기 어려우면 Claude Code에게 "Gmail 앱 비밀번호 발급 방법을 알려줘"라고 물어보세요.

> ⚠️ 평소 로그인 비밀번호를 `.env`에 적지 마세요. 반드시 앱 비밀번호를 씁니다.

## 실습 — 실습 20: 이메일 알림 모듈 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 `.env`의 메일 설정과 `price_cache` 폴더의 가격 파일을 쓰고, `execute_orders.py`에 매매 메일을 보내는 부분을 덧붙입니다. 리플레이의 주문 목록과 가상 체결은 `logs/replay` 폴더에만 남고, 보낸 메일은 `logs/alerts.log`에 남습니다.

```prompt
[맥락] 거래가 일어났을 때 무엇을 왜 사고팔았는지 설명하는 메일을 만들고, 장 마감 후 주문 목록 → 내 승인 → 다음 날 체결 → 메일의 흐름을 과거의 하루로 가상으로 다시 돌려(리플레이) 보고 싶어. 메일 설정은 작업 폴더의 .env에 있어. 작업 폴더의 generate_signals.py(신호 계산 함수), prepare_orders.py와 approve_orders.py(주문 목록 형식과 승인 검사), 'price_cache' 폴더의 가격 파일을 쓴다.

[만들 것]
1. 'notifier.py': .env의 SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD(앱 비밀번호), ALERT_TO로 메일을 보내는 함수 send_alert(종류, 제목, 본문)를 만들어줘. 종류는 '매매', '안전장치', '오류'이고 제목 앞에 [종류]를 붙여. 보낸 메일은 'logs/alerts.log'에 남겨.
2. '매매' 메일 본문: 주문마다 [종목, 매수/매도, 수량, 체결 가격]과 '왜'를 적어줘. '왜'는 그날 신호 파일에서 그 종목을 움직인 전략, 바뀐 이유, 판단에 쓴 값(200일선 대비 %, Z, 120거래일 수익률 순위, 국면 등)을 찾아 한두 줄로 써. 승인이 없어 사지 않은 매수도 따로 적어.
3. 'replay_day.py --date 날짜': 증권사에 연결하지 않고 그날 장 마감 후를 재현해. generate_signals.py의 계산 함수로 그날과 전 거래일의 신호를 계산하고, 전 거래일 목표 수량을 가상 보유로 삼아, 실제와 같은 형식의 주문 목록과 원본을 'logs/replay' 폴더에 만들어(매도 '자동', 매수 '승인 대기').
4. 'replay_day.py --date 날짜 --open': 다음 거래일 개장을 재현해. approve_orders.py의 검사로 리플레이 주문 목록을 검사하고, 매도와 '승인'인 매수만 그날 시가로 가상 체결해 'logs/replay' 폴더에 남긴 뒤 [가상]을 붙인 '매매' 메일을 보내.
5. execute_orders.py가 실제 체결을 확인한 뒤 2번 형식의 '매매' 메일을 보내게 덧붙여줘. 메일이 실패해도 주문과 기록에는 영향이 없게 해.
6. 가격 파일 기간 안에서 전략 신호가 바뀐 가장 최근 날을 찾아 3번을 실행하고 멈춰. 내가 주문 목록을 고친 뒤 말하면 4번을 실행해줘.

[하지 말 것]
- 리플레이에서 증권사 API를 부르거나, 실제 파일(signals.json, 실제 주문 목록, orders_history.json)을 만들거나 고치지 마. 리플레이 결과는 'logs/replay' 폴더에만 남겨.
- 리플레이 주문 목록의 승인 상태를 네가 고치지 마. 내가 고친다.
- 비밀번호와 .env 값을 어디에도 출력하지 말고 .env를 고치지 마. 메일로 승인을 받는 기능도 넣지 마.
- 메일 전송이 실패해도 프로그램을 멈추지 마. 실패는 기록만 남겨.

[확인] 리플레이한 날짜와 주문 목록 경로를 보여 주고, 내가 고친 뒤에는 가상 체결 결과(승인이 없어 사지 않은 매수 포함)와 메일 전송 결과를 보여줘. 받은편지함은 내가 확인한다.
```

### 내 눈으로 확인할 체크리스트

- [ ] [가상] 매매 메일에 무엇을 얼마에 사고팔았는지와 그 이유(전략과 판단 근거)가 함께 들어 있다.
- [ ] 리플레이 주문 목록에서 승인한 매수만 가상 체결되고, 그대로 둔 매수는 "승인이 없어 사지 않음"으로 나왔다.
- [ ] 실제 주문 목록과 `orders_history.json`은 바뀌지 않았다.
