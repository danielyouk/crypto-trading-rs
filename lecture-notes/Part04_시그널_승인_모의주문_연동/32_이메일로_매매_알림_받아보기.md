# 이메일로 매매 알림 받아보기

## 이번 클립에서 만들 것

프로그램이 한 일을 **이메일로 보고받는 알림 모듈**(`notifier.py`)을 만들고, 앞에서 보낸 1주 시험 주문의 체결 결과를 첫 메일로 받아 봅니다.

> 💡 알림은 **이미 일어난 일을 알려 주는 보고**입니다. 메일로는 승인할 수 없고, 매수 승인은 주문 목록 파일에서 합니다.

- 알림을 보내는 네 가지 경우
- 메일을 보내는 데 필요한 설정
- **실습 20**: `notifier.py` 작성, 주문 프로그램에 체결 결과 메일 붙이기

---

## 이론 핵심

### 1. 언제 알림을 보내나

| 알림 | 보내는 때 | 담는 내용 |
|---|---|---|
| **일일 보고** | 거래일마다 장 마감 후 | 그날 일지 |
| **체결 결과** | 개장 주문을 보낸 뒤 | 예상 가격과 체결 가격, 그 차이 |
| **안전장치** | 장중 손절이 실행됐을 때 | 무엇을 얼마에 팔았는지 |
| **오류** | 프로그램이 멈췄을 때 | 어느 단계에서 왜 멈췄는지 |

일일 보고는 매일 오고, 나머지는 일이 있을 때만 옵니다. 일일 보고가 오지 않은 날은 프로그램이 돌지 않은 날입니다.

---

### 2. 메일 설정

프로그램은 **SMTP**(메일을 보낼 때 쓰는 표준 규칙)로 메일을 보냅니다. 아래 다섯 값을 `.env`에 적습니다.

| 값 | 뜻 | 예 (Gmail) |
|---|---|---|
| `SMTP_HOST` | 메일을 보내 주는 서버 주소 | `smtp.gmail.com` |
| `SMTP_PORT` | 접속 번호 | `587` |
| `SMTP_USER` | 보내는 메일 주소 | 내 Gmail 주소 |
| `SMTP_PASSWORD` | **앱 비밀번호** | 16자리 |
| `ALERT_TO` | 알림을 받을 주소 | 내가 자주 보는 메일 주소 |

**앱 비밀번호**는 메일 서비스가 프로그램용으로 따로 내주는 비밀번호입니다. Gmail은 2단계 인증을 켠 뒤 Google 계정 보안 설정에서 발급합니다. 메뉴 위치는 바뀔 수 있으니, 찾기 어려우면 Claude Code에게 "Gmail 앱 비밀번호 발급 방법을 알려줘"라고 물어보세요.

> ⚠️ 평소 로그인 비밀번호를 `.env`에 적지 마세요. 반드시 앱 비밀번호를 씁니다.

## 실습 — 실습 20: 이메일 알림 모듈 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 `.env`의 메일 설정과 `orders_history.json`의 주문 기록을 읽고, `execute_orders.py`에 체결 결과 메일을 보내는 부분을 덧붙입니다. 보낸 메일은 `logs/alerts.log`에 남습니다.

```prompt
[맥락] 프로그램이 한 일(장 마감 후 일지, 체결 결과, 장중 손절, 오류)을 이메일로 받는 알림 모듈을 만들고 싶어. 메일 설정은 작업 폴더의 .env에 있어. 매수 승인은 이 모듈과 관계없이 주문 목록 파일에서 한다.

[만들 것] 파이썬 스크립트 'notifier.py'를 작성하고 실행해줘:
1. .env의 SMTP_HOST, SMTP_PORT, SMTP_USER, SMTP_PASSWORD(앱 비밀번호), ALERT_TO로 메일을 보내는 함수 'send_alert(종류, 제목, 본문)'을 만들어줘. 종류는 '일일 보고', '체결 결과', '안전장치', '오류'이고 제목 앞에 [종류]를 붙여. 성공하면 True, 실패하면 False를 돌려줘.
2. 'orders_history.json'의 기록으로 '체결 결과' 본문(주문마다 예상 가격·체결 가격·차이, 맨 아래 금액 합계와 차이)을, 일지 파일('docs/daily_journal_YYYYMMDD.md')로 '일일 보고' 본문을 만드는 함수를 만들어줘.
3. execute_orders.py가 체결 확인을 마친 뒤 '체결 결과' 메일을 보내게 덧붙여줘. 메일이 실패해도 주문과 기록에는 영향이 없게 해.
4. 보낸 메일마다 'logs/alerts.log'에 [시각, 종류, 제목, 성공/실패]를 남겨줘.
5. 시험 메일 2통을 보내줘: '오류' 시험 메일, 그리고 'orders_history.json'의 가장 최근 기록으로 만든 '체결 결과' 메일.

[하지 말 것]
- 비밀번호와 .env 값을 어디에도 출력하지 마. .env도 고치지 마.
- 메일 전송이 실패해도 프로그램을 멈추지 마. 두어 번 다시 시도하고 기록만 남겨.
- 메일로 승인을 받거나 답장으로 무언가를 실행하는 기능을 넣지 마.
- execute_orders.py에는 메일 보내는 부분만 덧붙이고, 시험한다고 주문을 보내지 마.

[확인] 두 메일의 전송 결과와 'logs/alerts.log' 기록, execute_orders.py에 덧붙인 곳을 보여줘. 받은편지함은 내가 확인한다.
```
