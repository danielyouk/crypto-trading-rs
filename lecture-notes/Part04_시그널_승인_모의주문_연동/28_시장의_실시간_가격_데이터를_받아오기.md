# 시장의 실시간 가격 데이터를 받아오기

## 이번 클립에서 만들 것

이 클립이 끝나면, 여러분은 한국투자증권 Open API로 **세 전략이 쓰는 종목들의 현재가·시가·고가·저가·거래량**을 받아 오고, 증권사 API의 초당 호출 제한(1초에 보낼 수 있는 요청 횟수의 상한)을 지키는 **'실시간 시세 수집기(`market_data.py`)'**를 완성하게 됩니다. 신호는 전날 종가로 이미 정해지므로, 실시간 가격은 주문 금액을 어림하고 장중 안전장치를 돌리는 데 씁니다.

> 💡 **수강생 안심 안내**: 증권사 HTS를 켜두지 않아도 파이썬 코드가 백그라운드에서 증권사 서버에 1초에 한 번씩 필요한 종목의 시세를 차례로 물어 가져옵니다(모의투자 서버는 계좌당 초당 1회까지만 받습니다).

- KIS의 **국내주식 현재가 시세 조회 요청(거래 코드 `FHKST01010100`)** 구조
- REST API 폴링(Polling) 방식 vs 웹소켓(WebSocket) 스트리밍의 차이점과 장단점
- 증권사 API의 초당 호출 제한(모의투자는 계좌당 초당 1건, 2026년 4월 기준)과 **호출 사이에 일부러 잠깐 쉬어 한도를 넘지 않게 하는 설계(쓰로틀링, `time.sleep`)**
- **실습 16**: 세 전략이 쓰는 6개 종목의 실시간 시세 수집 모듈 실행

## 이론 핵심

### 1. 실시간 주식 시세 데이터의 구조

KIS 현재가 조회 API를 호출하면 JSON 응답으로 다음 핵심 데이터가 수신됩니다.

```json
{
  "output": {
    "stck_prpr": "35400",     // 주식 현재가
    "prdy_vrss": "450",       // 전일 대비 변동액
    "prdy_ctrt": "1.29",      // 전일 대비 등락률 (%)
    "stck_oprc": "35100",     // 당일 시가 (Open)
    "stck_hgpr": "35650",     // 당일 고가 (High)
    "stck_lwpr": "35050",     // 당일 저가 (Low)
    "acml_vol": "1254300"     // 당일 누적 거래량 (Volume)
  }
}
```

---

### 2. 가격을 받는 두 가지 방식: 폴링 vs 웹소켓

| 방식 | 어떻게 받나 | 장점 | 단점 |
|---|---|---|---|
| **폴링(Polling)** | 내가 1초마다 "지금 얼마야?" 하고 물어보는 방식 | 코드가 단순하고, 한 번 실패해도 다음 질문에서 바로 회복 | 1초에 물을 수 있는 횟수에 한도가 있고, 물어보는 사이의 움직임은 못 봄 |
| **웹소켓(WebSocket)** | 연결을 켜 두면 가격이 바뀔 때마다 증권사가 알려주는 방식 | 빠르고, 매번 묻지 않으니 호출 한도 부담이 적음 | 연결이 끊겼는지 감시하고 다시 잇는 코드가 따로 필요해 복잡함 |

이 강의는 **폴링**을 씁니다. 우리 전략은 전날 종가로 판정하므로 1초 간격이면 충분하고, 초보자가 끊김 처리까지 챙기기에는 웹소켓이 부담이 크기 때문입니다.

> 💡 클립 01에서 하드 가드레일을 "0.1초 감시"라고 소개했습니다. 정확히 나누면, **가격 확인 간격은 증권사 호출 한도가 정하고**(모의투자는 계좌당 초당 1회라서 1~2초마다 확인), **기준에 닿았다고 판정한 뒤 주문을 만드는 계산은 0.1초 안**입니다.

---

### 3. 증권사 API 호출 한도(Rate Limiting)의 법칙

증권사 서버는 특정 프로그램이 1초에 수백 번씩 시세를 요청하면, 그 컴퓨터의 인터넷 주소(IP)에서 오는 요청을 막아 버립니다. 이때 돌아오는 오류 번호가 429(요청이 너무 많음)입니다.

## 실습 — 실습 16: 실시간 시세 수집기 구현

Claude Code 대화창에 아래 프롬프트를 입력하세요.

```prompt
[맥락] 한국투자증권 API를 활용해 전략 대상 종목들의 실시간 시세를 조회하는 시세 수집 모듈을 만들고 싶어. 인증은 작업 폴더의 kis_auth.py를 불러와서(import) 쓴다.

[만들 것] 다음 조건에 맞춰 파이썬 스크립트 'market_data.py'를 작성하고 실행해줘:
1. kis_auth.py가 발급하는 접근 토큰(증권사가 내주는 출입증. App Key·App Secret은 .env에 있음)을 받아 KIS 국내주식 현재가 시세조회(FHKST01010100) API를 호출하는 함수 'get_current_price(ticker)'를 구현해줘.
2. 세 전략이 실제로 쓰는 6개 종목의 실시간 시세(현재가, 시가, 고가, 저가, 전일비 등락률, 거래량)를 수집해줘:
   - KODEX 200 (069500) — 추세추종
   - TIGER 미국나스닥100 (133690) — 듀얼 모멘텀 공격
   - KODEX 미국채10년선물 (305080) — 듀얼 모멘텀 방어
   - KODEX 단기채권PLUS (214980) — 듀얼 모멘텀 방어
   - KB금융 (105560) — 페어트레이딩
   - 하나금융지주 (086790) — 페어트레이딩
3. 수집한 실시간 시세를 종목별 담당 전략과 함께 깔끔한 표로 출력해줘.
4. 모의투자 서버는 계좌당 초당 1회만 요청을 받으니, kis_auth.py의 공용 요청 함수를 써서 요청 사이에 최소 1초를 두고 6개 종목을 하나씩 차례로 조회해줘. (한 바퀴에 약 6초)

[하지 말 것]
- kis_auth.py의 인증 코드를 복사해 새로 만들지 말고, 기존 모듈을 불러와서(import) 써. kis_auth.py는 수정하지 마.
- 시세 조회에 실패한 종목의 가격을 지어내거나 전일 종가 등으로 대체하지 마. 실패한 종목은 실패로 표시해.
- API 호출 한도에 걸렸을 때 재시도를 무한히 반복하지 마. 정해진 횟수만 시도하고 멈춰.

[확인] 대화창에 6개 종목의 실시간 시세 표가 조회 시각과 함께 출력되어, 내가 증권사 앱(MTS)의 현재가와 직접 대조할 수 있는지 확인해줘.
```

---

### 내 눈으로 확인할 체크리스트

- [ ] 6개 종목의 현재가·시가·고가·저가·거래량이 에러 없이 나왔고, 백테스트한 종목과 같은지 대조했다.
- [ ] 출력된 현재가가 증권사 앱(MTS)의 현재가와 맞는지 대조했다(조회 시각에 따른 몇 초 차이는 정상).
- [ ] 호출 한도 초과 오류 없이 6개 종목이 1초 간격으로 차례로 조회되었다.
