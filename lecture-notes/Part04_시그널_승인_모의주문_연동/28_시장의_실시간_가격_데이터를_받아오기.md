# 시장의 실시간 가격 데이터를 받아오기

## 이번 클립에서 만들 것

이 클립이 끝나면, 여러분은 한국투자증권 Open API로 **세 전략이 쓰는 종목들의 현재가·시가·고가·저가·거래량**을 받아 오고, 증권사 API의 초당 호출 제한(1초에 보낼 수 있는 요청 횟수의 상한)을 지키는 **'실시간 시세 수집기(`market_data.py`)'**를 완성하게 됩니다. 신호는 전날 종가로 이미 정해지므로, 실시간 가격은 주문 금액을 어림하고 장중 안전장치를 돌리는 데 씁니다. 이어서 신호 스크립트(`generate_signals.py`)가 쓰는 날짜별 가격도 증권사에서 받도록 바꿉니다.

> 💡 **수강생 안심 안내**: 증권사 HTS를 켜두지 않아도 파이썬 코드가 백그라운드에서 증권사 서버에 1초에 한 번씩 필요한 종목의 시세를 차례로 물어 가져옵니다(모의투자 서버는 계좌당 초당 1회까지만 받습니다).

- 증권사 API로 **현재가를 받는 요청과 응답**의 구조
- REST API 폴링(Polling) 방식 vs 웹소켓(WebSocket) 스트리밍의 차이점과 장단점
- 증권사 API의 초당 호출 제한(모의투자는 계좌당 초당 1건, 2026년 4월 기준)과 **호출 사이에 일부러 잠깐 쉬어 한도를 넘지 않게 하는 설계(쓰로틀링, `time.sleep`)**
- 신호에 쓰는 날짜별 가격(일봉)도 증권사에서 받아야 하는 이유
- **실습 16**: 세 전략이 쓰는 6개 종목의 실시간 시세 수집 모듈 실행, 신호 스크립트를 증권사 일봉으로 바꾸기

## 이론 핵심

### 1. 실시간 주식 시세 데이터의 구조

KIS 현재가 조회 API를 호출하면 JSON 응답으로 다음 핵심 데이터가 수신됩니다.

```json
{
  "output": {
    "stck_prpr": "35400",     // 주식 현재가
    "prdy_vrss": "450",       // 전일 대비 변동액
    "prdy_ctrt": "1.29",      // 전일 대비 등락률 (%)
    "stck_oprc": "35100",     // 당일 시가 (Open)
    "stck_hgpr": "35650",     // 당일 고가 (High)
    "stck_lwpr": "35050",     // 당일 저가 (Low)
    "acml_vol": "1254300"     // 당일 누적 거래량 (Volume)
  }
}
```

---

### 2. 가격을 받는 두 가지 방식: 폴링 vs 웹소켓

| 방식 | 어떻게 받나 | 장점 | 단점 |
|---|---|---|---|
| **폴링(Polling)** | 내가 1초마다 "지금 얼마야?" 하고 물어보는 방식 | 코드가 단순하고, 한 번 실패해도 다음 질문에서 바로 회복 | 1초에 물을 수 있는 횟수에 한도가 있고, 물어보는 사이의 움직임은 못 봄 |
| **웹소켓(WebSocket)** | 연결을 켜 두면 가격이 바뀔 때마다 증권사가 알려주는 방식 | 빠르고, 매번 묻지 않으니 호출 한도 부담이 적음 | 연결이 끊겼는지 감시하고 다시 잇는 코드가 따로 필요해 복잡함 |

이 강의는 **폴링**을 씁니다. 우리 전략은 전날 종가로 판정하므로 1초 간격이면 충분하고, 초보자가 끊김 처리까지 챙기기에는 웹소켓이 부담이 크기 때문입니다.

---

### 3. 증권사 API 호출 한도(Rate Limiting)의 법칙

증권사 서버는 특정 프로그램이 1초에 수백 번씩 시세를 요청하면, 그 컴퓨터의 인터넷 주소(IP)에서 오는 요청을 막아 버립니다. 이때 돌아오는 오류 번호가 429(요청이 너무 많음)입니다.

### 4. 신호에 쓰는 가격도 증권사에서 받습니다

지금까지 신호 스크립트는 **FinanceDataReader**(인터넷에 공개된 가격 데이터를 모아 주는 파이썬 라이브러리)로 가격을 받았습니다. 지난 10년을 돌려 보는 백테스트에는 충분하지만, 매일 운영할 때는 두 가지가 걸립니다.

- **갱신이 늦을 때가 있습니다.** 출처마다 새 날짜가 들어오는 때가 다르고, 늦게 들어오면 며칠 전 가격으로 신호가 나옵니다.
- **주문을 넣는 곳과 출처가 다릅니다.** 주문은 증권사로 넣는데, 판단은 다른 곳의 가격으로 하게 됩니다.

증권사 API에는 현재가뿐 아니라 날짜별 가격(**일봉**: 하루마다 시가·고가·저가·종가·거래량을 한 줄로 적은 것)을 주는 창구도 있습니다. 한 번에 최대 100일치만 오므로 신호에 필요한 2년치는 여러 번 나눠 받습니다. 한 번 받은 가격은 파일로 두고, 다음부터는 빠진 날짜만 받습니다. 초당 1회 제한 때문에 처음 한 번은 시간이 좀 걸립니다.

> ⚠️ 예를 들어 FinanceDataReader에서 KOSPI 지수를 `'^KS11'`로 받으면 야후 파이낸스에서 매일 갱신된 값을 받지만, `'KS11'`로 받으면 따로 모아 둔 저장본을 읽어 갱신이 몇 주씩 늦을 때가 있습니다. 같은 지수라도 어떤 이름으로 받느냐에 따라 출처가 다릅니다.

## 실습 — 실습 16: 실시간 시세 수집기 구현

Claude Code 대화창에 아래 프롬프트를 입력하세요.

```prompt
[맥락] 한국투자증권 모의투자 계좌에 연결된 상태에서, 내가 매매하는 종목들의 지금 시세를 조회하는 모듈을 만들고 싶어. 인증과 요청은 작업 폴더의 kis_auth.py에 이미 만들어 둔 기능을 그대로 가져다 쓴다(앞에서 만든 파일이고, 키와 계좌번호는 .env에 있어). 먼저 kis_auth.py를 읽어 쓸 수 있는 기능을 확인해줘. 이번에 쓰는 증권사 API의 모의투자용 거래 코드(잔고 조회·주문 같은 기능마다 붙은 이름표)는 KIS Developers의 API 문서나 한국투자증권 공식 GitHub 예제(koreainvestment/open-trading-api)에서 확인해서 쓰고, 어디서 확인했는지 알려줘. 모의투자에서 쓸 수 없는 API도 있으니 그것도 확인해.

[만들 것] 다음 조건에 맞춰 파이썬 스크립트 'market_data.py'를 작성하고 실행해줘:
1. 종목코드를 넣으면 그 종목의 지금 시세(현재가, 시가, 고가, 저가, 전날 대비 등락률, 거래량)를 돌려주는 함수를 만들어줘. 뒤에 만들 프로그램들도 이 함수를 가져다 쓸 거야.

   - KODEX 200 (069500) — 추세추종
   - TIGER 미국나스닥100 (133690) — 듀얼 모멘텀
   - KODEX 미국채10년선물 (305080) — 듀얼 모멘텀
   - KODEX 단기채권PLUS (214980) — 듀얼 모멘텀
   - KB금융 (105560) — 페어 스위칭
   - 하나금융지주 (086790) — 페어 스위칭
3. 요청은 kis_auth.py의 공용 요청 함수로만 보내서 증권사의 요청 한도를 넘지 않게 해줘.

[하지 말 것]
- 공식 자료에서 확인하지 못한 거래 코드를 기억이나 짐작으로 채우지 마. 찾지 못하면 멈추고 알려줘.
- 인증이나 요청 기능을 새로 만들지 마. kis_auth.py에 있는 것을 그대로 가져다 쓰고, kis_auth.py는 수정하지 마.
- 시세 조회에 실패한 종목의 가격을 지어내거나 전날 종가 등으로 대체하지 마. 실패한 종목은 실패로 표시해.
- 요청 한도에 걸렸을 때 재시도를 무한히 반복하지 마. 정해진 횟수만 시도하고 멈춰.

[확인] 대화창에 6개 종목의 시세 표가 조회 시각과 함께 출력되어, 내가 증권사 앱(MTS)의 현재가와 직접 대조할 수 있는지 확인해줘.
```

### 이어서: 신호 스크립트가 증권사 일봉을 쓰게 바꾸기

시세 수집기가 동작하면, 같은 대화창에 아래 프롬프트를 이어서 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 `market_data.py`에 일봉 함수를 더하고 `generate_signals.py`의 가격 받는 부분을 바꿉니다. 증권사에서 받은 가격은 `price_cache` 폴더에 이름으로 구분해 따로 저장하고, 앞의 백테스트 실습이 받아 둔 파일은 그대로 둡니다. 실행하면 기준일의 신호가 `signals_날짜.json`과 `signals.json`으로 저장됩니다.

```prompt
[맥락] 작업 폴더의 generate_signals.py는 가격을 FinanceDataReader로 받아. 증권사 API가 연결됐으니, 신호에 쓰는 날짜별 가격(일봉)을 증권사 시세로 받게 바꾸고 싶어. 작업 폴더의 kis_auth.py(인증과 요청), market_data.py, generate_signals.py를 쓴다. 먼저 세 파일을 읽어 쓸 수 있는 함수와 가격을 받는 부분을 확인하고 시작해줘. 이번에 쓰는 증권사 API의 모의투자용 거래 코드(잔고 조회·주문 같은 기능마다 붙은 이름표)는 KIS Developers의 API 문서나 한국투자증권 공식 GitHub 예제(koreainvestment/open-trading-api)에서 확인해서 쓰고, 어디서 확인했는지 알려줘. 모의투자에서 쓸 수 없는 API도 있으니 그것도 확인해.

[만들 것]
1. market_data.py에 일봉(날짜별 시가·고가·저가·종가·거래량)을 받는 함수를 추가해줘. 종목은 KIS 국내주식 기간별 시세 API로 수정주가(액면분할 등을 반영해 고친 가격)를 받고, KOSPI 지수는 KIS 업종(지수) 기간별 시세 API로 받아. 한 번에 받을 수 있는 날짜 수에 상한이 있으면 기간을 나눠 받아 이어 붙여.
2. generate_signals.py가 쓰는 종목들과 KOSPI 지수의 가격을 1번 함수로 받게 바꿔줘. 받은 가격은 'price_cache' 폴더에 증권사 데이터임을 알 수 있는 이름(예: 'kis_069500.csv')으로 저장하고, 다음 실행부터는 저장된 파일 뒤에 빠진 날짜만 받아 이어 붙여.
3. 날짜 없이 실행할 때의 기준일을 지금 한국 시각으로 정하게 고쳐줘. 평일 장 마감(15:30) 뒤면 오늘, 그 전이거나 주말·휴장일이면 직전 거래일이야. 장중에 받은 오늘 가격은 확정 종가가 아니니 쓰지 마.
4. 고친 generate_signals.py를 날짜 없이 실행해줘. 그리고 종목별로 [증권사에서 받은 마지막 날짜와 종가 / 같은 날짜의 FinanceDataReader 종가(캐시에 있으면) / 차이]를 표로 보여 주고, 기준일, 국면, 전략별 [신호 / 조정 비중 / 목표 수량], 종목별 [목표 수량 / 순주문]을 표로 보여줘.

[하지 말 것]
- 공식 자료에서 확인하지 못한 거래 코드를 기억이나 짐작으로 채우지 마. 찾지 못하면 멈추고 알려줘.
- 전략 규칙, 입력값, 신호 파일의 항목 이름과 형식은 바꾸지 마. 가격을 받는 부분과 기준일을 정하는 부분만 바꿔.
- 증권사에서 받지 못한 종목이나 날짜를 다른 출처의 값이나 전날 값으로 채우지 마. 실패로 표시하고 멈춰.
- 앞의 백테스트 실습이 FinanceDataReader로 받아 둔 가격 파일은 지우거나 고치지 마.
- kis_auth.py는 수정하지 마. 요청은 공용 요청 함수로만 보내고, 주문 API는 부르지 마.

[확인] 종목별 마지막 날짜·종가 비교표, 기준일과 그렇게 정한 이유, 신호 표가 나왔는지, 그리고 'signals_기준일.json'과 'signals.json'이 그 기준일로 저장되었는지 확인해줘.
```
