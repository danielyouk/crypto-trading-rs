# 시장의 실시간 가격 데이터를 받아오기

## 이번 클립에서 만들 것

이 클립이 끝나면, 여러분은 한국투자증권 Open API를 통해 **관심 유니버스 종목들의 실시간 현재가, 체결 거래량, 매수/매도 10호가(Order Book) 데이터를 지연 없이 수신**하고, 증권사 API의 초당 호출 제한(Rate Limit / TPS)을 안전하게 관리하는 **'실시간 시세 수집기(`market_data.py`)'**를 완성하게 됩니다.

> 💡 **수강생 안심 안내**: 증권사 HTS를 켜두지 않아도 파이썬 코드가 백그라운드에서 증권사 서버와 통신하여 필요한 종목의 실시간 시세를 0.1초 만에 가져옵니다.

- KIS REST API의 **국내주식 현재가 시세 조회 엔드포인트(`FHKST01010100`)** 구조
- REST API 폴링(Polling) 방식 vs 웹소켓(WebSocket) 스트리밍의 차이점과 장단점
- 증권사 API의 초당 호출 제한(초당 20건 미만)과 **호출 간격 쓰로틀링(Throttling / `time.sleep`) 설계**
- **실습 16**: 4대 전략 유니버스 종목의 실시간 시세 및 당일 변동폭(Range) 수집 모듈 실행

## 이론 핵심

### 1. 실시간 주식 시세 데이터의 구조

KIS 현재가 조회 API를 호출하면 JSON 응답으로 다음 핵심 데이터가 수신됩니다.

```json
{
  "output": {
    "stck_prpr": "35400",     // 주식 현재가
    "prdy_vrss": "450",       // 전일 대비 변동액
    "prdy_ctrt": "1.29",      // 전일 대비 등락률 (%)
    "stck_oprc": "35100",     // 당일 시가 (Open)
    "stck_hgpr": "35650",     // 당일 고가 (High)
    "stck_lwpr": "35050",     // 당일 저가 (Low)
    "acml_vol": "1254300"     // 당일 누적 거래량 (Volume)
  }
}
```

---

### 2. 증권사 API 호출 한도(Rate Limiting)의 법칙

증권사 서버는 특정 프로그램이 1초에 수백 번씩 시세를 요청하면 IP를 차단(HTTP 429 Too Many Requests)합니다.

## 실습 — 실습 16: 실시간 시세 수집기 구현

Claude Code 대화창에 아래 프롬프트를 입력하세요.

```prompt
한국투자증권 API를 활용해 전략 대상 종목들의 실시간 시세를 조회하는 'market_data.py' 모듈을 만들어줘. (Context)

다음 요구사항에 맞춰 파이썬 스크립트를 작성하고 실행해줘: (Deliverable)
1. .env에 저장된 인증 토큰을 활용해 KIS 국내주식 현재가 시세조회(FHKST01010100) API를 호출하는 함수 'get_current_price(ticker)'를 구현해줘.
2. 다음 4개 종목의 실시간 시세(현재가, 시가, 고가, 저가, 전일비 등락률, 거래량)를 수집해줘:
   - KODEX 200 (069500)
   - KODEX 레버리지 (122630)
   - 삼성전자 (005930)
   - KB금융 (105560)
3. 수집한 실시간 시세를 깔끔한 터미널 표로 출력해줘.
4. API 초당 호출 한도를 준수하기 위해 종목 간 0.1초의 딜레이를 부여해줘.

실행 완료 후 터미널에 4개 종목의 실시간 시세 표를 출력하고 데이터가 정상 수신되었는지 확인시켜줘. (Verification)
```

---

### 내 눈으로 확인할 체크리스트

- [ ] 4개 종목의 현재가, 시가, 고가, 저가, 거래량이 에러 없이 수신되었다.
- [ ] 출력된 현재가가 실제 증권사 앱(MTS)의 실시간 가격과 정확히 일치한다.
- [ ] API 호출 시 429 에러나 끊김 없이 부드럽게 데이터가 로드되었다.
