# 장 마감 후 다음 거래일의 매매 조건 미리 확인하기

## 이번 클립에서 만들 것

장이 끝난 뒤 그날을 정리한 **일지**를 만듭니다. 일지는 사람이 읽는 글 파일(`docs/daily_journal_날짜.md`)이고, 이 파일을 쓰는 프로그램이 `daily_journal.py`입니다. 일지에는 오늘 주문이 계획대로 됐는지, 그리고 가격이 어디까지 가면 신호가 바뀌는지를 적습니다.

- 오늘 체결과 보유 확인
- 신호가 바뀌는 조건 미리 보기
- **실습 22**: 일지를 쓰는 프로그램 `daily_journal.py` 작성 및 오늘 자 일지 만들기

## 이론 핵심

### 1. 일지 한 장

일지는 장 마감 후 하루에 한 번 `docs/daily_journal_날짜.md` 파일로 저장됩니다. 파이썬 파일이 아니라 프로그램이 만든 결과 글이라, VS Code나 메모장으로 열어 읽습니다. 네 부분으로 되어 있습니다. 아래는 신호가 바뀐 월요일 저녁의 일지 예시입니다.

```text
# 장 마감 후 일지 2026-10-05 (월)                         (숫자는 예시, 일부만 보임)

1. 오늘 체결
   오늘 주문 없음

2. 잔고 (장 마감 기준)
   KODEX 200      66주   평균 매수가  98,200원   평가손익 +412,000원
   하나금융지주     5주   평균 매수가  88,000원   평가손익  -21,000원
   보유가 목표와 같음

3. 다음 거래일 주문 (orders_2026-10-05.json)
   하나금융지주    5주 매도   자동
   KB금융          3주 매수   승인 대기   ← 승인할 것
   이유: 페어 스위칭이 하나금융지주에서 KB금융으로 교체

4. 신호가 바뀌는 조건
   추세추종     지금 보유. 종가가 200일선보다 14.6% 위
   페어 스위칭  오늘 KB금융으로 바뀜
   듀얼 모멘텀  다음 판정일까지 18거래일. 지금 1위는 KODEX 200
```

- **1·2번**은 오늘 계획대로 됐는지 봅니다. 보유가 목표와 다르면 매수를 승인하지 않았거나, 일부만 체결됐거나, 안전장치가 팔았을 수 있어서 기록에서 그 이유를 찾아 함께 적습니다.
- **3번**은 오늘 만든 주문 목록을 옮겨 적은 것입니다. '승인 대기'가 있으면 주문 목록 파일을 열어 승인하거나 거절합니다. 대부분의 날은 "다음 거래일 주문 없음"입니다.
- 사람이 읽는 일지와 별도로, 2번 잔고의 숫자는 `logs/holdings_날짜.json`에도 남깁니다. 다른 프로그램(예: 매매 결과 분석)이 글을 해석하지 않고 숫자를 바로 읽게 하기 위해서입니다.
- **4번**은 신호가 바뀌려면 얼마나 남았는지 보여 줍니다. 신호 파일은 "지금 신호가 무엇인가"만 말해 주기 때문입니다. 기준에서 멀면 당분간 주문이 없을 가능성이 높고, 가까우면 다음 장 마감 후 일지를 꼭 확인합니다.

## 실습 — 실습 22: 장 마감 후 일지 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 신호 파일, 주문 목록, `approvals_log.json`, `orders_history.json`을 읽고, 일지를 `docs/daily_journal_YYYYMMDD.md`로, 잔고 숫자를 `logs/holdings_YYYYMMDD.json`으로 저장합니다. 먼저 `generate_signals.py`와 `prepare_orders.py`를 차례로 실행해 두세요.

```prompt
[맥락] 장 마감 후에 오늘 주문이 계획대로 됐는지 확인하고, 신호가 바뀌는 조건을 미리 정리한 일지를 만들고 싶어. 작업 폴더의 kis_auth.py, generate_signals.py와 그동안 쌓인 파일(signals_날짜.json, orders_날짜.json, approvals_log.json, orders_history.json)을 쓴다.

[만들 것] 파이썬 스크립트 'daily_journal.py'를 작성하고 실행해줘:
1. 오늘 체결: 'orders_history.json'의 오늘 주문을 증권사 체결 내역과 대조해 [종목 / 매수·매도 / 주문 수량 / 체결 수량 / 예상 가격 / 체결 가격 / 차이(%)] 표를 만들어줘. 오늘 주문이 없으면 '오늘 주문 없음'으로 적어.
2. 잔고: 종목별 [보유 수량, 평균 매수가, 현재가, 평가손익]과 [예수금, 총자산]을 적고, 보유 수량을 직전 거래일 신호 파일의 목표와 비교해줘. 다르면 승인 기록과 주문 기록(안전장치 매도 포함)에서 이유를 찾아 적어. 'lock.flag'가 있으면 맨 위에 '매수 중단 중'이라고 적어.
3. 다음 거래일 주문: 오늘 날짜의 주문 목록이 있으면 주문과 승인 상태를 옮겨 적어줘.
4. 신호가 바뀌는 조건: generate_signals.py의 규칙을 그대로 써서 추세추종(200일선까지 남은 %), 페어 스위칭(지금 Z와 ±1.5까지 거리), 듀얼 모멘텀과 시장 국면(다음 판정일), 조정 비중(지금 쓰는 값과 오늘 계산한 값의 차이)을 적어줘.
5. 'docs/daily_journal_YYYYMMDD.md'로 저장하고, 2번 잔고는 'logs/holdings_YYYYMMDD.json'에도 종목마다 [종목코드, 종목명, 보유 수량, 평균 매수가, 현재가, 평가손익]과 계좌의 [예수금, 총자산]으로 저장해. 대화창에 세 줄 요약(오늘 체결 / 다음 거래일 주문과 승인 대기 건수 / 기준에 가장 가까운 신호)을 보여줘.

[하지 말 것]
- 거래 코드(기능마다 붙은 이름표)를 짐작으로 쓰지 마. KIS Developers 문서나 한국투자증권 공식 GitHub 예제(koreainvestment/open-trading-api)에서 모의투자용을 확인하고 출처를 알려줘.
- 읽고 기록만 해. 주문을 내거나 다른 파일을 바꾸지 마.
- 조회에 실패한 값을 추정해서 채우지 마. '조회 실패'로 적어.
- 손익이 왜 그렇게 나왔는지 원인을 분석하지 마.

[확인] 세 줄 요약과 저장된 일지 경로를 보여줘.
```
