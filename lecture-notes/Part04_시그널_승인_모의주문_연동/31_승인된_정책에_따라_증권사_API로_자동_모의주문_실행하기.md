# 승인된 정책에 따라 증권사 API로 자동 모의주문 실행하기

## 이번 클립에서 만들 것

이 클립이 끝나면, 여러분은 승인된 주간 정책(`weekly_policy.json`)과 실시간 시그널(`signals.json`)을 읽어들여, 조건이 충족되었을 때 **한국투자증권 모의투자 API를 통해 실제 주식 매수/매도 주문을 자동으로 전송하고, 체결 영수증(주문번호, 체결가, 체결수량)을 받아 기록하는 '무인 자동 발주 엔진(`execute_orders.py`)'**을 완성하게 됩니다.

> 💡 **수강생 안심 안내**: 승인되지 않은 정책(상태가 `ACTIVE`가 아닌 정책)이거나 유효기간이 지난 정책인 경우, 발주 엔진은 스스로 안전하게 멈추며 절대로 임의로 주문을 넣지 않습니다.

- KIS 국내주식 주문(모의투자 현금매수 `VTTC0012U` / 현금매도 `VTTC0011U`) API 규격 이해

> 💡 **거래 코드는 계좌 종류와 시기에 따라 다릅니다.** 모의투자 코드는 `V`로, 실전 계좌 코드는 `T`로 시작합니다(예: 매수 `VTTC0012U` / `TTTC0012U`). 주문 코드는 2025년에 바뀌었고, 예전 코드(`…0802U`/`…0801U`)는 한국투자증권이 "사전 고지 없이 막힐 수 있다"고 안내하고 있습니다. 인터넷 예제에서 예전 코드를 보더라도 이 강의의 코드를 쓰세요.
- 주문 유형: 시장가(01) 주문 vs 지정가(00) 주문의 장단점과, 이 시스템에서 어느 쪽을 쓰는지
- 같은 신호로 주문이 두 번 나가지 않게 막는 주문 기록 파일(`orders_history.json`) 설계
- **실습 19**: `execute_orders.py` 실행을 통한 KIS 모의투자 계좌 실제 1주 매수/매도 체결 테스트

## 이론 핵심

### 1. 무인 자동 발주 파이프라인 (Execution Flow)

```text
[1. 사전 정책 검증] ──> weekly_policy.json이 ACTIVE 상태인지 & 유효기간 내인지 확인
         ↓
[2. 시그널 읽기]    ──> signals.json에서 BUY/SELL 신호 및 목표 수량 확인
         ↓
[3. 중복 주문 검사] ──> 이미 오늘 동일 종목으로 발주된 이력이 있는지 orders_history.json 대조
         ↓
[4. KIS API 주문]  ──> 현금 주문 주소(/uapi/domestic-stock/v1/trading/order-cash)로 주문 전송(POST)
         ↓
[5. 체결 확인 & 로깅]──> 주문번호(ODNO) 수신, 체결 결과 저장 및 일일 매매 저널 기록
```

---

### 2. KIS 주식 주문 요청에 꼭 넣는 항목

| 항목 이름 | 의미 | 예시값 | 설명 |
|---|---|---|---|
| `CANO` | 종합계좌번호 8자리 | `"50123456"` | `.env`에서 로드 |
| `ACNT_PRDT_CD` | 계좌상품코드 2자리 | `"01"` | 보통 주식 계좌 01 |
| `PDNO` | 종목코드 6자리 | `"069500"` | KODEX 200 등 |
| `ORD_DVSN` | 주문구분 | `"01"` | **"01": 시장가 (즉시 체결)**, "00": 지정가 |
| `ORD_QTY` | 주문 수량 | `"10"` | 문자열 형태의 정수 주수 |
| `ORD_UNPR` | 주문 단가 | `"0"` | 시장가 주문 시에는 "0" 전달 |

---

### 3. 시장가 vs 지정가: 무엇을 언제 쓰나

| 주문 | 뜻 | 장점 | 단점 |
|---|---|---|---|
| **시장가 (01)** | 가격을 정하지 않고 지금 나와 있는 가격에 바로 사고파는 주문 | 거의 확실하게 바로 체결됨 | 가격이 급하게 움직이거나 호가 간격이 벌어져 있으면 생각보다 불리한 가격에 체결됨(슬리피지: 주문한 가격과 실제 체결 가격의 차이) |
| **지정가 (00)** | 정한 가격에만 사고파는 주문 | 정한 가격보다 불리하게 체결되지 않음 | 가격이 안 맞으면 체결되지 않고, 넣었지만 아직 사고팔리지 않은 주문(미체결)으로 남음 |

이 시스템은 **시장가를 기본으로 씁니다.** 사람이 지켜보지 않는 무인 실행에서는 "주문이 걸린 채 안 팔렸다"가 "조금 불리하게 팔렸다"보다 훨씬 위험하기 때문입니다. 특히 다음 클립의 손절 청산은 반드시 시장가입니다.

## 실습 — 실습 19: 무인 자동 주문 발주 모듈 실행

Claude Code 대화창에 아래 프롬프트를 입력하세요.

```prompt
[맥락] 승인된 weekly_policy.json을 준수하여 KIS 모의투자 계좌로 자동 주문을 전송하는 발주 모듈을 완성하고 싶어. 클립 27~29에서 만든 kis_auth.py, market_data.py, realtime_signals.py와 signals.json을 그대로 쓴다.

[만들 것] 다음 조건에 맞춰 파이썬 스크립트 'execute_orders.py'를 작성하고 실행해줘:
1. weekly_policy.json의 정책 상태가 'ACTIVE'이고 오늘 날짜가 유효기간 내인지 먼저 검증해줘. (비정상 시 즉각 중단)
2. signals.json을 읽고, BUY 신호가 발생한 첫 번째 종목(또는 테스트용 1주)에 대해 KIS 주식 현금매수 API(모의투자용 거래 코드 VTTC0012U)를 호출해줘. 주문은 시장가(가격을 정하지 않고 지금 나와 있는 가격에 바로 사는 주문)로 넣어줘.
3. 주문 성공 시 반환되는 주문번호(ODNO)와 체결 메시지를 확인하고, 'orders_history.json'에 [주문시간, 종목코드, 주문유형, 주문수량, 주문번호]를 기록해줘.
4. 중복 발주를 방지하기 위해 이미 발주 완료된 신호는 재주문되지 않도록 필터링해줘.
5. 대화창에 체결 영수증 요약표를 출력해줘.

[하지 말 것]
- 주문은 반드시 모의투자 서버(openapivts)로만 보내. 실전투자 서버 주소나 실전 계좌번호가 코드에 들어가면 실행하지 말고 멈춰.
- weekly_policy.json 검증(ACTIVE·유효기간)을 건너뛰거나, 검증 실패 시 '일단 주문'하지 마. 실패하면 주문 없이 종료해.
- 주문 API 호출이 실패하거나 응답이 불확실하면 재시도로 중복 주문을 내지 마. 실패를 기록하고 멈춰.
- 오늘 이 실습에서는 테스트용 1주(또는 첫 종목 1건)만 주문해. signals.json의 모든 신호를 한 번에 발주하지 마.

[확인] 대화창에 모의투자 주문 체결 영수증(주문번호 ODNO, 종목, 수량)이 출력되었는지, 'orders_history.json'에 기록되었는지, 그리고 내가 증권사 모의투자 화면에서 같은 주문을 확인할 수 있는지 알려줘.
```

---

### 내 눈으로 확인할 체크리스트

- [ ] `weekly_policy.json`의 승인 상태를 검증한 뒤 발주 프로세스가 안전하게 시작되었다.
- [ ] 증권사가 주문을 정상 접수했다고 답했고(응답의 성공 여부 칸 `rt_cd`가 "0"), 주문번호가 발급되었다.
- [ ] `orders_history.json`에 오늘의 주문 이력이 정확하게 기록되었다.
- [ ] 한국투자증권 MTS/HTS 모의투자 화면에서 해당 종목의 체결 내역을 눈으로 확인했다.
