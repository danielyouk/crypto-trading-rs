# 설정한 조건에 따라 매매 신호 만들기

## 이번 클립에서 만들 것

장 마감 뒤 그날 종가로 만든 신호(`signals.json`)는 "무엇을 몇 주 들고 있어야 하는가"라는 **목표**입니다. 이 클립에서는 그 목표를 내 모의투자 계좌의 **실제 잔고**와 맞춰 보고, 다음 개장 때 낼 **주문 목록**으로 바꿉니다.

> 💡 세 전략(추세추종, 듀얼 모멘텀, 페어 스위칭)은 모두 장 마감 뒤 그날 종가로 판정이 끝납니다. 다음 날 장중에 가격을 보며 신호를 다시 계산하지 않습니다.

- 신호 파일의 목표 수량과 계좌의 실제 보유 수량 비교하기
- 순주문(사야 할 수량, 팔아야 할 수량) 계산과 현금 확인
- **실습 17**: `prepare_orders.py` 작성 및 `orders.json` 생성

---

## 이론 핵심

### 1. 신호는 목표이고, 계좌는 현실입니다

신호를 만들 때는 "직전 목표대로 체결됐다"고 가정하고 순주문을 계산했습니다. 실제 계좌는 그 가정과 다를 수 있습니다.

| 어긋나는 경우 | 예 |
|---|---|
| 주문이 다 체결되지 않았다 | 10주를 냈는데 7주만 체결 |
| 매수를 승인하지 않았다 | 목표는 14주인데 계좌에는 11주 그대로 |
| 안전장치가 장중에 팔았다 | 급락한 날 손절로 전량 매도 |
| 내가 직접 사고팔았다 | 증권사 앱에서 수동 매매 |
| 처음 시작하는 날 | 계좌에 주식이 하나도 없음 |

그래서 실제 주문은 신호 파일끼리 비교해서가 아니라 **계좌를 조회해서** 정합니다.

---

### 2. 순주문 계산

$$\text{순주문} = \text{종목 목표 수량} - \text{계좌 실제 보유 수량}$$

- 값이 +면 그만큼 사고, −면 그만큼 팝니다. 0이면 주문하지 않습니다.
- 같은 종목을 두 전략이 쓰면 신호 파일의 종목 목표 수량에 이미 합쳐져 있습니다.
- **파는 주문을 먼저, 사는 주문을 나중에** 놓습니다. 판 돈이 들어와야 살 수 있기 때문입니다.

```text
[예시]
종목          목표   실제 보유   순주문
KODEX 200     66주    66주       0   (주문 없음)
KB금융        14주    11주      +3   (3주 매수)
하나금융지주    0주     5주      −5   (5주 매도, 먼저 놓음)
```

대부분의 날은 목표와 보유가 같아 **주문 목록이 비어 있습니다.** 그것이 정상입니다.

---

### 3. 예상 금액은 어림값입니다

주문 목록의 금액은 지금 가격으로 어림한 값입니다. 실제로는 다음 날 시가에 체결되므로 가격이 달라지고(슬리피지: 주문할 때 본 가격과 실제 체결 가격의 차이), 수수료도 붙습니다. 그래서 두 가지를 해 둡니다.

- 사는 주문의 예상 금액 합계가 **쓸 수 있는 현금의 95%**를 넘으면 주문 목록을 만들지 않고 멈춥니다. 쓸 수 있는 현금은 **예수금**(계좌에 있는, 아직 주식을 사지 않은 현금)에 팔아서 들어올 예상 금액을 더한 값입니다.
- 실제 체결 가격과 금액은 주문한 뒤에 다시 확인합니다.

## 실습 — 실습 17: 다음 개장 때 낼 주문 목록 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 `generate_signals.py`가 저장한 `signals.json`을 읽고, 주문 목록을 `orders.json`과 `logs/orders_original.json`(고치기 전의 원본)으로 저장합니다. 연습 때 만든 신호는 날짜가 지났으니, 먼저 `generate_signals.py`를 날짜 없이 실행해 `signals.json`을 가장 최근 종가 기준으로 새로 만드세요. 신호가 오래됐으면 AI가 주문 목록을 만들지 않고 멈추도록 해 두었습니다.

```prompt
[맥락] 가장 최근 종가로 만든 매매 신호를 내 모의투자 계좌의 실제 잔고와 비교해, 다음 개장 때 낼 주문 목록을 만들고 싶어. 작업 폴더의 kis_auth.py(인증과 잔고 조회)와 market_data.py(현재가 조회)에 만들어 둔 기능을 그대로 가져다 쓴다.

[만들 것] 다음 조건에 맞춰 파이썬 스크립트 'prepare_orders.py'를 작성하고 실행해줘:
1. 먼저 작업 폴더의 'signals.json'과 'generate_signals.py', 'kis_auth.py', 'market_data.py'를 읽어 항목 이름과 쓸 수 있는 함수를 확인해줘. 그다음 'signals.json'에서 기준일, 국면, 총 투자금, 전략별 목표 수량과 바뀐 이유, 종목별 목표 수량을 읽어.
2. kis_auth.py로 모의투자 계좌의 예수금(아직 주식을 사지 않은 현금), 총자산(예수금 + 들고 있는 주식의 현재 평가금액), 종목별 실제 보유 수량을 조회해줘.
3. 종목마다 순주문 = 목표 수량 − 실제 보유 수량을 계산해줘. 신호 파일에 없는데 계좌에 들고 있는 종목은 목표 0주로 봐서 매도 대상에 넣고, 표에 '신호에 없는 보유 종목'이라고 표시해줘.
4. 주문이 있는 종목만 market_data.py로 현재가를 조회해(요청 한도를 넘지 않게 kis_auth.py의 공용 요청 함수로) 예상 주문 금액을 계산하고, 매도 주문을 앞에, 매수 주문을 뒤에 놓은 주문 목록을 만들어줘.
5. 주문 목록을 'orders.json'으로 저장해줘. 맨 위에 [만든 시각, 신호 기준일, 국면]을, 주문마다 [종목코드, 종목명, 매수/매도, 수량, 예상 가격, 예상 금액, 목표 수량, 실제 보유 수량, 이유(어느 전략의 무엇이 바뀌었는지), 승인 상태, 메모]를 담아. 승인 상태는 매도면 '자동', 매수면 '승인 대기'로 적고, 메모는 빈 칸("")으로 둬(내가 승인·거절 사유를 적는 칸). 주문이 하나도 없으면 빈 목록으로 저장해. 같은 내용을 'logs/orders_original.json'으로도 저장해줘(내가 승인 상태와 메모를 고치기 전의 원본).
6. 대화창에 [종목 / 목표 수량 / 실제 보유 / 순주문 / 예상 금액 / 이유] 표와 예수금, 총자산을 출력해줘.

[하지 말 것]
- 주문 목록을 만들기만 해. 매수·매도 주문 API를 호출하지 마.
- 신호를 현재가로 다시 판정하지 마. 목표 수량은 signals.json의 값을 그대로 써.
- 오래된 신호로 주문 목록을 만들지 마. generate_signals.py가 날짜 없이 실행될 때 기준일을 정하는 것과 같은 방식으로 '가장 최근 확정 종가일'을 구하고, signals.json의 기준일이 그 날짜와 다르면 멈춰서 "generate_signals.py를 먼저 실행하라"고 알려줘.
- 매수 예상 금액 합계가 (예수금 + 매도 예상 금액 합계)의 95%를 넘거나, signals.json의 총 투자금이 계좌 총자산보다 크면 주문 목록을 저장하지 말고 멈춰서 얼마가 모자라는지 알려줘.
- 잔고나 현재가 조회에 실패하면 수량을 지어내지 말고 멈춰서 알려줘.
- kis_auth.py, market_data.py, signals.json을 수정하지 마.

[확인] 대화창에 종목별 목표·보유·순주문 표가 출력되었는지, 'orders.json'이 저장되었는지 확인해줘.
```

---

### 내 눈으로 확인할 체크리스트

- [ ] 표의 실제 보유 수량과 예수금이 증권사 앱(MTS)의 잔고와 같은지 대조했다.
- [ ] 순주문이 목표 수량 − 실제 보유 수량으로 계산되었고, 매도 주문이 매수 주문보다 앞에 놓였다.
- [ ] `orders.json`에서 매도는 '자동', 매수는 '승인 대기'로 적혀 있다. 주문이 없으면 빈 목록이다.
