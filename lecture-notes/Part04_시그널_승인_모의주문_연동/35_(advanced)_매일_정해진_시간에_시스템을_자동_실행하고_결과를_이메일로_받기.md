# (advanced) 매일 정해진 시간에 시스템을 자동 실행하고 결과를 이메일로 받기

## 이번 클립에서 만들 것

지금까지 만든 프로그램을 내가 켜지 않아도 **매일 정해진 시각에 저절로 돌게** 합니다. 장 마감 후 작업과 개장 작업을 각각 실행 파일로 만들고, 컴퓨터의 예약 실행 기능에 등록합니다. 예약 실행 기능은 윈도우에서는 **작업 스케줄러**, Mac에서는 **launchd**라고 부릅니다. 실행 결과는 내 컴퓨터에 남기고, 그날 일지는 이메일로 받습니다.

> 💡 등록 방법이 낯설어도 괜찮습니다. Claude Code가 내 컴퓨터 종류를 확인해 등록 방법을 문서로 정리해 줍니다.

- 하루에 두 번 실행하는 이유
- 윈도우와 Mac에서 예약 실행 등록하기
- 실행 결과를 내 컴퓨터에 남기고 이메일로 받기
- **실습 23**: 장 마감 후 작업과 개장 작업 만들기 및 드라이런

---

## 이론 핵심

### 1. 하루에 두 번 실행합니다

```text
[평일 17:00] 장 마감 후 작업
   • 오늘이 휴장일이면 아무것도 하지 않음
   • 신호 계산. 가격 데이터가 오늘 종가까지 오지 않았으면 여기서 멈추고 오류 메일
   • 다음 거래일 주문 목록 → 장 마감 후 일지
   • 실행 기록과 일지를 내 컴퓨터에 저장하고, 일지를 이메일로 보냄
        ↓
[사람] 다음 날 개장 전까지 그날 주문 목록(orders_날짜.json)을 열어 매수를 승인하거나 거절
        ↓
[평일 09:00] 개장 작업
   • 승인 상태를 검사한 뒤 매도와 승인된 매수를 보냄
   • 이어서 15:30까지 1~2초마다 잔고를 확인하는 장중 안전장치를 돌림
```

**17:00에 돌리는 이유**: 장은 15:30에 끝나지만, 종가가 데이터 출처에 반영되기까지 시간이 걸립니다. 여유를 두고 돌립니다.

**09:00에도 돌리는 이유**: 저녁에 승인한 매수를 그 자리에서 증권사에 맡겨 두고 다음 날 아침에 체결되게 하려면 증권사의 **예약주문** 기능이 필요합니다. 모의투자에는 이 기능이 없어서, 다음 날 장이 열릴 때 우리 프로그램이 직접 주문을 보냅니다. 사람이 09:00에 할 일은 없습니다. 사람이 하는 일은 그 사이의 승인 한 가지입니다.

대부분의 날은 주문 목록이 비어 있어 09:00에 나가는 주문이 없고, 안전장치만 장 마감까지 돌고 끝납니다.

---

### 2. 윈도우와 Mac에서 예약 실행하기

예약 실행에는 **실행 파일**을 등록합니다. 실행 파일은 작업 폴더로 옮겨 간 뒤, 그 폴더 가상환경의 파이썬으로 프로그램을 실행하는 몇 줄짜리 파일입니다. 예약 실행은 터미널과 달리 작업 폴더와 가상환경을 잡아 주지 않아서 이렇게 적어 둡니다.

| | 윈도우 | Mac |
|---|---|---|
| 예약 실행 기능 | 작업 스케줄러 (`schtasks` 명령) | launchd (`launchctl` 명령) |
| 실행 파일 | `.bat` | `.sh` |
| 예약 설정이 저장되는 곳 | 작업 스케줄러 라이브러리 | `~/Library/LaunchAgents` 폴더의 `.plist` 파일 |

윈도우에서 평일 17:00에 실행 파일을 돌리는 등록 명령은 이런 모양입니다. 리눅스에서는 같은 일을 크론탭(crontab)으로 합니다.

```bat
schtasks /create /tn "AI트레이딩 장 마감 후" /tr "C:\ai-trading\run_after_close.bat" /sc weekly /d MON,TUE,WED,THU,FRI /st 17:00
```

`/sc weekly /d MON,…,FRI`는 매주 월~금, `/st 17:00`은 17시라는 뜻입니다. Mac은 같은 내용을 `.plist` 파일에 적어 등록합니다.

> ⚠️ 예약 시각에 컴퓨터가 **꺼져 있으면 그날은 실행되지 않습니다.** 잠자기 상태에서 놓친 실행을 깨어난 뒤 돌리는 설정은 윈도우와 Mac이 다르니 등록 안내 문서에서 확인하세요. Mac은 작업 폴더가 '문서'나 '데스크탑' 안에 있으면 권한 문제로 예약 실행이 막힐 수 있습니다.

공휴일에 개장 작업이 켜져 주문을 보내더라도 증권사가 받지 않으며, 그 실패는 실행 기록과 오류 메일로 남습니다.

---

### 3. 결과는 내 컴퓨터에 남기고, 일지는 메일로 받습니다

- 두 작업 모두 화면에 찍히는 내용과 에러를 날짜별 실행 기록(`logs/run_YYYYMMDD.log`)에 남깁니다. 예약 실행은 화면이 없기 때문입니다.
- 장 마감 후 작업이 끝나면 그날 일지를 **일일 보고** 메일로 보냅니다. 일지에 다음 거래일 주문이 적혀 있어도 메일로는 승인할 수 없습니다. 승인은 내 컴퓨터의 주문 목록 파일(`orders_날짜.json`)에서 합니다.
- 일일 보고가 오지 않은 날은 장 마감 후 작업이 돌지 않은 날입니다. 컴퓨터가 꺼져 있었는지, 실행 기록에 오류가 있는지 확인합니다.
- 한 단계가 실패하면 **오류** 메일을 보내고, 그 결과가 필요한 뒤 단계만 건너뜁니다. 장 마감 후 작업이 돌지 않아 전날 주문 목록이 없으면, 개장 작업은 그보다 오래된 목록으로 주문하지 않습니다. 그 자리에서 전날 종가로 주문 목록을 만들어 **매도만 보내고**, 매수는 내가 본 적이 없으니 보내지 않은 채 오류 메일을 보냅니다. 빠진 매수는 그날 장 마감 후 목록에 다시 올라옵니다(주문 목록은 목표와 실제 보유의 차이로 만들기 때문).

## 실습 — 실습 23: 정해진 시각에 실행되는 작업 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 앞에서 만든 프로그램들을 불러 쓰고, 실행 기록을 `logs/run_YYYYMMDD.log`에, 등록 안내를 `docs/scheduler_setup.md`에 저장합니다. 일지는 `notifier.py`의 일일 보고 기능으로 보냅니다. 드라이런에서도 장 마감 후 작업은 그대로 실행되어 신호 파일과 그날의 주문 목록(`orders_날짜.json`)을 만듭니다. 같은 날짜의 주문 목록이 이미 있으면 덮어쓰지 않으므로, 고쳐 둔 승인 상태는 그대로 남습니다.

```prompt
[맥락] 작업 폴더의 프로그램들(generate_signals.py, prepare_orders.py, daily_journal.py, approve_orders.py, execute_orders.py, risk_guard.py, notifier.py)을 내가 켜지 않아도 평일마다 정해진 시각에 실행되게 하고 싶어. 먼저 이 파일들을 읽어 각각 어떤 함수와 실행 옵션이 있는지 확인하고, 내 컴퓨터 종류(윈도우, 윈도우 안의 WSL, Mac)와 작업 폴더 가상환경의 파이썬 위치를 확인한 뒤 시작해줘.

[만들 것] 다음 조건에 맞춰 스크립트와 실행 파일, 안내 문서를 만들고 드라이런으로 실행해줘:
1. 'run_after_close.py' (평일 17:00 장 마감 후 작업):
   - 평일 15:30 전에 켜졌거나 오늘이 휴장일(오늘 종가가 없는 날)이면 아무것도 만들지 말고 이유를 기록한 뒤 끝내.
   - generate_signals.py를 '--date 오늘'로 실행 ➔ prepare_orders.py ➔ daily_journal.py 순서로 실행해. prepare_orders.py가 같은 날짜의 주문 목록이 이미 있어서 멈추면 실패로 보지 말고 그 파일을 그대로 둔 채 다음 단계로 넘어가.
   - generate_signals.py가 쓰는 종목들과 KOSPI 지수의 가격 데이터가 오늘 종가까지 오지 않았으면 주문 목록을 만들지 말고 '오류' 메일을 보내.
   - 끝나면 notifier.py로 오늘 일지를 '일일 보고' 메일로 보내. 승인은 내가 주문 목록 파일에서 하므로 이 작업에서 승인하거나 묻지 마.
2. 'run_market_open.py' (평일 09:00 개장 작업):
   - 맨 위에 실행 방식('승인' 또는 '자동', 기본값 '승인')을 둬. '승인'이면 approve_orders.py로 검사만 하고, '자동'이면 '--auto'로 실행해.
   - execute_orders.py를 옵션 없이 실행한 것과 같게 매도와 승인된 매수를 보내. 보낼 주문이 없으면 건너뛰어.
   - 가장 최근 확정 종가일(직전 거래일)의 주문 목록 파일이 없으면(전날 장 마감 후 작업이 돌지 않은 경우) 더 오래된 파일로 주문하지 마. generate_signals.py를 '--date 직전 거래일'로, 이어서 prepare_orders.py를 실행해 그 날짜의 주문 목록을 지금 만들고, 매도만 보내. 이 목록의 매수는 내가 본 적이 없으니 실행 방식이 '자동'이어도 승인하지 마. 그리고 '오류' 메일로 '전날 주문 목록이 없어 오늘 아침 만들었고, 매도만 보냄'을 알려.
   - 이어서 15:30까지 risk_guard.py의 점검 함수를 '--live'로 실행한 것과 같게 되풀이 호출해. 요청은 kis_auth.py의 공용 요청 함수로만 보내 증권사의 요청 한도를 넘지 않게 해.
   - 09:00 전에 켜지면 09:00까지 기다리고, 15:30 뒤에 켜지면 아무것도 하지 말고 기록만 남겨.
3. 두 스크립트 공통:
   - 어느 폴더에서 실행하든 작업 폴더의 파일을 읽고 쓰게 해줘.
   - 모든 출력과 에러를 'logs/run_YYYYMMDD.log'에 이어서 기록해줘.
   - 한 단계가 실패하면 실패를 기록하고 '오류' 메일을 보낸 뒤, 그 결과를 써야 하는 뒤 단계만 건너뛰어. 개장 작업에서 주문 단계가 실패해도 안전장치는 돌려.
   - approve_orders.py 검사에 걸린 것은 단계 실패로 보지 마. 이유를 기록하고 '오류' 메일로 '검사에 걸려 매수는 보내지 않음'을 알린 뒤, 매도는 그대로 보내.
4. 내 컴퓨터에 맞는 실행 파일 두 개(윈도우면 '.bat', Mac이면 '.sh')를 만들어줘. 각각 작업 폴더로 옮겨 간 뒤 가상환경의 파이썬으로 위 스크립트 하나를 실행하게 해.
5. 'docs/scheduler_setup.md'에 예약 등록 안내를 써줘: 평일 17:00과 09:00에 두 실행 파일을 돌리는 등록 방법(윈도우는 작업 스케줄러, Mac은 launchd), 등록됐는지 확인하는 방법, 지우는 방법, 그 시각에 컴퓨터가 꺼져 있거나 잠자기 상태면 어떻게 되는지, 권한 문제로 실행이 막힐 때 확인할 것.
6. 두 스크립트 모두 '--dry-run'을 붙이면 시각을 기다리지 않고 바로 한 번 끝까지 돌게 해줘. 시각·휴장일 확인에 걸려도 멈추지 말고 '실제 실행이면 여기서 멈춤: (이유)'를 기록한 뒤 가장 최근 확정 종가일 기준으로 계속해. 주문은 execute_orders.py의 '--dry-run'으로, 안전장치는 risk_guard.py를 옵션 없이(점검만) 한 바퀴만 돌리고, 메일은 보내지 말고 보낼 제목과 본문 앞 몇 줄만 기록해. 이 실습에서는 두 스크립트를 '--dry-run'으로만 실행해줘.

[하지 말 것]
- 드라이런에서는 실제 주문 API를 호출하지 말고 메일도 보내지 마.
- 실행 방식이 '승인'일 때 매수를 대신 승인하지 마. 승인 대기인 매수는 보내지 않고 넘어가.
- 주문은 모두 execute_orders.py의 주문 함수로만 보내. 이 스크립트들에 주문 코드를 따로 만들지 마.
- 예약 실행에 직접 등록하지 마. 등록은 내가 안내 문서를 보고 한다.
- 기존 프로그램 파일을 수정하지 마.

[확인] 드라이런 기록에 장 마감 후 작업(시각·휴장일 확인 ➔ 신호 ➔ 데이터 날짜 확인 ➔ 주문 목록 ➔ 일지 ➔ 메일 미리 보기)과 개장 작업(승인 검사 ➔ 개장 주문 ➔ 안전장치 한 바퀴)이 순서대로 남았는지, 실행 파일 두 개와 'docs/scheduler_setup.md'가 만들어졌는지 확인해줘.
```
