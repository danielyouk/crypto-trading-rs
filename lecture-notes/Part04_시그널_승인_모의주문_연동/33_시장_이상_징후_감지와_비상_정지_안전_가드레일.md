# 시장 이상 징후 감지와 비상 정지(Kill-Switch) 안전 가드레일

## 이번 클립에서 만들 것

이 클립이 끝나면, 증권사 API 오류, 네트워크 단절, 지수 급락(Flash Crash) 등 비정상 상황이 발생했을 때 **시스템을 안전 상태로 전환하고 모든 신규 주문을 차단하는 비상 정지 킬스위치(Kill-Switch)**가 완성됩니다.

- 3회 연속 API 호출 실패 시 즉시 자동 안전 모드(Safe Mode) 전환
- 코스피/S&P 500 등 대표 지수 분당 -2% 이상 급락 시 긴급 매매 동결
- 단 한 줄의 터미널 명령어 또는 비상 플래그 파일(`EMERGENCY_STOP`)로 모든 주문 프로세스 즉시 종료

## 이론 핵심

### 시스템 트레이딩의 3대 비상 상황

아무리 뛰어난 알고리즘도 아래 3가지 환경적 재난 앞에서는 치명적 오류를 낼 수 있습니다:

1. **증권사/네트워크 먹통**: 주문 요청은 나갔는데 응답을 받지 못해 중복 발주가 나가는 사고
2. **시장 유동성 증발(Flash Crash)**: 호가창이 비어 있어 터무니없는 가격에 슬리피지가 발생하는 상황
3. **데이터 피드 오염**: 이상치(Outlier) 가격(예: 0원 또는 100배 폭등) 데이터가 들어와 엉뚱한 매매 신호가 뜨는 버그

## 실습 17 — 비상 정지 킬스위치 및 이상치 필터 구축

Claude Code에게 시스템 안전 감시 모듈을 작성하도록 요청합니다.

```prompt
트레이딩 봇의 이상 징후 감지 및 비상 정지(Kill-Switch) 모듈을 만들어줘.
1. 네트워크/증권사 API 오류가 3회 연속 발생하면 신규 주문을 즉시 동결하고 안전 모드로 전환해줘.
2. workspace 폴더에 'EMERGENCY_STOP'이라는 빈 파일이 생성되면 모든 주문 루프를 즉시 멈추고 종료해줘.
3. 데이터에 비정상적인 스파이크(가격 급변)가 발생하면 매매를 건너뛰도록 해줘.
가상 비상 상황을 발생시켜 안전하게 시스템이 멈추는 것을 보여줘.
```

### 내 눈으로 확인할 체크리스트

- [ ] API 3회 연속 실패 시 시스템이 무한 재시도하지 않고 안전 모드로 전환되었다
- [ ] `EMERGENCY_STOP` 파일 생성 시 실행 루프가 즉시 안전하게 종료되었다
- [ ] 비정상 가격 데이터 입력 시 주문이 나가지 않고 경고 로그가 기록되었다
- [ ] 비상 정지 후에도 기존 모의투자 계좌의 포지션 정보가 파일에 안전하게 보존되었다

## 자주 발생하는 문제

- **비상 정지 후 재시작 방법**: 비상 상황이 해제되면 `EMERGENCY_STOP` 파일을 삭제하고 정상 모드로 재실행하면 됩니다.
- **API 일시적 끊김**: 지하철 이동 등 일시적 네트워크 끊김은 3회 재시도(Retry with backoff) 후에도 실패할 때만 킬스위치가 작동하도록 설계합니다.
