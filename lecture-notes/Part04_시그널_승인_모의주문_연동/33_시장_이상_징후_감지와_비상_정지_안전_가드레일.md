# 시장 이상 징후 감지와 비상 정지 안전 가드레일

## 이번 클립에서 만들 것

이 클립이 끝나면, 여러분은 증권사 API가 정해진 시간 안에 답하지 않는 응답 지연(타임아웃), 인터넷 끊김, 몇 분 사이에 가격이 비정상적으로 폭락하는 급변, 또는 프로그램 오류로 주문이 멈추지 않고 계속 나가는 주문 폭주 같은 치명적인 돌발 사태를 실시간으로 감지하고, **'원터치 비상 정지 킬 스위치'**(파일 하나만 만들면 모든 주문이 멈추는 비상 정지 장치)를 통해 1초 만에 전체 시스템을 안전 모드로 동결하는 비상 대응 인프라를 완성하게 됩니다.

> 💡 **나이트 캐피털(Knight Capital) 파산 사건의 교훈**: 2012년 미국의 대형 투자사 나이트 캐피털은 알고리즘 버그로 45분 만에 4억 4천만 달러(약 5,000억 원)의 무차별 주문이 나가 파산했습니다. 비상 정지 킬 스위치는 모든 시스템 트레이더의 **'비상 탈출 버튼'**입니다.

- **3대 시스템 비상 징후**: API 3회 연속 타임아웃, 사겠다·팔겠다는 주문이 호가창에서 거의 사라지는 비정상 호가 공백, 주문 빈도 초과(1분에 10회를 넘는 주문 감지)
- **파일 기반 킬 스위치(`kill_switch.flag`)**의 원리: 있기만 하면 신호가 되는 빈 파일(플래그 파일) 하나로 모든 주문을 멈추는 방식
- 언제든지 실행해 킬 스위치를 켜는 긴급 스크립트(`kill_switch.py`)
- **실습 21**: 킬 스위치 발동 테스트 및 시스템의 즉각적인 안전 동결(Freeze) 검증

## 이론 핵심

### 1. 킬 스위치의 작동 원리

인터넷이 끊겨도, **내 컴퓨터에 특정 플래그 파일(`kill_switch.flag`)이 있는지만 검사하는 방식**은 그대로 동작합니다. 그래서 가장 믿을 수 있는 비상 정지 방법입니다. 클립 32의 서킷브레이커가 만드는 `lock.flag`도 같은 방식으로 확인합니다. **둘 중 하나라도 있으면 주문을 내지 않습니다.**

```text
[실행 루프 (매 초마다 감시)]
if os.path.exists("kill_switch.flag") or os.path.exists("lock.flag"):
    logger.critical("🚨 비상 정지 표시 감지! 모든 신규 주문 즉각 차단 및 안전 종료!")
    sys.exit(1)
```

## 실습 — 실습 21: 비상 정지 킬 스위치 구축 및 테스트

Claude Code 대화창에 아래 프롬프트를 입력하세요.

```prompt
[맥락] 시스템의 안전을 보장하는 비상 정지 킬 스위치와, 모든 무인 실행 스크립트가 그것을 먼저 확인하는 가드레일을 만들고 싶어.

[만들 것] 다음 조건에 맞춰 파이썬 스크립트 'kill_switch.py'를 작성하고 기존 모듈에 가드레일을 추가한 뒤 실행해줘:
1. 'kill_switch.py': 실행 시 'kill_switch.flag' 파일을 생성하고, 현재 계좌의 미체결 주문(넣었지만 아직 사고팔리지 않고 기다리는 주문)을 전량 취소하며 비상 정지 사유를 로그에 기록해줘.
2. 모든 무인 실행 스크립트(execute_orders.py, realtime_signals.py)의 최상단에 가드레일 함수 'check_emergency_stop()'을 추가해줘. 이 함수는 'kill_switch.flag' 또는 'lock.flag'(risk_guard.py의 서킷브레이커가 오늘 매매를 멈추라는 표시로 만드는 빈 파일) 중 하나라도 있으면 멈춰야 해.
3. 두 파일 중 하나라도 있을 때는 어떤 주문도 증권사로 나가지 않고 'EMERGENCY_STOPPED' 에러와 함께 즉시 종료되도록, 두 파일 각각으로 테스트해줘.
4. 비상 상황 해제 명령어(플래그 파일 삭제 함수)도 함께 제공해줘. lock.flag는 서킷브레이커가 발동한 날의 표시라서, 다음 거래일 전에 내가 원인을 확인하고 이 함수로 지운다.

[하지 말 것]
- execute_orders.py, realtime_signals.py에 check_emergency_stop() 호출을 추가하는 것 외에 기존 로직을 바꾸지 마.
- 두 파일 중 하나라도 있을 때 '중요한 주문이니 예외로 통과'시키는 우회 경로를 만들지 마. 예외는 없어야 해.
- 미체결 주문 취소는 모의투자 서버에서만 실행해. 취소에 실패하면 사유를 로그에 남기고 멈춰.

[확인] 대화창에 킬 스위치 생성 ➔ 발주 차단(EMERGENCY_STOPPED) ➔ 킬 스위치 해제의 3단계 동작 검증 로그가 순서대로 출력되었는지, 그리고 lock.flag만 있을 때도 발주가 차단되었는지 확인해줘.
```

### 내 눈으로 확인할 체크리스트

- [ ] `kill_switch.py` 실행 시 `kill_switch.flag` 파일이 즉시 생성되었다.
- [ ] 킬 스위치 활성화 상태에서 발주 스크립트를 실행했을 때 주문이 100% 원천 차단되고 안전 종료되었다.
- [ ] `lock.flag`만 있을 때도 발주 스크립트가 주문 없이 멈췄다.
- [ ] 킬 스위치 해제 시 다시 정상 감시 상태로 복귀함을 확인했다.
