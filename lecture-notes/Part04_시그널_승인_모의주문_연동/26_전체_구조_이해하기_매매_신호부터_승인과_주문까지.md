# 전체 구조 이해하기: 매매 신호부터 승인과 주문까지

## 이번 클립에서 만들 것

이번 클립에서는 새 프로그램을 만들지 않습니다. Part 4에서 만들 시스템이 **장 마감 후 신호 계산과 승인 → 다음 날 개장 주문 → 장중 안전장치** 순서로 어떻게 이어지는지 지도를 먼저 보고, 앞에서 만든 신호 스크립트를 오늘 날짜로 한 번 돌려 **신호에서 승인까지**를 미리 따라가 봅니다.

> 💡 지금 증권사 계좌를 켤 필요는 없습니다. 증권사 연결은 다음 클립에서 합니다.

- 하루가 어떤 순서로 돌아가는가
- 사람이 하는 일과 프로그램이 하는 일의 구분
- 오늘 신호를 뽑아 승인까지 미리 따라가 보기

## 이론 핵심

### 1. 매일 확인하지만, 주문은 가끔 나갑니다

우리가 운용하는 세 전략(추세추종, 듀얼 모멘텀, 페어 스위칭)은 모두 **장 마감 뒤 그날 종가로 판정이 끝납니다.** 그래서 다음 날 장이 열리기 전에 무엇을 몇 주 사고팔지가 모두 정해지고, 신호가 실제로 바뀌는 날은 드뭅니다.

| 주기 | 무엇 | 실제로 바뀌는 빈도 |
|---|---|---|
| 월말 | 시장 국면 판정 | 1년에 몇 번 |
| 매일 (장 마감 후) | 신호 계산, 다음 날 낼 주문 목록 만들기, 승인 | 주문이 생기는 날은 한 달에 몇 번 |
| 장중 | 급락을 막는 안전장치 | 기준에 닿는 날만 |

주문이 나갈 날이 언제일지는 미리 알 수 없습니다. 그래서 프로그램은 **매일 장 마감 뒤 주문 목록을 만들고**, 사람은 그 목록을 보고 승인합니다. 목록이 비어 있는 날은 확인만 하고 끝납니다.

---

### 2. 하루의 흐름

```text
[장 마감 후]  신호 계산 → 주문 목록 → 승인
  오늘 종가로 세 전략의 신호와 목표 수량을 계산하고, 계좌의 실제 보유 수량과 비교해
  내일 낼 주문 목록을 만듭니다. 사람은 이 목록을 보고 매수 주문을 승인하거나 거절합니다.
        ↓
[다음 날 개장]  주문
  매도 주문과 승인된 매수 주문을 프로그램이 증권사로 보냅니다.
        ↓
[장중]  안전장치
  손절 기준에 닿으면 사람에게 묻지 않고 청산합니다.
```

사람이 하는 일은 **장 마감 후의 승인 한 가지**입니다. 다음 날 개장 전까지만 하면 되고, 주문 목록이 비어 있는 날은 확인만 하고 끝납니다. 대부분의 날이 그렇습니다.

이 흐름과 별개로, 프로그램이 한 일을 알려 주는 **보고** 두 가지가 있습니다. 장 마감 후 일지는 오늘 주문이 제대로 체결됐는지와 신호가 바뀌는 조건을 정리하고, 이메일은 프로그램이 나 없이 한 일(체결 결과, 손절 실행, 오류)을 알려 줍니다. 둘 다 승인의 단계가 아니라, 이미 일어난 일을 알려 주는 것입니다.

---

### 3. 사람이 하는 일과 프로그램이 하는 일

| 일 | 누가 | 이유 |
|---|---|---|
| 신호 계산, 주문 목록 만들기 | 프로그램 | 규칙대로 계산하면 되는 일 |
| **매수 주문** | **사람이 승인한 뒤** 프로그램이 주문 | 위험을 늘리는 주문. 승인이 없으면 그날은 사지 않음 |
| 매도 주문 | 프로그램 (승인 없이) | 위험을 줄이는 주문 |
| 손절, 하루 손실 한도 | 프로그램 (승인 없이) | 급락 때 사람의 답을 기다리면 늦음 |

**위험을 늘리는 일은 사람이 확인하고, 위험을 줄이는 일은 기계가 바로 합니다.** 매수는 사람이 승인하지 않으면 나가지 않으므로, 아무것도 하지 않는 쪽이 늘 안전한 쪽입니다.

매수 주문은 장 마감 뒤에 정해지고, 사람은 그 주문 목록 파일을 열어 값을 확인한 뒤 승인 상태를 고쳐 둡니다. 다음 날 개장 전까지만 하면 되고, 개장 때 주문이 자동으로 나갑니다. 시스템에 익숙해진 뒤에는 승인 상태를 고치지 않아도 프로그램이 매수를 모두 승인해 내보내는 **자동 방식**으로 바꿀 수 있습니다.

---

### 4. Part 4에서 만들 것

| 단계 | 하는 일 |
|---|---|
| 증권사 연결 | 모의투자 계좌 인증, 잔고와 현재가 조회 |
| 주문 목록 | 신호를 계좌의 실제 보유 수량과 비교해 낼 주문 정하기 |
| 승인 | 주문 목록을 보고 매수 주문을 승인하거나 거절 |
| 알림 | 프로그램이 나 없이 한 일(체결 결과, 손절 실행, 오류)을 이메일로 보고 |
| 주문 실행 | 매도와 승인된 매수를 증권사로 보내고 체결 확인 |
| 안전장치 | 장중 급락 때 묻지 않고 청산 |
| 장 마감 후 확인 | 오늘 체결 확인, 신호가 바뀌는 조건 미리 보기 |
| 자동 실행 | 위 단계를 시간표대로 실행 |

단계마다 프로그램을 하나씩 따로 만들고 따로 확인합니다. 프로그램 이름과 세부 내용은 만들어 가면서 정합니다.

## 미리 보기 — 오늘 신호에서 승인까지

아직 증권사를 연결하지 않았으니 실제 주문은 나가지 않습니다. 앞에서 만든 신호 스크립트를 오늘 날짜로 돌리고, 그 결과가 주문과 승인으로 어떻게 이어지는지 대화로 따라가 봅니다.

> 📁 **공유 파일**: 이 프롬프트는 앞에서 만든 `generate_signals.py`를 날짜 없이 실행합니다. 실행하면 오늘 기준 신호가 `signals_날짜.json`과 `signals.json`으로 저장되고, 미리 보기용 주문 목록이 `orders_preview.json`으로 저장됩니다. 미리 보기 파일은 뒤의 실습에서 쓰지 않습니다.

```prompt
[맥락] 작업 폴더의 'generate_signals.py'로 오늘 기준 매매 신호를 뽑고, 이 신호대로라면 다음 개장 때 어떤 주문이 나가는지, 그중 내가 승인해야 하는 것은 무엇인지 미리 따라가 보고 싶어. 아직 증권사 계좌는 연결하지 않았어.

[만들 것] 새 프로그램을 만들지 말고 아래를 차례로 해줘:
1. 'generate_signals.py'를 날짜 없이 실행해서 가장 최근 확정 종가 기준 신호를 만들고, 기준일, 국면, 전략별 [신호 / 조정 비중 / 목표 수량]을 표로 보여줘.
2. 계좌에 주식이 하나도 없다고 가정하고, 종목별 목표 수량을 다음 개장 때 낼 주문으로 바꿔 [매수·매도 / 종목 / 수량 / 예상 금액 / 이유 / 승인 상태] 표로 보여 주고, 같은 내용을 'orders_preview.json'으로 저장해줘. 승인 상태는 매도면 '자동', 매수면 '승인 대기'로 적어.
3. 나는 'orders_preview.json'을 직접 열어 값을 확인하고, 매수 주문의 승인 상태를 '승인'이나 '거절'로 고쳐 저장할 거야. 내가 고쳤다고 말하면 파일을 다시 읽어 [다음 개장 때 나갈 주문]과 [나가지 않을 주문]을 나눠 보여줘. '승인 대기'로 남아 있는 매수는 나가지 않을 주문에 넣어.

[하지 말 것]
- 증권사 API를 호출하거나 주문을 보내지 마. 이번에는 흐름만 따라가 봐.
- 'generate_signals.py'와 입력값을 고치지 마.
- 'generate_signals.py'가 실행되며 스스로 저장하는 파일과 'orders_preview.json' 외에 다른 파일을 만들지 마.
- 승인 상태를 네가 고치지 마. 승인 상태는 내가 파일에서 직접 고친다.

[확인] 대화창에 오늘 신호 표와 주문 표가 나오고 'orders_preview.json'이 저장되었는지 확인해줘. 내가 파일을 고친 뒤에는 [나갈 주문 / 나가지 않을 주문] 표를 보여줘.
```

파일을 열어 매수 하나는 '승인'으로 고치고, 하나는 '승인 대기' 그대로 두어 보세요. 고치지 않은 매수는 나가지 않는다는 점이 이 시스템의 기본값입니다.
