# 전체 구조 이해하기: 매매 신호부터 승인과 주문까지

## 이번 클립에서 만들 것

이번 클립에서는 새 프로그램을 만들지 않습니다. Part 4에서 만들 시스템이 **장 마감 후 신호 계산 → 주문 목록 → 알림 → 승인 → 다음 날 개장 주문 → 장중 안전장치** 순서로 어떻게 이어지는지 지도를 먼저 보고, 앞에서 만든 신호 스크립트를 오늘 날짜로 한 번 돌려 **신호에서 승인까지**를 미리 따라가 봅니다.

> 💡 지금 증권사 계좌를 켤 필요는 없습니다. 증권사 연결은 다음 클립에서 합니다.

- 하루가 어떤 순서로 돌아가는가
- 사람이 하는 일과 프로그램이 하는 일의 구분
- 오늘 신호를 뽑아 승인까지 미리 따라가 보기

---

## 이론 핵심

### 1. 매일 확인하지만, 주문은 가끔 나갑니다

우리가 운용하는 세 전략(추세추종, 듀얼 모멘텀, 페어 스위칭)은 모두 **장 마감 뒤 그날 종가로 판정이 끝납니다.** 그래서 다음 날 장이 열리기 전에 무엇을 몇 주 사고팔지가 모두 정해지고, 신호가 실제로 바뀌는 날은 드뭅니다.

| 주기 | 무엇 | 실제로 바뀌는 빈도 |
|---|---|---|
| 월말 | 시장 국면 판정 | 1년에 몇 번 |
| 매일 (장 마감 후) | 신호 계산, 다음 날 낼 주문 목록 만들기 | 주문이 생기는 날은 한 달에 몇 번 |
| 장중 | 급락을 막는 안전장치 | 기준에 닿는 날만 |

주문이 나갈 날이 언제일지는 미리 알 수 없습니다. 그래서 **확인은 프로그램이 매일** 하고, 사람은 주문이 생긴 날에만 관여합니다.

---

### 2. 하루의 흐름

```text
[장 마감 후]  프로그램을 다시 돌림
  ① 신호 계산            오늘 종가로 세 전략의 신호와 목표 수량을 계산
  ② 주문 목록 만들기      목표 수량을 계좌의 실제 보유 수량과 비교해, 내일 낼 주문을 정함
  ③ 일지                 오늘 주문이 제대로 체결됐는지 확인하고, 신호가 바뀌는 조건을 정리
  ④ 알림                 내일 낼 주문이 있으면 이메일로 알림 (없으면 보내지 않음)
        ↓
[저녁 ~ 다음 날 개장 전]
  ⑤ 승인                 사람이 ②의 주문 목록을 보고 매수 주문을 승인하거나 거절
        ↓
[개장]
  ⑥ 주문                 매도 주문과 승인된 매수 주문을 증권사로 보냄
        ↓
[장중]
  ⑦ 안전장치             손절 기준에 닿으면 사람에게 묻지 않고 청산
```

내일 낼 주문은 ②에서 정해집니다. ③과 ④는 그 결과를 정리하고 알려 줄 뿐, 주문을 새로 만들지 않습니다. 주문 목록이 비어 있는 날은 ④, ⑤, ⑥에서 아무 일도 일어나지 않습니다. 대부분의 날이 그렇습니다.

---

### 3. 사람이 하는 일과 프로그램이 하는 일

| 일 | 누가 | 이유 |
|---|---|---|
| 신호 계산, 주문 목록 만들기 | 프로그램 | 규칙대로 계산하면 되는 일 |
| **매수 주문** | **사람이 승인한 뒤** 프로그램이 주문 | 위험을 늘리는 주문. 승인이 없으면 그날은 사지 않음 |
| 매도 주문 | 프로그램 (승인 없이) | 위험을 줄이는 주문 |
| 손절, 하루 손실 한도 | 프로그램 (승인 없이) | 급락 때 사람의 답을 기다리면 늦음 |

**위험을 늘리는 일은 사람이 확인하고, 위험을 줄이는 일은 기계가 바로 합니다.** 매수 신호에 응답하지 않으면 거래가 일어나지 않으므로, 응답하지 않는 쪽이 늘 안전한 쪽입니다.

매수 주문은 전날 저녁에 정해지므로 승인에 쫓길 일이 없습니다. 개장 전까지만 하면 됩니다. 시스템에 익숙해진 뒤에는 매수도 묻지 않고 실행하는 **자동 방식**으로 바꿀 수 있습니다.

---

### 4. Part 4에서 만들 것

| 단계 | 하는 일 |
|---|---|
| 증권사 연결 | 모의투자 계좌 인증, 잔고와 현재가 조회 |
| 주문 목록 | 신호를 계좌의 실제 보유 수량과 비교해 낼 주문 정하기 |
| 알림과 승인 | 주문이 생기면 알리고, 매수는 사람이 승인하거나 거절 |
| 주문 실행 | 매도와 승인된 매수를 증권사로 보내고 체결 확인 |
| 안전장치 | 장중 급락 때 묻지 않고 청산 |
| 장 마감 후 확인 | 오늘 체결 확인, 신호가 바뀌는 조건 미리 보기 |
| 자동 실행 | 위 단계를 시간표대로 실행 |

단계마다 프로그램을 하나씩 따로 만들고 따로 확인합니다. 프로그램 이름과 세부 내용은 만들어 가면서 정합니다.

## 미리 보기 — 오늘 신호에서 승인까지

아직 증권사를 연결하지 않았으니 실제 주문은 나가지 않습니다. 앞에서 만든 신호 스크립트를 오늘 날짜로 돌리고, 그 결과가 주문과 승인으로 어떻게 이어지는지 대화로 따라가 봅니다.

> 📁 **공유 파일**: 이 프롬프트는 앞에서 만든 `generate_signals.py`를 날짜 없이 실행합니다. 실행하면 오늘 기준 신호가 `signals_날짜.json`과 `signals.json`으로 저장됩니다.

```prompt
[맥락] 작업 폴더의 'generate_signals.py'로 오늘 기준 매매 신호를 뽑고, 이 신호대로라면 다음 개장 때 어떤 주문이 나가는지, 그중 내가 승인해야 하는 것은 무엇인지 미리 따라가 보고 싶어. 아직 증권사 계좌는 연결하지 않았어.

[만들 것] 새 파일을 만들지 말고 아래를 차례로 해줘:
1. 'generate_signals.py'를 날짜 없이 실행해서 가장 최근 확정 종가 기준 신호를 만들고, 기준일, 국면, 전략별 [신호 / 조정 비중 / 목표 수량]을 표로 보여줘.
2. 계좌에 주식이 하나도 없다고 가정하고, 종목별 목표 수량을 다음 개장 때 낼 주문으로 바꿔 [매수·매도 / 종목 / 수량 / 예상 금액 / 이유 / 승인이 필요한가] 표로 보여줘. 매수는 승인이 필요하고, 매도는 필요 없어.
3. 매수 주문마다 승인할지 거절할지 나에게 물어봐. 내 답을 받은 뒤에 [다음 개장 때 나갈 주문]과 [나가지 않을 주문]을 나눠 다시 보여줘. 내가 답하지 않은 주문은 나가지 않을 주문에 넣어.

[하지 말 것]
- 증권사 API를 호출하거나 주문을 보내지 마. 이번에는 흐름만 따라가 봐.
- 'generate_signals.py'와 입력값을 고치지 마.
- 주문 목록이나 승인 결과를 파일로 저장하지 마. 대화창에 표로만 보여줘.
- 내가 답하기 전에 승인된 것으로 넘기지 마.

[확인] 대화창에 오늘 신호 표, 주문 표, 그리고 내 답을 반영한 [나갈 주문 / 나가지 않을 주문] 표가 차례로 나왔는지 확인해줘.
```

한 번은 승인으로, 한 번은 거절이나 무응답으로 답해 보세요. 답하지 않은 매수는 나가지 않는다는 점이 이 시스템의 기본값입니다.
