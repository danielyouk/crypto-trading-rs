이론 핵심

1. 100% 자동수익의 환상과 복잡계 시장의 현실

시중의 수많은 강의나 광고는 "잠자는 동안 돈을 벌어다 주는 100% 전자동 매매 봇"을 약속합니다. 하지만 현실의 금융시장에서 그런 블랙박스 시스템은 반드시 실패합니다. 그 이유는 기계공학적 시스템과 금융시장의 본질적인 차이에 있습니다.

닫힌계 (Closed System: 기계 / 공학)
• 물리 법칙이 시간에 따라 변하지 않고 고정됨
• 데이터 수집 ──> 수학 모델 수립
• 100% 예측 및 완전 자동 제어 가능
복잡계 (Complex Adaptive System: 금융시장)
• 참여자들의 심리와 상호작용으로 시장 규칙이 끊임없이 진화
• 과거 최적 모델의 필연적 붕괴 (과최적화 리스크)
• 시장 적응과 인간의 유연한 개입 필수
  • 과거 데이터 과최적화(Overfitting)의 함정: 과거 30년 백테스트에서 완벽해 보이는 파라미터를 찾아내도, 시장 국면(상승장, 횡보장, 급락장)이 바뀌면 가장 먼저 계좌를 파괴합니다.
  • 버튼을 끄는 것은 결국 사람이다: 아무리 정교한 알고리즘도 -30%, -50%의 최대 낙폭(MDD) 구간을 마주하면 사람이 공포를 이기지 못하고 시스템을 강제로 꺼버리게 됩니다.
  • 인간 개입형 하이브리드 모델의 필연성: 시스템은 지치지 않고 데이터를 감시하고 시그널을 계산하여 보고하고, 최종 진입(매수)과 전략 선택은 사람이 판단하고 승인하며, 돌발 급락에 대한 손절은 사전에 정해진 규칙이 즉시 실행해야 합니다.
역할 구분 주체 구체적 담당 업무
데이터 감시 & 시그널 제안 시스템 (AI Agent) 장중 실시간 시세 수신, 4대 전략 조건 계산, 매매 후보 및 근거 보고서 생성
최종 매수 승인 & 전략 전환 사람 (나 / 감독관) 텔레그램 승인/거절 버튼 클릭, 시장 국면 판단, 전략 파라미터 조정
비상 리스크 제어 (손절/정지) 엄격한 하드웨어 규칙 알림 무응답 시 자동 손절, 일일 주문 한도 초과 시 긴급 정지(Kill Switch)

2. 우리가 완성할 시스템의 5대 핵심 서브시스템

5개 파트에 걸쳐 여러분 컴퓨터에 구축될 전체 시스템은 다음과 같이 유기적으로 연결된 5개의 독립 모듈로 구성됩니다.

① 데이터 & 시그널 엔진
FinanceDataReader 및 KIS API로 실시간 주가를 수신하고, 4대 전략 조건 충족 시 매매 신호를 생성합니다. (Part 1~2)
② 워크포워드 검증 루프
실전처럼 시간 구간을 전진하며 과최적화를 걸러내고, 손실 발생 시 AI 운영 보고서로 개선안을 도출합니다. (Part 3)
③ 알림 & 대화형 승인 게이트
스마트폰 텔레그램 봇으로 진입 근거 리포트와 [승인] / [거절] 버튼을 발송하여 사람의 결정을 대기합니다. (Part 4)
④ 모의주문 체결 브리지
사람이 승인한 건에 한해서만 한국투자증권 모의계좌로 매수 주문을 전송하고 체결 내역을 기록합니다. (Part 4)
⑤ 비상 안전 & 일일 점검 회고
알림 무응답 시 자동 손절 규칙, 주문 한도 Kill Switch를 작동시키며, 장 마감 후 일일 진단서를 발행합니다. (Part 4~5)

3. 코더에서 '시스템 아키텍트(감독관)'로의 사고 전환

기존의 프로그래밍 강의는 문법, 변수, 반복문, API 통신 에러를 잡다가 지쳐서 정작 중요한 '투자 전략'은 만들어보지도 못하고 포기하게 만듭니다. 이 강의는 완전한 제로코드 패러다임을 지향합니다.

과거의 방식 (Coder)
문법 암기 ──> 라이브러리 디버깅 ──> API 래퍼 수동 구현 ──> 문법 에러로 중도 포기
에이전트 시대의 방식 (Architect & Supervisor)
아이디어 구조화 ──> 결과 모습(목표) 선언 ──> 화면으로 시각적 확인 ──> 후속 개선 요청
  • 코드의 일치 여부가 아니라 화면의 일치 여부를 본다: Claude Code가 작성한 파이썬 코드가 강사의 코드와 글자 하나까지 같을 필요는 전혀 없습니다. 우리가 확인하는 것은 "차트가 제대로 그려졌는가?", "성과표의 수치가 논리적인가?", "텔레그램 메시지가 오는가?"입니다.
  • 생각 → 요청 → 확인 → 개선 루프: 1. 생각: 이 클립이 끝나면 내 모니터에 어떤 시각적 결과물(차트, 표, 메시지)이 떠 있어야 하는지 정의합니다. 2. 요청: 구현 절차가 아니라 '완성된 결과의 모습'이 담긴 목표 프롬프트를 에이전트에게 전달합니다. 3. 확인: AI에게 확인을 맡기지 않고, 사람이 직접 눈으로 화면과 숫자를 대조합니다. 4. 개선: 목표와 다른 부분이 있다면 그 부분만 콕 집어 후속 프롬프트로 수정합니다.

실습 및 확인 관전 포인트

이번 첫 클립은 시스템 전체가 동작하는 시뮬레이션 조감도(애니메이션 및 구조 다이어그램)를 관람하는 시간입니다. 화면을 보시면서 아래의 핵심 흐름 4가지를 눈여겨보세요.

  • 1. 신호 분리: 매매 시그널이 발생해도 즉시 주문이 나가지 않고 사람의 확인을 기다리는 대기 상태를 확인했다.
  • 2. 대화형 알림 구조: 텔레그램으로 종목명, 진입 사유, 목표가/손절가 리포트와 함께 [승인] / [거절] 인라인 버튼이 오는 방식을 확인했다.
  • 3. 사람의 개입: 사람이 [승인] 버튼을 눌렀을 때만 모의주문이 실행되는 승인 게이트웨이의 원리를 이해했다.
  • 4. 일일 회고: 하루 매매가 끝난 뒤 손익 원인을 분석해 다음 날 전략에 반영하는 일일 점검 흐름을 파악했다.

입문자가 가장 많이 묻는 질문 (FAQ)

Q1. 지금 바로 증권사 계좌나 텔레그램 봇을 만들어야 하나요?
아닙니다! 지금은 아무것도 준비할 필요가 없습니다. Part 1~3에서는 주식 데이터 불러오기와 알고리즘 백테스트에 집중합니다. 증권사 모의투자 계좌와 텔레그램 봇은 Part 4에서 강사와 함께 화면을 보며 클릭 몇 번으로 쉽게 만들게 됩니다.

Q2. 코딩이나 수학을 전혀 못하는데 정말 5개 파트를 다 만들 수 있나요?
네, 가능합니다. 우리가 할 일은 파이썬 코드를 한 줄씩 타이핑하는 것이 아니라, "무엇을 만들고 싶은지" 명확한 한국어로 목표를 제시하고 결과를 검증하는 것입니다. 에러 수정과 코드 구현은 Claude Code가 전담합니다.

Q3. AI에게 모든 매매를 100% 자동으로 맡기면 더 편하지 않나요?
편리함의 대가는 계좌의 파멸입니다. 시장은 끊임없이 규칙이 바뀌는 복잡계이며, 알고리즘이 예측하지 못한 블랙스완이 언제든 발생합니다. 시스템의 기계적인 계산력과 사람의 거시적 판단력이 결합된 하이브리드만이 장기적으로 살아남습니다.
