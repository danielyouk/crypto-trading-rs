이론 핵심

승인 없이는 주문 없다

이 시스템에서 매수 주문이 나가는 경로는 단 하나, 사람이 승인 버튼을 누른 경우뿐입니다. 시그널 엔진도, AI도, 스케줄러도 매수 주문을 직접 낼 수 없습니다. 이 원칙을 코드 구조로 강제해 두면, 나중에 어떤 기능을 추가해도 "모르는 사이에 매수가 나가는" 사고를 원천 차단할 수 있습니다.

주문에 필요한 세 가지 결정

승인 버튼을 눌렀을 때 시스템이 주문을 접수하려면 세 가지가 정해져 있어야 합니다.

  1. 수량 — 미리 정한 금액(예: 신호당 100만 원)을 현재가로 나눠 계산
  2. 가격 방식 — 시장가(즉시 체결) 또는 지정가(내가 정한 가격)
  3. 유효 시간 — 승인이 너무 늦으면 신호 가격과 현재가가 벌어지므로, 오래된 신호는 만료 처리

이 결정들은 승인 순간에 고민하는 것이 아니라 미리 규칙으로 정해 둡니다. 사람은 "이 신호를 믿을까"만 판단합니다.

접수와 체결은 다르다

주문을 보냈다고 끝이 아닙니다. 접수(주문이 들어감)와 체결(실제로 거래됨)은 별개이며, 체결 결과를 다시 조회해서 텔레그램으로 회신받아야 한 사이클이 닫힙니다. "승인 → 접수 → 체결 확인"까지가 이번 실습의 완성 기준입니다.

실습 16 — 승인하면 모의주문이 나가게 연결하기

AI 프롬프트 템플릿 (목표 중심) 
텔레그램에서 [승인] 버튼을 누르면, 해당 신호의 종목을 모의투자 계좌에
시장가로 주문하도록 연결해줘. 주문 금액은 신호당 100만 원 기준으로 수량을 계산해.
주문이 체결되면 "체결 완료: 종목명, 수량, 체결가"가 텔레그램으로 회신되어야 하고,
[거절]을 누르거나 아무것도 누르지 않으면 주문이 나가면 안 돼.
테스트 신호로 승인·거절 두 경우를 모두 보여줘.

내 눈으로 확인할 체크리스트

  • 승인을 누르면 텔레그램에 "체결 완료: 종목명·수량·체결가" 회신이 온다
  • 한국투자증권 모의투자 화면(HTS/MTS)에서 같은 체결 내역이 보인다
  • 거절한 신호는 계좌 체결 내역에 아무것도 남지 않았다
  • 아무 버튼도 누르지 않은 신호도 주문이 나가지 않았다
  • 주문·체결 내역이 로그 파일에도 기록되었다

자주 발생하는 문제

강사와 여러분의 주문 코드 구조는 다를 수 있습니다. 모의투자 화면의 체결 내역과 텔레그램 회신이 일치하는지가 판정 기준입니다.

  • 장 시간 밖 주문: 모의투자도 장 운영 시간에만 체결됩니다. 장 밖에는 주문 거부가 정상입니다.
  • 모의투자 주문 코드 구분: 모의투자와 실전은 주문 요청의 거래 코드가 다릅니다. 실전용 코드를 쓰면 거부됩니다.
  • 토큰 만료 후 주문 실패: 승인 시점에 토큰이 만료되어 있으면 주문이 실패합니다.
AI 프롬프트 템플릿 (목표 중심) 
승인을 눌렀는데 주문이 거부됐어. 증권사가 돌려준 오류 메시지를 그대로 보여주고,
모의투자용 주문 설정이 맞는지 확인해서 고쳐줘. 고친 뒤 다시 승인해서
체결 완료 회신이 오는 것까지 보여줘.
AI 프롬프트 템플릿 (목표 중심) 
체결은 됐는데 텔레그램 회신이 안 와. 체결 결과를 조회하는 부분이 실행되는지
확인하고, 체결 후 1분 안에 회신 메시지가 오게 해줘.
