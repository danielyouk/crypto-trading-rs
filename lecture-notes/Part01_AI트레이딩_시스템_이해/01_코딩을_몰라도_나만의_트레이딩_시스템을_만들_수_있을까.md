## 이론 핵심



### 1. 단순계 vs 복잡계 — 엔지니어링과 AI 현장에서 겪은 진실

시중의 수많은 강의나 광고는 "잠자는 동안 돈을 벌어다 주는 100% 전자동 매매 봇"을 약속합니다. 하지만 현실의 금융시장에서 그런 블랙박스 시스템은 반드시 실패합니다. 그 이유는 **'단순계'와 '복잡계'의 본질적인 차이**에 있습니다.

#### 강사의 경험에서 배우는 시스템의 현실

- **기계공학의 반전**: 학부 시절 이론으로 배울 때는 공식대로 제어 가능한 시스템 같았지만, 실제 산업 현장에서 기계공학 제품을 개발해 보니 예상치 못한 수많은 환경 변수, 공차, 간섭이 발생하는 **전형적인 복잡계**였습니다.
- **초기 코딩과 데이터 분석의 편안함**: 오히려 초기의 단순 코딩이나 데이터 분석은 입력값이 주어지면 정해진 로직대로 결과가 나오는 **단순계(Simple System)**처럼 느껴져 매우 편하고 안정적이었습니다.
- **80명 규모 AI 에이전트 프로젝트의 교훈**: 최근 약 80명의 인원을 이끌며 대규모 AI 에이전트 프로젝트를 리딩하면서, 현대의 소프트웨어 개발 역시 수많은 에이전트 간 상호작용과 돌발 변수가 얽힌 **거대한 복잡계**로 회귀했음을 절감하고 있습니다. AI로 모든 것을 전자동화하는 것은 결코 단순하지 않습니다.
- **최신 AI 벤치마킹 프로젝트에서 확인한 사실**: 정형화된 장표 분석이나 문서 요약 같은 단순계 작업은 이미 AI가 전문가보다 뛰어난 성과를 냅니다. 하지만 **복잡계로 들어갈수록 AI 단독으로 인간을 대체하는 것은 불가능**에 가깝습니다.

### 2. 금융시장 — 복잡계 중의 복잡계 (The Ultimate Complex System)

금융시장은 지구상에 존재하는 가장 극단적인 복잡계입니다. 금융시장이 단순한 수학 공식이나 100% 자동 봇으로 정복될 수 없는 5가지 이유가 있습니다.

1. **비선형적 인과관계 (Non-linear Causality)**: 원인(A)이 발생했을 때 결과(B)가 정비례하게 나타나지 않으며, 작은 나비의 날갯짓이 거대한 폭락으로 이어집니다.
2. **다중 인과관계의 얽힘 (Intertwined Networks)**: 금리, 환율, 기업 실적, 기관 수급, 투자자 심리, 알고리즘 매매가 서로 얽혀 상호 피드백을 주고받습니다.
3. **인과관계 규칙 자체의 진화 (Non-stationarity)**: 시장 참여자들이 과거의 성공 패턴을 학습하는 순간, 시장의 규칙 자체가 변해버려 **과거 최적 모델이 필연적으로 붕괴(과최적화의 함정)**합니다.
4. **보이지 않는 숨겨진 인과관계 (Latent Factors)**: 표면적인 캔들스틱 차트 뒤에 숨겨진 유동성 변화와 매크로 역학이 가격을 움직입니다.
5. **예외 사항과 블랙스완의 지속적 발생 (Continuous Exceptions)**: 과거 데이터에 한 번도 없었던 돌발 사태가 일상적으로 발생합니다.

> **💡 핵심 결론: 2-Tier 하이브리드(Weekly Governance + Daily Autonomous Execution) 모델의 필연성**  
> 24시간 데이터 감시와 정형화된 수치 계산은 **AI 시스템**에 맡기고, 거시적 시장 국면 판단과 주간 매매 정책(`weekly_policy.json`) 승인은 **사람(나 / 최고투자책임자 CIO)**이 결정하며, 장중 급변에 대한 손절은 **코드 레벨의 무인 하드 가드레일**이 0.1초 만에 즉각 집행해야만 살아남을 수 있습니다.

### 4. 코더에서 '시스템 아키텍트(감독관)'로의 사고 전환

기존의 프로그래밍 강의는 문법, 변수, 반복문, API 통신 에러를 잡다가 지쳐서 정작 중요한 '투자 전략'은 만들어보지도 못하고 포기하게 만듭니다. 이 강의는 **완전한 제로코드 패러다임**을 지향합니다.

<div class="compare-box">
  <div class="compare-card bad">
    <div class="tag">과거의 방식 (Coder)</div>
    <div class="steps">
      문법 암기 ──> 라이브러리 디버깅 ──> API 래퍼 수동 구현 ──> <strong>문법 에러로 중도 포기</strong>
    </div>
  </div>
  <div class="compare-card good">
    <div class="tag">에이전트 시대의 방식 (Architect & Supervisor)</div>
    <div class="steps">
      아이디어 구조화 ──> 결과 모습(목표) 선언 ──> 화면으로 시각적 확인 ──> <strong>후속 개선 요청</strong>
    </div>
  </div>
</div>

- **코드의 일치 여부가 아니라 화면의 일치 여부를 본다**: Claude Code가 작성한 파이썬 코드가 강사의 코드와 글자 하나까지 같을 필요는 전혀 없습니다. 우리가 확인하는 것은 **"차트가 제대로 그려졌는가?", "성과표의 수치가 논리적인가?", "모의투자 체결 내역이 생성되는가?"**입니다.
- **생각 → 요청 → 확인 → 개선 루프**:
  1. **생각**: 이 클립이 끝나면 내 모니터에 어떤 시각적 결과물(차트, 표, 메시지)이 떠 있어야 하는지 정의합니다.
  2. **요청**: 구현 절차가 아니라 **'완성된 결과의 모습'**이 담긴 목표 프롬프트를 에이전트에게 전달합니다.
  3. **확인**: AI에게 확인을 맡기지 않고, 사람이 직접 눈으로 화면과 숫자를 대조합니다.
  4. **개선**: 목표와 다른 부분이 있다면 그 부분만 콕 집어 후속 프롬프트로 수정합니다.

## 입문자가 가장 많이 묻는 질문 (FAQ)

**Q1. 지금 바로 증권사 계좌나 API 키를 만들어야 하나요?**  
아닙니다! 지금은 아무것도 준비할 필요가 없습니다. Part 1~3에서는 주식 데이터 불러오기와 알고리즘 백테스트에 집중합니다. 증권사 모의투자 계좌는 Part 4에서 강사와 함께 화면을 보며 클릭 몇 번으로 쉽게 만들게 됩니다.

**Q2. 코딩이나 수학을 전혀 못하는데 정말 5개 파트를 다 만들 수 있나요?**  
네, 가능합니다. 우리가 할 일은 파이썬 코드를 한 줄씩 타이핑하는 것이 아니라, "무엇을 만들고 싶은지" 명확한 한국어로 목표를 제시하고 결과를 검증하는 것입니다. 에러 수정과 코드 구현은 Claude Code가 전담합니다.

**Q3. AI에게 모든 매매를 100% 자동으로 맡기면 더 편하지 않나요?**
