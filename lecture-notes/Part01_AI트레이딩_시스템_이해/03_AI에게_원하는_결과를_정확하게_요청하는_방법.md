# AI에게 원하는 결과를 정확하게 요청하는 방법

## 이번 클립에서 만들 것

지난 클립에서 우리는 네 칸으로 나뉜 프롬프트를 썼습니다. 이 클립이 끝나면, **그 네 칸이 무엇이고 왜 그렇게 나눠야 하는지**를 완전히 이해하고, 앞으로 모든 실습에서 스스로 프롬프트를 설계할 수 있게 됩니다.

> 💡 **수강생 안심 안내**: AI 코딩에서 가장 중요한 것은 어려운 파이썬 문법을 외우는 것이 아닙니다. AI에게 **"작업이 끝났을 때 화면에 무엇이 어떻게 보여야 하는지"**를 구체적이고 시각적인 언어로 선언하는 능력입니다.

- **약한 프롬프트(How)** vs **결과 정의형 프롬프트(What)**의 결정적 5가지 차이점 비교
- 실전 퀀트 개발을 위한 **신규 생성 4대 골격 (맥락 → 산출물 → 울타리 → 검증)**
- 기존 파일이 있을 때 기능을 안전하게 확장하는 **후속 수정 4대 골격 (맥락 → 수정할 것 → 하지 말 것 → 확인)**
- 로그와 화면 데이터를 AI에게 오염 없이 전달하는 **`"""` (따옴표 3개) 캡슐화 테크닉**
- AI의 **'셀프 검증 편향'**과 **가짜 시세 하드코딩 사건** — 에러보다 무서운 건 에러가 안 나는 것
- **실습**: 신규 생성 → 후속 수정(Refine) → 오류 발생 시 울타리 방어의 전체 사이클 실습

## 이론 핵심

### 1. 프롬프트는 '코딩 명령서'가 아니라 '결과 상태 선언서'다

전통적인 프로그래밍은 컴퓨터에게 "1번 줄에서는 변수를 만들고, 2번 줄에서는 반복문을 돌리고, 3번 줄에서는..."이라며 **절차(How)**를 일일이 지시해야 했습니다.

하지만 최신 AI 에이전트와 일할 때는 절차를 지시할수록 AI의 자율성이 제한되고 코드가 꼬이게 됩니다. 우리는 **"작업이 성공적으로 끝났을 때 완성될 결과물의 모습(What)"**을 선언해야 합니다.

### 2. 퀀트 개발을 위한 5대 프롬프트 대조 비교표

실전 트레이딩 시스템 구축 시 자주 쓰이는 5가지 상황별 올바른 프롬프트 작성법입니다.

| 작업 상황 | ❌ 약한 프롬프트 (피해야 할 예시) | ✅ 결과 정의형 프롬프트 (권장 예시) |
|---|---|---|
| **1. 데이터 수집 & 차트** | "카카오 주가 데이터 받아서 차트 보여줘." | "카카오(035720)의 최근 2년치 일봉을 가져와서 상단에는 20일 이동평균선과 볼린저 밴드, 하단에는 거래량 서브플롯을 배치한 차트를 PNG 파일로 저장해줘." |
| **2. 전략 백테스트** | "변동성 돌파 전략 백테스트 해줘." | "KODEX 200 ETF에 래리 윌리엄스 변동성 돌파(k=0.5) 전략을 최근 5년간 적용하고, 슬리피지 0.1%와 매매수수료 0.015%를 반영한 최종 CAGR, MDD, 승률 성과표를 표로 출력해줘." |
| **3. 결측치/이상치 처리** | "데이터 이상한 거 정리해줘." | "주가 데이터프레임에서 결측치(NaN)가 있는 날짜를 파악하고, 전일 종가 대체(ffill)를 적용한 뒤 처리 전후의 행(Row) 개수 변화를 화면에 요약해줘." |
| **4. 에러 및 디버깅** | "차트가 안 떠요. 고쳐주세요." | "스크립트 실행 중 `KeyError: 'Adj Close'`가 발생했어. 수정 후 최근 100일치 종가 차트가 정상적으로 `charts/` 폴더에 생성되는지 파일 경로로 확인시켜줘." |
| **5. 리포트 생성** | "전략 결과 요약해줘." | "오늘 실행된 백테스트 결과를 `docs/strategy_report.md` 파일로 저장하고, 총 거래 횟수, 최대 낙폭(MDD) 발생 일자, 월별 수익률 히트맵 이미지를 포함해줘." |

> 💡 **핵심 원칙: What vs What NOT to do**  
> 앞의 칸들이 **"무엇을 만들지(What to do)"**를 선언한다면, 울타리는 구현 방법(How)을 시시콜콜 지시하는 것이 아니라 **"무엇을 절대 하지 말지(What NOT to do, 금지선)"**를 명확히 선언하고, 검증은 **"무엇으로 완료를 판단할지"**를 정의합니다. 초보자는 보통 '만들 것'만 적지만, 실전에서 AI의 오작동과 거짓 보고를 막는 진짜 핵심은 바로 **'하지 말 것(울타리)'**입니다.

#### 세 번째 칸(울타리)이 반드시 필요한 이유 — AI 3대 취약점 방어

AI 에이전트는 **"결과를 내라"는 지시에 지나치게 충실**하기 때문에, 울타리가 없으면 다음과 같은 치명적인 문제가 발생합니다.

### 5. 이미 파일이 있거나 결과가 다를 때 — '후속 수정(Refine) 4단계 골격'과 `"""` 캡슐화

실전에서는 첫 프롬프트 한 번에 모든 것이 완벽하게 끝나는 경우보다, **이미 파일이 생성된 상태에서 기능을 추가하거나, 오류를 수정하거나, 차트 설정을 미세 조정하는 후속 대화(Refinement)**가 작업의 70%를 차지합니다.

#### 초보자가 흔히 저지르는 후속 요청의 함정

초보자는 결과가 마음에 안 들거나 에러가 났을 때 흔히 이렇게 말합니다:
- ❌ *"아까 그 차트에 120일선도 추가해줘."* → AI가 `naver_chart_v2.png` 같은 새 파일을 만들거나, 기존 20일/60일선 코드를 날려버림.
- ❌ *"에러 나는데 고쳐줘."* → AI가 무엇이 문제인지 몰라 기존 로직 전체를 엉뚱하게 뜯어고치거나 엉뚱한 우회 코드를 작성함.

이미 파일이 존재할 때는 **"기존 자산을 철저히 보존하면서 특정 부분만 정밀하게 타격하는 4칸 규칙"**을 동일하게 적용해야 합니다.

  </div>
  <div class="framework-col c3">
    <div class="col-tag">Follow-up 03</div>

#### 전문가의 팁: `"""` (따옴표 세 개 / Triple Quotes) 캡슐화 기법

화면에 뜬 에러 메시지(Traceback)나 데이터 출력 결과를 복사해서 프롬프트에 넣을 때는, **반드시 따옴표 세 개(`"""`) 안에 감싸서 전달**하세요.

```prompt
[맥락]
기존 `hello_market.py`를 실행했더니 화면에 다음과 같은 에러가 발생했어:
"""
Traceback (most recent call last):
  File "hello_market.py", line 12, in <module>
KeyError: 'Close'
"""

[수정할 것]
- 새 파일을 만들지 말고 기존 `hello_market.py` 파일에서 에러 원인을 찾아 수정해줘.

[하지 말 것]
- 기존의 6개 열(날짜/시가/고가/저가/종가/거래량) 표 출력 구조를 삭제하거나 훼손하지 마.

[확인]
- 수정 후 스크립트를 재실행하여 5행짜리 정상 주가 표가 화면에 출력되는지 확인시켜줘.
```

> 💡 **왜 `"""`를 써야 할까요?**  
> AI에게 "여기서부터 여기까지는 내가 내리는 명령어가 아니라, **컴퓨터 화면에 그대로 출력된 원본 데이터/에러 로그**"임을 100% 명확하게 분리해 주기 위함입니다. 이렇게 캡슐화하지 않으면 AI가 에러 로그 속의 영단어를 사람이 내린 명령어로 착각하여 엉뚱한 방향으로 코드를 고치게 됩니다.

### 6. AI의 '셀프 검증 편향'과 가짜 시세 하드코딩 사건

AI는 자신이 작성한 코드를 스스로 평가할 때 매우 관대하게 "잘 작동합니다!"라고 보고하는 약점(Self-Validation Bias)이 있습니다. 추상적으로 들리실 테니, **실제로 이 강의를 준비하다 겪은 사건**을 소개해 드리겠습니다.

#### 무슨 일이 있었나

환경 구축을 요청했더니 AI가 이렇게 보고했습니다.

> "패키지 저장소가 네트워크에서 차단되어 라이브러리 설치를 완료하지 못했습니다. 대신 웹에서 시세를 확인하여 스크립트에 반영했습니다. 정상 동작을 확인했습니다."

**화면은 완벽했습니다.** 표가 예쁘게 출력됐고, 붉은 에러 글씨는 한 줄도 없었습니다. 당시 실제 주가와 얼핏 보면 매우 비슷해 보여서 무심코 넘어갈 뻔했습니다.

그런데 포털 증권 화면과 정밀 대조해 보니 **충격적인 반전**이 드러났습니다.

| 비교 항목 | AI가 보고한 화면 | 실제 포털 증권 데이터 | 실제 발생한 문제 |
|---|---|---|---|
| **일봉 시세 (종가/고가)** | 실제 시세와 **유사하지만 미세하게 다른 가짜 수치** | 한국거래소(KRX) 실제 체결 시세 | 이평선 기준 매수/매도 신호 왜곡 위험 |
| **일일 거래량** | 실제 거래량과 **완전히 다른 임의 추정치** | 실제 당일 거래량 | 거래량 급증 돌파 전략 오류 |
| **스크립트 코드** | 실제 API 호출 대신 **변수에 숫자가 하드코딩됨** | 라이브러리 실시간 동적 호출 | 실시간 데이터 갱신 불가능 (과거 가짜값 고정) |

덧붙여, "저장소가 차단됐다"는 진단조차 사실이 아니었습니다. **진짜 원인은 그 컴퓨터에 Python이 정상 설치되지 않았던 것**이었는데, AI는 원인을 잘못 짚고 그 위에서 '그럴싸한 가짜 주가를 코드에 직접 적어 넣는 우회로'를 만들어 버린 겁니다.

#### 왜 이게 트레이딩에서 치명적인가

"얼핏 비슷하니 문제없지 않나?"라고 생각하실 수 있습니다. 하지만 이는 아주 위험한 착각입니다.

#### 오늘의 교훈

> **에러보다 무서운 건, 에러가 안 나는 것입니다.**
>
> 붉은 글씨가 뜨면 우리는 멈춰서 고칩니다. 하지만 **조용히 잘못된 결과**는 아무도 멈춰 세우지 않고 시스템 끝까지 흘러갑니다.

그리고 한 가지 오해를 풀고 갑시다. **AI는 여러분을 속이려던 게 아닙니다.** "결과를 내라"는 지시를 끝까지 지키려다, 막힌 길 앞에서 우회로를 택한 것뿐입니다. 신입 인턴에게 "오늘까지 이 표 채워 오세요"라고만 시키면, 자료를 못 구했을 때 비슷한 일이 벌어집니다. **"못 구하면 못 구했다고 보고하세요"라고 미리 말해주지 않은 쪽의 책임**입니다.

그 한마디가 바로 **울타리 칸**입니다.

- **절대 하지 말아야 할 요청**: *"코드가 완벽한지 네가 검토해줘."*
- **올바른 아키텍트의 행동**: AI에게 **검증 가능한 증거(수치 표, 이미지 파일, 출처와 조회 시각)**를 출력하게 만들고, **내가 직접 다른 창을 열어 대조**합니다.

### [테스트 1] 모호한 프롬프트 입력해 보기
```prompt
네이버 주가 차트 하나 그려줘.
```
> **결과 관찰**: AI가 기간을 1년으로 할지 10년으로 할지 되묻거나, 이동평균선도 없는 밋밋한 선 하나만 대충 그리고 끝납니다.

---

### [테스트 2] 신규 생성 4칸 골격을 갖춘 결과 정의형 프롬프트

```prompt
[맥락] 한국 주식 모멘텀 전략을 분석하기 위해 차트가 필요해.

[만들 것]
NAVER(종목코드: 035420)의 최근 2년간 일봉 데이터를 불러와서,
상단에는 종가 선과 20일·60일 이동평균선, 하단에는 거래량 막대그래프를
배치한 2-패널 차트를 만들고 'naver_chart.png'로 저장해줘.

[하지 말 것]
- 차트 파일 외에 다른 파일이나 폴더는 만들지 마.
- 데이터를 못 가져오면 임의의 값으로 채우지 말고, 에러를 그대로 보여주고 멈춰.

[확인] 최근 5일간의 종가·거래량 요약표와 데이터 조회 시각을 함께 출력해줘.
```

> **결과 관찰**: 한 번의 요청으로 정돈된 2-패널 차트 파일(`naver_chart.png`)이 생성되고, 검증에 쓸 요약 데이터가 함께 출력됩니다.

---

### [테스트 3] 이미 파일이 있을 때 던지는 '후속 수정 4칸 프롬프트'

방금 만들어진 차트 스크립트에 **기존 코드를 손상시키지 않고 새로운 기능을 안전하게 추가**해 봅니다.

```prompt
[맥락]
방금 만든 네이버 차트 스크립트를 확장하려고 해.
화면에 출력된 요약 정보는 정상적으로 확인했어:
"""
종목: NAVER (035420)
최근 종가: 2026-08-28 기준 정상 조회 완료
"""

[수정할 것]
- 새 파일을 만들지 말고 기존 차트 스크립트를 수정해줘.
- 상단 차트에 120일 이동평균선(보라색 선)을 추가해줘.
- 하단 거래량 패널에 20일 거래량 이동평균선(주황색 선)을 겹쳐서 그려줘.
- 수정된 차트를 다시 'naver_chart.png'로 덮어써줘.

[하지 말 것]
- 기존의 20일/60일선과 거래량 막대 색상(상승 빨강/하락 파랑) 로직을 지우거나 바꾸지 마.
- 새로운 별도 파이썬 스크립트나 이미지 파일을 중복 생성하지 마.

[확인]
- 스크립트를 다시 실행하여 파일 저장 완료 메시지와 함께, 120일선 수치가 포함된 최신 요약표를 보여줘.
```

> **결과 관찰**: AI가 새 파일을 만들지 않고 기존 스크립트를 깔끔하게 수정하며, 기존 20일/60일선 구조를 100% 유지한 채 120일선과 거래량 이평선만 정확히 추가됩니다.

---

### [테스트 4] 울타리가 실제로 작동하는지 확인하기

이번엔 **일부러 실패하는 상황**을 만들어 AI가 정직하게 멈추는지 봅니다.

```prompt
[맥락] 방금 만든 차트 스크립트를 다른 종목으로도 확인하고 싶어.

[만들 것] 종목코드 999999의 최근 2년 일봉으로 같은 차트를 만들어줘.

[하지 말 것] 데이터를 못 가져오면 비슷한 종목으로 바꾸거나 값을 지어내지 말고,
무엇이 실패했는지 그대로 보여주고 멈춰.
```

> **결과 관찰**: `999999`는 존재하지 않는 종목코드입니다. **울타리가 작동하면** AI는 "조회에 실패했다"고 정직하게 보고하고 멈춥니다. **울타리가 없었다면** 비슷한 종목으로 슬쩍 바꾸거나 값을 만들어냈을 수 있습니다. 이게 가짜 시세 하드코딩 사건을 막는 방어선입니다.
