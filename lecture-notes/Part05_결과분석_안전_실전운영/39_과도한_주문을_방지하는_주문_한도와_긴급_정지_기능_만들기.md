# 과도한 주문을 방지하는 주문 한도와 긴급 정지 기능 만들기

## 이번 클립에서 만들 것

이 클립이 끝나면, 여러분은 두 가지 사고를 미리 막는 **'3중 주문 안전장치'**를 구현하게 됩니다. 하나는 10주를 살 자리에 1,000주를 치거나 가격을 잘못 적는 것 같은 잘못된 주문 입력(**팻 핑거**, 손가락이 굵어 키를 잘못 눌렀다는 데서 온 말)이고, 다른 하나는 프로그램 오류로 주문이 멈추지 않고 계속 나가는 폭주입니다. 세 장치는 ① 한 번에 넣을 수 있는 주문 금액의 상한, ② 하루 주문 횟수 제한, ③ 현재가에서 너무 멀리 떨어진 가격의 주문 차단입니다.

> 💡 **주문 가드레일의 중요성**: 금융 시장에서 가장 멍청한 파산은 전략이 틀려서가 아니라, 10주를 살 자리에 1,000주를 잘못 입력하거나, 같은 동작을 되풀이하는 코드(루프)가 멈추지 않고 주문을 계속 내서 생기는 '만든 사람의 실수'입니다. 이 안전 가드레일은 여러분의 전 재산을 지키는 최후의 안전핀입니다.

- **1회 주문 금액 상한**: `weekly_policy.json`에 승인된 **그 전략의 배정 비중**을 넘는 주문은 발주 원천 거부 (어떤 국면에서도 60% 상한)
- **하루 주문 횟수 제한**: 당일 누적 주문 횟수가 15회를 초과하면 그날 남은 주문을 모두 거부
- **비정상 가격 주문 차단**: 현재가 대비 3% 이상 벗어난 가격의 주문 차단
- **실습 27**: 주문 유효성 검증기(`order_validator.py`) 작성 및 비정상 주문 차단 시뮬레이션

## 이론 핵심

### 1. 주문 전 3중 안전 검사

증권사 API로 주문을 보내기 직전, 코드 안에서 반드시 통과해야 하는 관문입니다.

```text
[주문 요청 발생: 종목, 수량, 가격, 전략명]
  ↓
[검증 1: 정책 비중 초과] ──> (주문수량 * 현재가) > 총자산 * 그 전략의 정책 비중 ? ──> YES ➔ 차단 (POLICY_WEIGHT_EXCEEDED)
  ↓
[검증 2: 당일 주문 횟수]  ──> 오늘 누적 주문 횟수 > 15회 ?        ──> YES ➔ 차단 (DAILY_LIMIT_EXCEEDED)
  ↓
[검증 3: 현재가와 차이]   ──> |주문단가 - 현재가| / 현재가 >= 3% ?  ──> YES ➔ 차단 (PRICE_DEVIATION_TOO_HIGH)
  ↓
[모든 검증 통과] ──> 비로소 증권사(KIS) API로 주문을 보냄
```

## 실습 — 실습 27: 주문 검증기 및 차단 시뮬레이션

Claude Code 대화창에 아래 프롬프트를 입력하세요.

```prompt
[맥락] 과도한 주문과 주문 폭주를 주문을 보내기 전에 막는 주문 검사 코드를 완성하고 싶어.

[만들 것] 다음 조건에 맞춰 파이썬 스크립트 'order_validator.py'를 작성하고 실행해줘:
1. 주문 하나(종목코드·전략 이름·수량·가격)와 지금 총자산을 받아서, 아래 세 조건을 검사해 통과(PASS) 또는 거부(REJECT)와 거부 사유를 돌려주는 검사 함수 'validate_order'를 만들어줘:
   - 조건 1: 주문 금액(수량 × 가격)이 총자산 × weekly_policy.json에 승인된 그 전략의 배정 비중을 초과하면 거부 (정책 파일을 읽어서 비교하고, 어떤 경우에도 60%를 넘으면 거부)
   - 조건 2: 당일 누적 발주 횟수가 15회를 초과하면 거부
   - 조건 3: 주문 가격이 실시간 현재가와 3% 이상 차이 나면 거부
2. 정상 주문 시나리오(정책 비중 안쪽 매수)와 3가지 비정상 주문 시나리오(정책 비중 초과, 횟수 초과, 가격 오류)를 실행하여 모두 정확하게 필터링되는지 테스트해줘.
3. 검증 성공/실패 로그가 'logs/risk_validation.log'에 명확히 기록되도록 해줘.

[하지 말 것]
- 테스트 시나리오에서 실제 주문 API를 호출하지 마. 검증 함수의 PASS/REJECT 판정만 확인해.
- 세 조건 중 하나라도 걸리면 거부해. '금액은 초과했지만 횟수가 적으니 통과' 같은 예외를 넣지 마.
- 비중 상한을 코드 안에 새로 적어 넣지 마. 반드시 weekly_policy.json에서 읽어. 정책 파일이 없거나 만료됐으면 주문을 모두 거부해.
- 거부된 주문의 수량이나 가격을 자동으로 줄여서 다시 통과시키지 마. 거부는 거부로 끝내고 사유를 기록해.

[확인] 대화창에 4가지 시나리오(정상 1건 + 비정상 3건)의 PASS/REJECT 판정 결과 표가 출력되었는지, 그리고 'logs/risk_validation.log'에 같은 내용이 기록되었는지 확인해줘.
```

---

### 내 눈으로 확인할 체크리스트

- [ ] 정책 비중 안쪽의 정상 주문은 통과(PASS)했다.
- [ ] 정책 비중 초과, 하루 15회 초과, 현재가와 3% 넘게 차이 나는 가격의 주문이 각각 거부(REJECT)되고 사유가 기록되었다.
