# 과도한 주문을 방지하는 주문 한도와 긴급 정지 기능 만들기

## 이번 클립에서 만들 것

전략과 상관없이 일어나는 두 가지 사고를 막는 장치를 만듭니다. 하나는 10주를 살 자리에 1,000주를 넣는 것 같은 잘못된 주문(**팻 핑거**, 손가락이 굵어 키를 잘못 눌렀다는 데서 온 말)이고, 다른 하나는 프로그램 오류로 주문이 멈추지 않고 계속 나가는 폭주입니다.

앞에서 만든 장중 안전장치(하루 손실 한도)가 **시장이 빠질 때**의 장치라면, 이번은 **프로그램이나 내가 틀릴 때**의 장치입니다.

> 💡 2012년 미국의 투자사 나이트 캐피털은 프로그램 오류로 45분 동안 잘못된 주문이 계속 나가 4억 4천만 달러를 잃었습니다. 전략이 틀려서가 아니라 주문을 멈출 장치가 없어서 생긴 사고입니다.

- **주문 한도**: 주문을 보내기 직전에 거치는 세 가지 검사
- **긴급 정지(킬 스위치)**: 파일 하나만 만들면 모든 자동 주문이 멈추는 장치
- **실습 27**: `order_validator.py`와 `kill_switch.py` 작성 및 차단 시험

### 2. 긴급 정지의 원리

정지 신호는 서버나 메신저가 아니라 **내 컴퓨터의 파일 하나**(`kill_switch.flag`)입니다. 파일 하나 만들면 켜지고, 모든 프로그램이 같은 파일을 보니 한 번에 멈추며, 컴퓨터를 껐다 켜도 남아 있습니다.

| 표시 파일 | 누가 만드나 | 뜻 |
|---|---|---|
| `lock.flag` | 장중 안전장치 (계좌 총자산이 아침보다 3% 이상 줄면 모두 매도) | 매수 주문을 보내지 않음 (지울 때까지, 매도는 나감) |
| `kill_switch.flag` | 사람 (`kill_switch.py` 실행) | **새 주문을 모두 막음.** 만들 때 이미 증권사에 들어가 있던 미체결 주문도 취소 |

<div class="compare-box">
  <div class="compare-card good">
    <div class="tag">프로그램이 하는 것</div>
    <div class="steps">
      • 주문 프로그램은 시작할 때 한 번, 그리고 <strong>주문 한 건을 보내기 직전마다</strong> 파일을 확인합니다. 매도 → 체결 대기 → 매수 도중이든, 장중 안전장치가 매도를 보내려는 순간이든, 파일이 보이면 그 주문부터 나가지 않습니다.<br>
      • 이미 증권사에 들어간 미체결 주문은 <code>kill_switch.py</code>가 취소합니다. 한 번이 아니라 1분 동안 몇 초 간격으로 되풀이해, 막 도착한 주문도 잡습니다.<br>
      • 두 파일 모두 저절로 없어지지 않습니다. 원인을 확인한 뒤 내가 해제합니다.
    </div>
  </div>
  <div class="compare-card bad">
    <div class="tag">프로그램이 못 하는 것</div>
    <div class="steps">
      • 파일을 만드는 바로 그 순간 <strong>막 떠난 주문 한 건</strong>은 되돌리지 못합니다. 시장가라 도착 즉시 체결되어 보유가 되고, 사람이 정리합니다. 피해는 그 한 건까지입니다.<br>
      • 인터넷이 끊기면 증권사와 아무 말도 못 합니다. 새 주문이 못 나가니 폭주는 저절로 멈추지만, <strong>미체결 주문의 취소도 못 합니다.</strong><br>
      • 그때는 휴대폰(이동통신)으로 증권사 앱에서 직접 취소하거나 고객센터에 전화합니다.<br>
      • 이 시스템의 주문은 시장가라 바로 체결되므로 미체결로 남는 일은 드물지만, 구멍이 없는 것은 아닙니다.
    </div>
  </div>
</div>

긴급 정지가 켜져 있는 동안에는 장중 안전장치의 매도까지 포함해 프로그램이 어떤 주문도 보내지 않습니다. 보유 종목을 정리해야 하면 사람이 증권사 앱에서 직접 합니다.

## 실습 — 실습 27: 주문 검사와 긴급 정지 만들기

Claude Code 대화창에 아래 프롬프트를 입력하세요.

> 📁 **공유 파일**: 이 프롬프트는 `signals.json`(총 투자금)과 `orders_history.json`(오늘 주문 횟수)을 읽고, 앞에서 만든 `execute_orders.py`에 주문 전 검사와 긴급 정지 확인을 덧붙입니다. `risk_guard.py`의 손절 매도도 같은 주문 함수를 거치므로 함께 검사되고, 긴급 정지 때 함께 멈춥니다.

```prompt
[맥락] 잘못된 주문과 주문 폭주를 보내기 전에 막는 검사와, 모든 자동 주문을 즉시 멈추는 긴급 정지를 만들고 싶어. 작업 폴더의 signals.json(총 투자금), orders_history.json(오늘 주문 기록), kis_auth.py, market_data.py, execute_orders.py, risk_guard.py를 쓴다.

[만들 것]
1. 'order_validator.py': 주문 하나(종목코드, 매수/매도, 수량, 예상 가격)를 받아 통과 또는 거부(사유 포함)를 돌려주는 검사를 만들어줘. 다른 프로그램이 그대로 가져다 쓸 수 있게 해.
   - 매수 금액(수량 × 예상 가격)이 총 투자금의 60%를 넘으면 거부
   - 오늘 보낸 주문이 이미 15회 이상이면 거부 (매수·매도 모두)
   - 매수의 예상 가격이 지금 현재가와 3% 이상 차이 나면 거부
   - 매도는 횟수만 검사해. 위험을 줄이는 주문이라 금액이나 가격 차이로 막지 않아.
2. 'kill_switch.py': 실행하면 빈 파일 'kill_switch.flag'를 만들고, 계좌에 남아 있는 미체결 주문(넣었지만 아직 사고팔리지 않은 주문)을 모두 취소해. 취소는 한 번으로 끝내지 말고 1분 동안 몇 초 간격으로 되풀이해, 그 사이 도착한 주문도 취소한 뒤 끝내고 'logs/kill_switch.log'에 사유를 남겨. 해제 방법도 만들어, 해제하면 'kill_switch.flag'를 지우고 그 사실도 같은 기록에 남겨.
3. execute_orders.py에 덧붙여줘: 'kill_switch.flag'가 있으면 아무 주문도 보내지 말고 멈춰. 이 확인은 시작할 때 다른 어떤 확인보다 먼저 한 번, 그리고 주문 한 건을 보내기 직전마다 다시 해(프로그램이 이미 돌고 있는 중에 파일이 생겨도 그다음 주문부터 막히게). 주문마다 1번 검사를 거쳐 통과한 것만 보내고, 거부는 사유와 함께 기록해. risk_guard.py가 보내는 매도도 같은 길을 지나게 해(risk_guard.py 자체는 고치지 마).
4. 만든 뒤 바로: 정상 주문 1건과 비정상 주문 3건(금액 초과, 횟수 초과, 가격 차이)을 1번 검사에 넣어 결과 표를 보여줘. 횟수 초과는 시험용 기록 파일로 시험하고 끝나면 지워. 그다음 kill_switch.py를 실행해 정지를 켜고(미체결 주문이 없을 때), execute_orders.py를 한 번 실행해 멈추는지 본 뒤 해제해.

[하지 말 것]
- 거래 코드(기능마다 붙은 이름표)를 짐작으로 쓰지 마. KIS Developers 문서나 한국투자증권 공식 GitHub 예제(koreainvestment/open-trading-api)에서 모의투자용을 확인하고 출처를 알려줘.
- 시험에서 실제 주문을 보내거나, 실제 orders_history.json에 기록을 더하거나 지우지 마.
- 거부된 주문을 수량이나 가격을 줄여서 통과시키거나, 긴급 정지 중에 '예외로' 보내는 길을 만들지 마.
- execute_orders.py에서 바꾸는 것은 3번에 적은 두 가지뿐이야(1번 검사를 가져다 쓰는 데 필요한 부분 포함). 주문을 고르고 보내고 기록하는 나머지 동작은 그대로 둬.

[확인] 시험 주문 4건의 통과·거부 표와, 긴급 정지 켜기 → 주문 차단 → 해제의 기록을 보여줘.
```
