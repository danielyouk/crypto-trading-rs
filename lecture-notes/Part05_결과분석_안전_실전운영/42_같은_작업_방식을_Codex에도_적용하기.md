# 같은 작업 방식을 Codex에도 적용하기

## 이번 클립에서 만들 것

이 클립이 끝나면, 이 강의 내내 Claude Code에서 쓰던 프롬프트 템플릿을 **Codex에 그대로 적용해 같은 결과물**을 얻는 화면을 봅니다.

- Codex에 같은 프롬프트를 넣어 만든 차트(또는 보고서)가 체크리스트를 통과하는 모습
- "내 자산은 특정 도구가 아니라 **작업 방식과 프롬프트 템플릿**"이라는 확신

## 이론 핵심

### 도구는 바뀌어도 작업 루프는 남는다

이 강의에서 배운 것의 본질은 Claude Code 사용법이 아니라 **생각→요청→확인→개선 루프**입니다. 이 루프는 어떤 AI 코딩 도구에서도 동일하게 작동합니다.

1. 끝나면 화면에 뭐가 보여야 하는지 생각하고
2. 결과 모습이 담긴 목표를 프롬프트로 전달하고
3. 사람이 체크리스트로 확인하고
4. 부족하면 후속 프롬프트를 보냅니다

### 도구 독립성이 왜 중요한가

AI 도구 시장은 빠르게 바뀝니다. 가격이 오르거나, 더 좋은 도구가 나오거나, 쓰던 도구가 사라질 수 있습니다. 프롬프트 템플릿과 체크리스트를 자산으로 갖고 있으면 **도구를 갈아타는 비용이 거의 없습니다.** 반대로 특정 도구의 버튼 위치만 외웠다면 도구가 바뀔 때 처음부터 다시 배워야 합니다.

### 같은 프롬프트, 다른 결과 — 그래서 체크리스트

Codex가 만든 코드는 Claude Code가 만든 코드와 다를 것입니다. 하지만 우리는 처음부터 코드가 아니라 **결과 화면을 체크리스트로 검증**해 왔습니다. 도구를 바꿔도 검증 방식이 그대로라는 것, 이것이 이번 실습의 진짜 확인 사항입니다.

## 실습 — 실습 23

강의에서 이미 성공했던 프롬프트 하나를 Codex에 그대로 넣어봅니다. 예를 들어 첫 실습의 차트 프롬프트입니다.

```prompt
한국 주식 삼성전자(005930)의 최근 3년 일봉 데이터를 불러와서
이동평균선(20일, 60일)이 포함된 차트를 그려줘.
완성되면 차트 이미지 파일 경로를 알려줘.
```

익숙해졌다면 일일 보고서 프롬프트(실습 20)도 Codex에서 시도해 보세요.

### 내 눈으로 확인할 체크리스트

- [ ] Codex에서도 같은 프롬프트로 차트(또는 보고서)가 만들어졌다
- [ ] 결과물이 원래 클립의 체크리스트 항목을 그대로 통과한다
- [ ] 두 도구의 생성 코드가 달라도 결과 화면 기준으로는 문제가 없음을 확인했다
- [ ] 오류가 났을 때 Part 1에서 배운 방식(오류 메시지 전달)으로 해결했다

## 자주 발생하는 문제

이번 클립은 "결과가 다를 수 있다"가 문제 상황이 아니라 **학습 목표 그 자체**입니다. Claude Code와 Codex의 코드, 그리고 강사와 여러분의 결과가 모두 다를 수 있습니다. 체크리스트만 같으면 됩니다.

- Codex의 결과물이 체크리스트에 못 미칠 때:

```prompt
차트는 그려졌는데 이동평균선 두 개가 보이지 않아.
20일선과 60일선이 서로 다른 색으로 구분되어 보이도록 수정해줘.
```

- 환경 차이로 오류가 날 때:

```prompt
이 오류 메시지가 나왔어: [오류 메시지 붙여넣기]
원인을 설명해주고, 필요한 설치나 설정을 진행한 뒤
차트가 정상적으로 보이는 상태까지 만들어줘.
```
