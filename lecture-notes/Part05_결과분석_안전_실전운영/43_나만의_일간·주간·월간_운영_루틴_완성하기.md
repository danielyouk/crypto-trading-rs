이 클립이 끝나면, 여러분은 5개 파트 43개 클립을 관통하여 구축한 모든 시스템과 전략을 일상생활 속에 완벽하게 정착시키는 **'1인 퀀트 헤지펀드 매니저의 지속 가능한 라이프사이클(일간 10분, 주간 30분, 월간 1시간)'**을 완성하고, 평생 내 자산을 지키고 불려줄 나만의 독립된 AI 트레이딩 시스템을 온전히 소유하게 됩니다.

> 💡 **강의 완주 축하 메시지**: 여러분은 코딩 문법을 달달 외우지 않고도, 현대 퀀트와 AI 엔지니어링의 최고 정수인 **네 가지 투자 전략 백테스트, 워크포워드 검증, 사람이 매수를 승인하고 프로그램이 매일 실행하는 모의주문 시스템, 장중 안전장치**을 직접 설계하고 통제하는 진정한 '시스템 아키텍트'로 거듭났습니다.

- 1인 퀀트의 지속 가능한 3단계 운영 타임라인 (**일간 10분 / 주간 30분 / 월간 1시간**)
- 지치지 않고 장기 복리 투자를 이어가는 **심리적 방패와 멘탈 관리법**
- 5개 파트 전체 시스템 구성 총결산 및 폴더 구조도
- **최종 실습 31**: 나만의 일간·주간·월간 운영 가이드 문서(`docs/my_quant_routine.md`) 최종 발행

## 이론 핵심: 1인 퀀트의 라이프사이클

### 1. [일간 루틴: 10분] 장 마감 후 한 번

```text
[일일 보고 메일을 받은 뒤 ~ 다음 개장 전, 편한 시간] (10분)
1. 일일 보고 메일(그날 일지)에서 체결 결과, 다음 거래일 주문 건수, 신호가 바뀌는 조건을 훑어봄
2. 승인 대기인 매수가 있으면 주문 목록(orders.json)을 열어 값을 확인하고 승인 상태를 승인 또는 거절로 고침
3. 안전장치·오류 메일이 없으면 그대로 마무리 (장중에는 HTS/MTS를 쳐다보지 않음). 일일 보고가 오지 않았다면 logs 폴더의 실행 기록을 확인
```

대부분의 날은 주문 목록이 비어 있어 2번에서 할 일이 없습니다.

---

### 2. [주간 루틴: 30분] 주말에 한 주 돌아보기

```text
[토요일/일요일 중 편한 시간] (30분)
1. 한 주 동안의 일지와 알림 기록(logs/alerts.log)을 훑어봄. '오류' 알림이 있었다면 원인 확인
2. 승인·거절 기록(approvals_log.json) 확인. 거절한 매수가 있었다면 그 판단이 옳았는지 되돌아봄
3. 예상 가격과 체결 가격의 차이가 평소보다 컸던 주문이 있는지 확인
```

주간 루틴은 **점검**입니다. 이때 규칙이나 값을 바꾸지 않습니다.

---

### 3. [월간 루틴: 1시간] 월말 판정 뒤 국면과 성과 점검

```text
[월말 거래일이 지난 뒤 첫 주말] (1시간)
1. 월말 국면 판정 결과와 이번 달 비중 확인
2. 월간 수익률, MDD, 샤프 지수를 KODEX 200 단순 보유와 대조
3. 입력값(비중, 목표 변동성)을 바꾸고 싶으면 먼저 재검증. 통과했을 때만 변경
```

국면이 바뀌어 생긴 매수도 여느 날처럼 월말 거래일 장 마감 후 일간 루틴 1번에서 승인하거나 거절합니다. 월간 루틴에는 승인 단계가 없습니다.

## 5개 파트 전체 시스템 폴더 구조 총결산

```text
ai-trading/
├── .env                       # [보안] KIS API 키, 계좌번호, 메일 설정
├── requirements.txt           # [환경] pandas, requests, FinanceDataReader 등
│
├── signals.json               # 가장 최근 신호 (입력값, 국면, 목표 수량, 순주문)
├── signals_날짜.json           # 날짜별 신호 기록
├── orders.json                # 다음 개장 때 낼 주문 목록과 승인 상태
├── approvals_log.json         # 매수 승인·거절 기록
├── orders_history.json        # 주문과 체결 기록
├── stopped_positions.json     # 안전장치가 판 종목 (그 달이 끝날 때까지 매수 보류)
├── lock.flag                  # [안전] 매수 중단 표시 (지울 때까지)
├── kill_switch.flag           # [안전] 모든 자동 주문 정지 표시
│
├── generate_signals.py        # 세 전략의 신호와 목표 수량 계산
├── kis_auth.py                # 증권사 접근 토큰(출입증) 발급 및 잔고 조회
├── market_data.py             # 현재가 조회
├── prepare_orders.py          # 신호를 계좌와 비교해 주문 목록 만들기
├── approve_orders.py          # 고친 승인 상태 검사와 기록
├── notifier.py                # 일일 보고·체결 결과·손절 실행·오류 이메일
├── execute_orders.py          # 매도와 승인된 매수를 증권사로 보내기
├── risk_guard.py              # 장중 개별 종목 -3% 손절 및 계좌 -2% 하루 손실 한도
├── order_validator.py         # 주문 금액·하루 횟수·가격 차이 검사
├── kill_switch.py             # 긴급 정지 켜기와 해제
├── daily_journal.py           # 장 마감 후 체결 확인과 신호가 바뀌는 조건 정리
├── run_after_close.py         # 평일 17:00 장 마감 후 작업 (신호 → 주문 목록 → 일지 → 메일)
├── run_market_open.py         # 평일 09:00 개장 주문과 장중 안전장치
│
├── price_cache/               # 내려받은 가격 데이터
├── docs/                      # 손실 진단 보고서, 일지, 국면 보고서
└── logs/                      # 날짜별 실행 기록, 알림 기록
```

## 최종 실습 — 실습 31: 나만의 퀀트 운영 헌법 제정

Claude Code 대화창에 아래 프롬프트를 입력하여 나만의 운영 루틴 가이드 문서를 완성하세요.

```prompt
[맥락] 우리가 완성한 AI 트레이딩 시스템(신호 계산, 매수 승인, 자동 주문, 장중 안전장치)의 운영 절차를 정리한 나만의 운영 루틴 문서를 만들고 싶어.

[만들 것] 다음 내용을 담은 'docs/my_quant_routine.md' 문서를 작성해줘:
1. 시스템 전체 구성도(어떤 프로그램이 어떤 파일을 읽고 쓰는지 그린 그림) 및 핵심 파일별 역할 설명
2. 일간(10분), 주간(30분), 월간(1시간) 체크리스트 및 매번 그대로 쓸 프롬프트. 주문에 관해 사람이 하는 일은 장 마감 후부터 다음 개장 전까지 'orders.json'을 열어 '승인 대기'인 매수의 승인 상태를 '승인' 또는 '거절'로 고치는 것 한 가지이니 일간 체크리스트에 넣고, 이메일(일일 보고·체결 결과·안전장치·오류)은 승인과 관계없이 프로그램이 한 일을 알리는 사후 보고로 적어줘.
3. 비상 상황이 생겼을 때 순서대로 따라 할 3단계 대응 절차 (긴급 정지, 원인 확인, 증권사 앱에서 수동 정리)
4. 1인 퀀트로서 감정에 흔들리지 않기 위한 5대 투자 행동 강령
5. 수강생(나)의 이름과 오늘 날짜로 서명된 'AI 퀀트 시스템 독립 선언문'

[하지 말 것]
- 이 승인 말고 다른 승인 단계(메일을 받고 승인, 주말이나 월말에 따로 하는 주문 승인 등)를 만들지 마.
- 문서에 적는 파일 이름과 수치(손절 기준, 하루 손실 한도, 비중 상한 등)는 이 프로젝트 안의 실제 파일과 signals.json의 입력값에서 읽어 와. 기억이나 일반론으로 채우지 마.
- 운영 절차만 정리해. 전략 코드나 신호·주문 파일을 고치지 마.
- 문서를 미사여구로 채우지 마. 매일 실제로 따라 할 수 있는 절차와 수치로 써.

[확인] 대화창에 최종 축하 메시지와 함께 완성된 문서의 목차 요약이 출력되었는지, 그리고 'docs/my_quant_routine.md' 파일이 저장되어 경로가 표시되었는지 확인해줘.
```

---

### 내 눈으로 확인할 체크리스트

- [ ] `docs/my_quant_routine.md`에 일간·주간·월간 운영 절차가 정리되었다.
- [ ] 문서의 파일 이름과 수치(손절 기준, 하루 손실 한도 등)가 실제 파일·`signals.json`의 입력값과 같은지 대조했다.
- [ ] 비상 상황 3단계 대응 절차를 순서대로 따라 할 수 있다.
