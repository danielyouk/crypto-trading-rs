## 이번 클립에서 만들 것

이 클립이 끝나면, 감시 종목들의 **현재가가 화면에서 실시간으로 갱신되는 모습**을 보게 됩니다.

- 감시 종목 목록(예: 3~5개 종목)의 현재가·등락률 표
- 가격이 바뀔 때마다 표의 숫자가 따라서 움직이는 화면

## 이론 핵심

### 웹소켓: 시장이 밀어주는 데이터

지금까지 백테스트에서는 과거 데이터를 한 번에 내려받았습니다. 실시간 매매에서는 **가격이 바뀌는 순간마다 데이터를 받아야** 합니다. 한국투자증권 API는 이를 위해 **웹소켓** 방식을 제공합니다.

- **REST 조회**: 내가 물어볼 때만 답이 옵니다. "지금 삼성전자 얼마야?" → 응답.
- **웹소켓**: 한 번 연결해 두면 가격이 바뀔 때마다 증권사가 **먼저** 보내줍니다.

전화를 걸어 매번 물어보는 것과, 담당자가 변동이 있을 때마다 바로 알려주는 것의 차이입니다.

### 대안: REST 폴링

웹소켓 연결이 어렵거나 종목 수가 적다면, 몇 초 간격으로 REST 조회를 반복하는 **폴링** 방식도 실용적인 대안입니다. 우리 전략은 초 단위 반응이 필요한 초단타가 아니므로, 폴링으로도 충분히 동작합니다. AI에게 웹소켓을 먼저 요청하고, 문제가 계속되면 폴링으로 바꿔달라고 하면 됩니다.

### 받은 데이터는 눈으로 검증한다

실시간 데이터가 "들어오는 것"과 "맞는 것"은 다릅니다. 받은 현재가를 증권사 앱(HTS/MTS)의 가격과 나란히 비교해서 같은 값인지 확인하는 것이 이번 실습의 핵심 검증입니다.

## 실습 13 — 감시 종목의 실시간 가격 표 만들기

```prompt
모의투자 계좌에 연결된 시스템에서, 감시 종목 3개(삼성전자, SK하이닉스, NAVER)의
실시간 현재가를 받아와서 화면에 표로 보여줘.
표에는 종목명, 현재가, 전일 대비 등락률이 있어야 하고,
가격이 바뀌면 표의 숫자가 자동으로 갱신되는 모습이 보여야 해.
```

### 내 눈으로 확인할 체크리스트

- [ ] 감시 종목 3개의 현재가·등락률이 표로 보인다
- [ ] 잠시 지켜보면 숫자가 실제로 갱신된다 (장중 기준)
- [ ] 증권사 앱에서 본 현재가와 시스템 표의 가격이 일치한다
- [ ] 장이 닫혀 있다면, 마지막 체결가가 표시되고 갱신이 멈춘 상태임을 확인했다

## 자주 발생하는 문제

강사와 여러분의 AI가 만든 코드는 다를 수 있습니다. 웹소켓 대신 폴링으로 구현되어도, 체크리스트의 화면이 나오면 정상입니다.

- **장 시간 밖 실습**: 장이 닫혀 있으면 가격이 움직이지 않는 것이 정상입니다. 오류가 아닙니다.
- **웹소켓 접속키 문제**: 웹소켓은 별도의 접속키가 필요합니다. 인증 오류가 나면 AI에게 오류 메시지를 그대로 전달하세요.
- **토큰 만료**: 오래 켜두면 토큰이 만료되어 갱신이 멈출 수 있습니다.

```prompt
실시간 가격 표가 어느 순간부터 갱신이 안 돼. 연결이 끊긴 건지 확인하고,
끊겼다면 자동으로 다시 연결해서 표가 계속 갱신되게 해줘.
```

```prompt
웹소켓 연결이 계속 실패해. 5초 간격 REST 폴링 방식으로 바꿔줘.
바꾼 뒤에도 같은 표가 보이고 숫자가 갱신되어야 해.
```
