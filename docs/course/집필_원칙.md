# 강의 자료 집필 원칙

43개 클립 전부에 적용합니다. **새 클립을 쓰거나 고칠 때 이 문서를 먼저 보세요.**

원칙마다 Clip 02에서 실제로 고친 사례를 붙였습니다.

---

## 1. 정의 없이 쓰지 않는다

수강생이 모를 수 있는 말은 **첫 등장 자리에서 한 줄로** 풀어씁니다. 뒤에 설명하거나 별도 용어집으로 미루지 않습니다.

| | |
|---|---|
| ❌ | "라이브러리 관리를 대신해 주는 도구입니다" — `라이브러리`가 뭔지 안 나옴 |
| ✅ | "**라이브러리**: 남이 미리 만들어 둔 **기능 묶음**. 직접 안 만들고 가져다 씁니다" |

**같은 것을 두 이름으로 부르지 않습니다.** `라이브러리` / `패키지` 처럼 섞어 쓰면 초보자는 다른 것으로 읽습니다. 하나를 골라 끝까지 씁니다.

용어가 서너 개 이상 몰리면 클립 첫머리에 작은 표로 묶고, **"지금 외우실 필요 없습니다. 나올 때마다 다시 설명합니다"** 를 덧붙입니다.

---

## 2. 프롬프트에 정답을 심지 않는다 ★

**이 원칙이 가장 중요합니다.**

프롬프트는 **모르는 것을 AI가 대신하게 만드는 도구**입니다. 목표와 판단 기준을 주는 것이지, 내가 이미 아는 답을 받아쓰게 하는 게 아닙니다.

강사가 아는 정답을 프롬프트에 넣으면 그 순간은 성공하지만, **수강생은 아무것도 배우지 못합니다.** 다음에 다른 함정을 만나면 미리 써둔 줄이 없으니까요.

**Clip 02 실제 사례**

```prompt
❌ Windows라면, 경로에 WindowsApps가 들어간 python은 진짜 Python이 아니라
   Microsoft Store 안내용 껍데기야. 그건 '없음'으로 처리해줘.
```
→ 강사가 아는 정답. Windows에만 해당하고, 다른 함정에는 못 씁니다.

```prompt
✅ "설치돼 있다고 표시되는 것"이 아니라 "실제로 실행되는지"가 기준이야.
```
→ **판단 기준**. 어떤 함정이든 걸러냅니다. 그리고 수강생이 다음 프로젝트에서도 씁니다.

**강사의 경험은 프롬프트가 아니라 해설에 씁니다.** "제가 여기서 10분을 날렸습니다"는 좋은 이야기지만, 그건 **왜 저 기준이 필요한지 설명하는 자리**에 있어야 합니다.

`[하지 말 것]` 칸도 같습니다. 특정 파일 이름을 나열하는 대신 **"요청한 것 외에는 만들지 마"** 처럼 규칙으로 씁니다.

## 3. 정당화는 결정 직전에 둔다

"왜 이걸 쓰는가"는 **그 결정을 내리기 바로 전**에 있을 때 읽힙니다. 앞에 몰아두면 아직 생기지 않은 질문에 답하는 꼴이라 그냥 넘어갑니다.

| 내용 | ❌ 있던 자리 | ✅ 옮긴 자리 |
|---|---|---|
| 왜 앱이 아니라 확장인가 | 이론 핵심 | `Install` 누르기 직전 |
| 왜 파이썬이 필요한가 | (없었음) | 진단 프롬프트 직전 |
| `.venv`가 무엇인가 | (프롬프트 안에 단어만) | 폴더가 실제로 생긴 뒤 |

---

## 4. 검색으로 풀리는 것은 뺀다

"혹시 이런 경우엔?"을 다 담으면 **정작 90%의 흐름이 끊깁니다.**

판단 기준은 하나입니다 — **검색으로 풀리면 빼고, 검색으로 안 나오면서 막히면 치명적인 것만 남깁니다.**

Clip 02에서 이 기준으로 약 80줄을 덜어냈습니다.

| 뺀 것 | 이유 |
|---|---|
| Cursor 화면 전환 안내 | 소수만 해당, 검색으로 해결 |
| VS Code 설치 상세 (41줄) | 대다수가 이미 앎 |
| `Auto` 없을 때 원인 진단 3단계 | 검색으로 해결 |
| 첫 설치자에게 해당 없는 설정 확인 | 논리적으로 발생 불가 |

대신 **검색으로 안 나오는 대안 한 문장**은 남겼습니다. `Auto`가 없는 수강생이 승인 지옥을 겪다가 "이 강의가 잘못됐구나" 하는 게 첫날 최대 이탈 요인이기 때문입니다.

---

## 5. "지금 몰라도 된다"고 말해준다

초보자의 이탈은 *"모르는 게 나왔다"* 가 아니라 **"이걸 알아야 하는 건지 아닌지 모르겠다"** 에서 생깁니다.

당장 이해할 필요 없는 것이 나오면 **명시적으로 그렇게 적습니다.**

> 지금 외우실 필요 없습니다. 하시면서 자연스럽게 익으실 거예요.

---

## 6. 임의의 선택에는 "왜" 한 줄을 붙인다

종목·기간·개수처럼 강사가 고른 값에는 이유를 답니다. 그래야 **강의를 안 들은 사람도 논리를 따라오고**, 나중에 직접 바꿔 씁니다.

| 선택 | 붙인 이유 |
|---|---|
| 삼성전자 | 포털에서 **1초 만에 대조 가능**한 종목이라서 |
| 5거래일 | 한눈에 들어오면서 눈으로 대조하기 충분한 최소량 |
| 라이브러리 3개 | 가져오기 + 다루기 + 그리기. **딱 최소** |

## 7. 줄글 대신 표

비교·선택·조건 분기는 **표**로 씁니다. 수강생은 긴 문단을 안 읽습니다.

Clip 02의 VS Code 설치 안내는 41줄 줄글에서 **2행짜리 표 + 팁 한 줄**이 됐습니다.

## 8. 번호는 대단원마다 1부터

**목차만 봤을 때 번호 기준이 한눈에 보여야 합니다.**

규칙은 하나입니다 — **각 대단원(`##`)은 자기 하위 항목(`###`)에 1부터 번호를 매긴다.**

```
이론 핵심
   1. 왜 AI 코딩인가?
   2. 비용은 얼마나 드나
   3. 오늘의 진행 흐름

실습 — 실습 01
   Step 1. 확장 설치와 자율권 모드 설정
   Step 2. 작업 폴더 생성 및 열기
   ...

자주 발생하는 문제 및 트러블슈팅
   1. 진단 결과 "Python 없음"이라고 나올 때
   2. 원인 모를 에러로 멈출 때
   ...
```

- **실습 구간만 `Step`이라는 이름을 함께 씁니다.** 순서대로 따라 해야 하는 구간이라는 신호이고, 대본과 영상에서 "Step 4로 가겠습니다"라고 부르기 위해서입니다
- **0번을 만들지 않습니다.** `Step 0` 같은 건 쓰지 않습니다
- **번호 없는 짧은 안내는 제목으로 만들지 않습니다** — 목차에 번호 없는 항목이 하나 끼면 그 자리에서 기준이 무너져 보입니다. 본문 굵은 글씨로 씁니다

## 9. 검증은 선언이 아니라 실제로 한다

이 강의를 관통하는 주제입니다. 자료 곳곳에서 같은 모양으로 반복되어야 합니다.

| Step | "선언" | "실제" |
|---|---|---|
| 진단 | "파이썬이 있다" | **실제로 실행되는가** |
| 대조 | AI의 "완료했습니다" | **포털 시세와 숫자가 맞는가** |
| diff | AI가 쓴 코드 | **승인 전에 내 눈으로 본다** |

새 클립을 쓸 때도 **"여기서 수강생이 무엇을 자기 눈으로 확인하는가"** 를 항상 하나 넣습니다.
